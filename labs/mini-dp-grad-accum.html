LAB A3 · DATA PARALLEL

TP 是“同一个样本一起算”。
DP 是“同一份模型，各算不同样本”。

前两课一直在 Tensor Parallel group 里切权重。现在换一个维度：两个 rank 都保留同样的参数，但各自拿不同训练样本。它们可以先在本地连续做多个 microbatch 的 backward，把梯度累积起来，最后再做一次 all-reduce。这样你会第一次把“梯度累积”和“梯度同步”拆成两件独立的事。

01 · TP VS DP

先把“切权重”和“切样本”分开。

RANK 0same W · samples A完整参数 W；只看自己那部分数据，连续跑多个 microbatch。
RANK 1same W · samples B参数必须与 Rank 0 一致，但输入样本不同，因此本地梯度也不同。
DP SYNCall-reduce gradients把各 rank 的局部梯度求和/平均，之后所有副本用同一个 global gradient 更新。

所以 TP 的核心问题是“一个矩阵怎么分工”；DP 的核心问题是“不同数据算出的梯度，什么时候合成同一个更新”。真实 Megatron 会同时存在 TP group、DP group，二者的通信不能混为一谈。

02 · ACCUMULATION BEFORE COMMUNICATION

microbatch 每 backward 一次，不代表每次都必须通信。

ONE TRAINING STEPper DP rank
microbatch 0 → backward → grad += g₀
microbatch 1 → backward → grad += g₁
...
microbatch M → backward → grad += gₘ

# only now
all_reduce_sum(grad)
grad /= global_num_samples
optimizer.step()

脚本故意把每个 microbatch 的 loss 用 SUM 累积，最后只按全局样本数归一化一次。这样等式最清楚：global_grad = (Σ rank Σ microbatch gradients) / N。如果你在每个 microbatch、每个 rank 上都先做不同的 mean，再随手平均，很容易把缩放因子搞错。

04 · MAP TO MEGATRON

下一次看 Megatron DDP 时，先找“什么时候开始同步”，不要先看类继承。

LABlocal accumulation → one all-reducew.grad / b.grad accumulate, then dist.all_reduce
same contract →
MEGATRONdistributed_data_parallel.pygrad buffers · sync control · overlap hooks

真实实现会把很多 parameter gradients 放进连续 buffer/bucket，并允许不同 bucket 在 backward 尚未完全结束时开始通信。这里没有做 bucket，也没有 overlap；我们只先钉死最基础的语义：DP 同步的是不同样本产生的 parameter gradient。

Gradient accumulation 不等于 Data Parallel。

单 GPU 也可以 accumulation；多 GPU DP 也可以每个 microbatch 都同步。二者是两个正交开关：一个控制“多久 update 一次”，另一个控制“多个模型副本如何得到一致梯度”。

05 · NEXT

如果所有 rank 最终都拿到完整梯度，为什么 optimizer state 还要每张卡复制一份？

① 当前 all-reduce 后，每个 rank 都拥有完整 global gradient。
② SGD momentum / Adam m,v 如果也完整复制，参数越大越浪费显存。
③ 下一实验让 gradient reduction 直接落成 shard：reduce-scatter。
④ 每个 rank 只更新自己的 optimizer-state shard，再 all-gather 新参数。
