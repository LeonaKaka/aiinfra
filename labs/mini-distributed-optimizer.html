LAB A4 · REDUCE-SCATTER + ALL-GATHER

不要把完整梯度发给每个人。
让 reduction 的结果直接落到各自的分片。

普通 DP all-reduce 之后，每个 rank 都拿到完整梯度；如果每个 rank 还保存完整 momentum、Adam m/v、FP32 master params，显存会重复很多份。这个实验做一个最小“Distributed 优化器骨架”：梯度用 reduce-scatter 直接变成分片；每个 rank 只维护自己的 momentum 分片；更新后再 all-gather 参数，供下一次前向计算使用。

01 · 显存契约

计算时需要完整参数，不代表优化器 state 也必须完整复制。

前向计算 / 反向传播full 参数副本这个教学版本仍让每个 DP rank 用完整参数做计算，并得到完整 local 梯度。
梯度reduce-scatter先跨 rank 求和，再把结果按参数区间切开；Rank r 只接收属于自己的 global grad 分片。
优化器local state 分片只更新本 rank 的参数分片与 momentum；之后 all-gather 新参数分片。

这和“先 all-reduce 完整梯度，再每张卡都做同样优化器.step()”的数学结果可以一致，但状态复制量不再一样。world size 越大，优化器-state sharding 的价值越明显。

02 · 一次完整更新

把一轮更新压成四行，就能看清两次 collective 各自负责什么。

DISTRIBUTED 优化器 SKELETONDP dimension
local_full_grad = backward(local_batch)

grad_shard = reduce_scatter_sum(local_full_grad) / DP
state_shard = momentum * state_shard + grad_shard
param_shard = param_shard - lr * state_shard

full_param = all_gather(param_shard)
# next forward uses full_param

reduce-scatter 的“reduce”解决不同 DP 样本的梯度合并，“scatter”顺便决定哪个 rank 负责哪一段优化器 update；all-gather 则把更新后的分片重新 materialize 成下一轮计算需要的参数视图。

04 · 映射到 Megatron

现在再打开 distrib_optimizer.py，先沿缓冲区/range 找分片，而不是试图一口气理解 15 万行工程细节。

LABflat param → 分片 rangereduce_scatter → local momentum → all_gather
same idea →
MEGATRON优化器/distrib_optimizer.pybuffers · ranges · main params · reduce-scatter · all-gather

真实 Megatron 还要处理 mixed precision、FP32 main params、通信桶 alignment、checkpoint、重叠、TP/PP/CP/EP 组合与多种优化器。这个实验不是它的简化复制品，而是用最少状态把“为什么 reduce-scatter + local 优化器分片 + all-gather”这条主因果链固定下来。

不要把这个实验直接叫 ZeRO-3。

这里只有优化器-state / update sharding 的核心数据流；参数在前向计算前仍被完整 materialize，且没有实现完整 ZeRO 阶段语义、prefetch、offload 或真实 Megatron 缓冲区管理。

05 · 下一步

Training 线下一次要把“通信发生了”变成“通信什么时候发生”。

① 把参数 gradients 放进通信桶，而不是每个 tensor 单独 collective。
② 反向传播某个通信桶 ready 后立即启动异步 reduce-scatter。
③ 用 profiler 看 GEMM 与 collective 是否真正重叠。
④ 最后再组合 TP × DP，区分两个 process 进程组的通信。
