LAB B6 · KV 分配不等于传输区域

“注册一块内存”和“我要传哪一层、哪一个 KV 块”
不是同一个问题。

B5 已经有握手与生命周期，但还没有真正拆开内存注册的两个层次。这个实验故意让 3 层 KV 视图 共享同一个底层存储：内存系统看到的是一个分配，而传输逻辑看到的是三个层级区域。每个区域再用 base offset、block length、block stride 描述“第 b 个 KV 块到底在哪里”。这正是读当前 vLLM NIXL register_kv_caches() 前必须建立的心智模型。

01 · 一块存储，对应多个传输区域

共享存储不意味着所有 layer 都是同一个传输 region。

TEACHING 布局3 layers · 8 blocks
one storage allocation
┌───────────────────────────────────────────────────┐
│ layer 0 region │ layer 1 region │ layer 2 region   │
└──────────────────────────────────────────────────────┘
      ↑                 ↑                 ↑
   offset 0          offset 4096       offset 8192

within each region:
block b address = region_base + b × block_stride

脚本里的三层 tensor 是同一块存储的 view，因此 untyped_storage().data_ptr() 只对应一个底层分配；但每层 data_ptr() 不同，所以可以形成多个逻辑 region。

02 · 长度与步长

block_len 回答“传多少”，block_stride 回答“下一个 block 从哪开始”。

BLOCK LENGTHpayload bytes当前 block 真正要搬的连续字节数
≠
BLOCK STRIDEaddress stepblock b → block b+1 的地址步长

在最简单的 contiguous 布局里两者相等；但一旦布局 interleave、padding 或跨层共享存储，stride 可以大于真正 payload。把两者混成一个数，会直接导致远端描述符指向错误位置。

04 · 映射到当前 vLLM NIXL

读当前 register_kv_caches() 时，先把 registration range 与 transfer region geometry 分成两层。

REGISTRATION底层可注册范围当前实现先构造 registration ranges；device KV 通常按底层 storage base / nbytes 注册，host-resident 路径则可能按 tensor 自身 base / nbytes。去重还会区分 memory type。
REGIONbase · len · stride传输侧再记录每个逻辑 region 的 base address、block length 与 block stride。普通 Attention 常接近“每层一个 region”，Mamba / CSA-linear 等布局会出现子 region 或共享 storage 下的多个逻辑 region。
HANDSHAKENixlAgentMetadata注册完成后，把 KV base addresses、num_blocks、block_lens、block_strides、布局、block_size，以及当前实现需要的 region/group 信息编码进握手元数据。

更稳妥的阅读原则是：registration 跟“哪些底层内存范围可被 transport 访问”走，transfer region 跟“后续按什么几何和逻辑单元搬数据”走。这两层经常相关，但不应机械等同；当前 hybrid / Mamba / CSA-linear 路径正好说明了为什么。

05 · 源码阅读顺序

现在读 NIXL 工作进程，只追这条路径。

① 找 storage.data_ptr() / storage.nbytes()：谁是真正被注册的分配？
② 找 block_len_per_layer / block_stride_per_layer：逻辑 region 如何描述？
③ 找 get_reg_descs() → register_memory()：实际 NIXL registration 在哪里发生？
④ 找 NixlAgentMetadata：哪些 registration/布局信息被带到远端 handshake？
