LAB B6 · ALLOCATION ≠ TRANSFER REGION

“注册一块内存”和“我要传哪一层、哪一个 block”
不是同一个问题。

B5 已经有 handshake 与 lifetime，但还没有真正拆开 memory registration 的两个层次。这个实验故意让 3 层 KV view 共享同一个底层 storage：内存系统看到的是一个 allocation，而传输逻辑看到的是三个 layer region。每个 region 再用 base offset、block length、block stride 描述“第 b 个 block 到底在哪里”。这正是读当前 vLLM NIXL register_kv_caches() 前必须建立的心智模型。

01 · ONE STORAGE, MULTIPLE REGIONS

共享 storage 不意味着所有 layer 都是同一个 transfer region。

TEACHING LAYOUT3 layers · 8 blocks
one storage allocation
┌─────────────────────────────────────────────────────┐
│ layer 0 region │ layer 1 region │ layer 2 region   │
└─────────────────────────────────────────────────────┘
      ↑                 ↑                 ↑
   offset 0          offset 4096       offset 8192

within each region:
block b address = region_base + b × block_stride

脚本里的三层 tensor 是同一块 storage 的 view，因此 untyped_storage().data_ptr() 只对应一个底层 allocation；但每层 data_ptr() 不同，所以可以形成多个逻辑 region。

02 · LENGTH VS STRIDE

block_len 回答“传多少”，block_stride 回答“下一个 block 从哪开始”。

BLOCK LENGTHpayload bytes当前 block 真正要搬的连续字节数
≠
BLOCK STRIDEaddress stepblock b → block b+1 的地址步长

在最简单的 contiguous layout 里两者相等；但一旦 layout interleave、padding 或跨层共享 storage，stride 可以大于真正 payload。把两者混成一个数，会直接导致远端 descriptor 指向错误位置。

04 · MAP TO CURRENT VLLM NIXL

当前 register_kv_caches() 正好把 allocation registration 与 logical region geometry 分开处理。

ALLOCATIONunique storage源码按 storage address 去重，把 (storage_addr, storage.nbytes(), device_id) 交给 NIXL descriptor/registration 路径。
REGIONbase · len · stride每个逻辑 region 单独记录 base address、block length 与 block stride，供后续按 block 构造 transfer descriptors。
HANDSHAKENixlAgentMetadata注册完成后，把 KV base addresses、num_blocks、block_lens、block_strides、layout、block_size 等编码进握手 metadata。

当前源码甚至明确写出：memory registration follows allocations, while transfer regions follow logical layers。这句话就是 B6 的全部核心。

05 · SOURCE ORDER

现在读 NIXL worker，只追这条路径。
