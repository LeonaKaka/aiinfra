LAB A12 · TRAINING CAPSTONE

前 11 个 Training Labs 是零件。
这一节把它们第一次装成“一个 training step”。

4 个 ranks 组成 TP=2 × DP=2。每个 rank 同时属于一个 TP group 和一个 DP group：forward 用 TP shards 合成模型输出；backward 在 W2 gradient ready 后立刻启动 DP async reduce-scatter，同时继续算 W1；optimizer 只更新自己负责的 parameter chunk，再 all-gather 恢复下一次 forward 需要的 TP parameter shard。

01 · ONE STEP, FOUR LAYERS OF STATE

不要再把 TP、DP、optimizer sharding 和 overlap 当四个独立功能。

MODEL COMPUTE · TPW1/W2 are TP-sharded同一个 DP replica 内两个 TP ranks 共同完成 MLP forward；partial output 通过 TP all-reduce 合成。
DATA · DPdifferent samples per replica两个 DP replicas 处理不同数据，但相同 TP coordinate 必须对齐同一份模型分片。
GRADIENT / OPTIMIZERreduce-scatter → local update → all-gatherglobal gradient 直接落成 DP-owned shard；每个 rank 更新自己那段，再 materialize 完整 TP shard。
02 · READINESS CREATES AN OVERLAP WINDOW

通信能否隐藏，首先取决于你有没有在正确时机启动它。

这个 Lab 只证明依赖顺序允许 overlap：W2 communication 的 post 和 wait 之间确实存在独立 backward work。CPU/Gloo 的耗时不证明 GPU 上真的隐藏了多少通信；A7 的 profiler 证据层仍然有效。

03 · WHY TWO GROUPS EXIST AT ONCE

同一个 rank 的“邻居”会随着当前问题改变。

WORLD SIZE 4TP=2 · DP=2
TP groups: [0,1] [2,3]
  ↳ 同一个 data replica 内完成 layer-internal tensor computation

DP groups: [0,2] [1,3]
  ↳ 相同 TP coordinate 的不同 data replicas 汇总 gradient / optimizer state

这就是为什么真实 Megatron 要维护多个 process groups：global rank 只是进程身份；“这一次 collective 应该和谁发生”由并行轴决定。

最终验收不是“collective 全跑完”，而是更新后的每个 TP parameter shard 都等于 dense global-batch SGD。
