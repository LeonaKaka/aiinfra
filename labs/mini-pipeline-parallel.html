LAB A9 · PIPELINE PARALLEL

PP 真正跨 stage 搬的不是整套参数。
Forward 传 activation，Backward 把 activation gradient 送回来。

这个实验把两层模型硬拆成两个进程：rank 0 只拥有第一段权重，rank 1 只拥有第二段权重和 loss。多个 microbatch 依次穿过 stage 边界，再反向把 dL/dh 送回来。最后两边各自的参数梯度必须和单进程 dense model 完全一致。

01 · MODEL OWNERSHIP

先把“谁拥有哪部分模型”钉死，PP 才不会和 DP/TP 混掉。

STAGE 0 · RANK 0x @ W0 → h保存输入 microbatch；forward 把 h 发给下一 stage；backward 收到 dL/dh 后计算 dW0。
P2P BOUNDARYh → · ← dL/dhstage 之间传的是边界 activation 与对应 gradient，不是每个 microbatch 都复制全部参数。
STAGE 1 · RANK 1h @ W1 → loss拥有第二段权重与 loss；backward 计算 dW1 和 dL/dh，再把后者发回 rank 0。
02 · MICROBATCh SCHEDULE

为了先看清依赖，这里故意用最简单的 GPipe-style schedule。

TEACHING SCHEDULE3 microbatches
Forward:   F0  →  F1  →  F2
Backward:  B2  →  B1  →  B0

Stage 0: compute h_i → send(h_i)
Stage 1: recv(h_i) → compute loss_i

Backward reverses the dependency:
Stage 1: backward(loss_i) → send(dh_i)
Stage 0: recv(dh_i) → accumulate dW0

这个顺序故意没有冒充 Megatron 的生产 schedule。真实 Pipeline Parallel 会加入 warmup、steady-state 1F1B、cooldown，甚至 interleaving / virtual pipeline stage 来减少 bubble。这个 Lab 只负责先把stage ownership、microbatch 与 P2P dependency跑对。

03 · RUN + VERIFY

如果跨进程 forward/backward 拼接正确，两个 stage 的参数梯度都应等于 dense reference。

TERMINAL2 ranks
torchrun --standalone --nproc-per-node=2 \
  labs/code/mini_pipeline_parallel.py
