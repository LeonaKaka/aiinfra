LAB B3 · 非阻塞 DATA PLANE

“异步传输”最重要的不是快。
而是 启动 之后，你暂时不用等。

B2 已经有 元数据、块表 和 物理 KV pool，但发送仍然是“做完一件再做下一件”的同步心智模型。这里把每个 K/V block 的传输改成 非阻塞 P2P：Decode 先准备 目标缓冲区 并 post irecv，Prefill post isend；两边拿到 Work 句柄 后先做与 KV 无关的工作，真正需要数据时才 wait()。

01 · 异步 CONTRACT

把一个 transfer 拆成 启动、progress、dependency。

POSTisend / irecv描述 source / destination tensor 与 peer，立即拿到一个 Work 句柄。
INDEPENDENT WORKdo something else只要这段工作不依赖刚才的 KV，就不必立刻阻塞等待传输结束。
DEPENDENCYwork.等待()真正要用 KV 前建立依赖：此时数据必须已经到位。

这就是 重叠 的最小前提，但不是“调用异步 API 就自动加速”。真实 重叠 还取决于 backend 是否异步 progress、CUDA stream/event、NIC/GPU DMA、message size、拓扑，以及你中间是否真的有可并行的计算。

02 · PREALLOCATED DESTINATION

消费端 必须先知道数据会落在哪里。

DECODEallocate recv_k / recv_v blocksirecv(dst_block, src=prefill)
wire →
PREFILLslice K/V blocksisend(src_block, dst=decode)

这里仍然只是普通 torch.distributed P2P，但它已经建立了 NIXL/RDMA 之前必须理解的内存契约：生产端 和 消费端 不只是“传 Python 对象”，而是在讨论一块已经存在的 tensor memory、它的 shape/size，以及何时可以安全读写。

它只是一次 CPU/Gloo 小 tensor 本地运行，用来确认执行顺序：post → independent work → 等待。真正的性能实验必须固定 工作负载、放大传输量、用 GPU/NCCL 或 NIXL，并结合 profiler 时间线 看传输和 compute 是否在时间轴上重叠。

下一步把 异步 dependency 从“整个请求”细化到“每一层”。

① Prefill 每生成一层 KV 就立即发送，不等全部 layers 完成。
② Decode 提前 post receives，但只在进入 layer L 前 等待 KV[L]。
