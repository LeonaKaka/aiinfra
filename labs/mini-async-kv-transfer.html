LAB B3 · NONBLOCKING DATA PLANE

“异步传输”最重要的不是快。
而是 launch 之后，你暂时不用等。

B2 已经有 metadata、block table 和 physical KV pool，但发送仍然是“做完一件再做下一件”的同步心智模型。这里把每个 K/V block 的传输改成 nonblocking P2P：Decode 先准备 destination buffers 并 post irecv，Prefill post isend；两边拿到 Work handle 后先做与 KV 无关的工作，真正需要数据时才 wait()。

01 · ASYNC CONTRACT

把一个 transfer 拆成 launch、progress、dependency。

POSTisend / irecv描述 source / destination tensor 与 peer，立即拿到一个 Work handle。
INDEPENDENT WORKdo something else只要这段工作不依赖刚才的 KV，就不必立刻阻塞等待传输结束。
DEPENDENCYwork.wait()真正要用 KV 前建立依赖：此时数据必须已经到位。

这就是 overlap 的最小前提，但不是“调用异步 API 就自动加速”。真实 overlap 还取决于 backend 是否异步 progress、CUDA stream/event、NIC/GPU DMA、message size、拓扑，以及你中间是否真的有可并行的计算。

02 · PREALLOCATED DESTINATION

Consumer 必须先知道数据会落在哪里。

DECODEallocate recv_k / recv_v blocksirecv(dst_block, src=prefill)
wire →
PREFILLslice K/V blocksisend(src_block, dst=decode)

这里仍然只是普通 torch.distributed P2P，但它已经建立了 NIXL/RDMA 之前必须理解的内存契约：Producer 和 Consumer 不只是“传 Python 对象”，而是在讨论一块已经存在的 tensor memory、它的 shape/size，以及何时可以安全读写。

05 · NEXT

下一步不再只是 async API，而是“怎样证明真的 overlap”。

① 放大 KV payload，并在 GPU 上跑 NCCL P2P。
② 用 CUDA events / profiler 分别标记 compute、post、transfer wait。
③ 尝试 layer-by-layer KV transfer，让第 L 层搬运与第 L+1 层计算重叠。
④ 最后进入 NIXL memory registration、remote descriptor 与 RDMA path；没有对应硬件时只做源码/协议分析，不伪造 benchmark。
