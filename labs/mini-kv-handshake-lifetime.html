LAB B5 · CONTROL PLANE BEFORE RDMA

高速搬内存之前，双方必须先回答：
“你是谁、这块数据是什么、我能不能接、什么时候才能复用？”

B4 已经能 layer-by-layer 地搬 KV，但仍默认两边天然兼容。真实跨实例传输不能这么乐观：模型/KV layout/协议不兼容就不能直接读；远端还要知道 block/地址相关 metadata；Producer 也不能在 Consumer 尚未完成读取时把同一块 KV memory 提前复用。本实验先用一个很小的 control-plane protocol 把这些约束跑通，再对照 NIXL 源码。

01 · CONTROL BEFORE DATA

Handshake 不是“多余的小包”，它决定大 tensor 能不能安全开始传。

DESCRIPTORversion · request · shape · bytesProducer 先描述本次 handoff。Consumer 检查协议版本、shape/capacity 等是否兼容。
ACCEPTcompatible?只有控制面验证通过，Consumer 才接受后续 K/V data plane。
DATAK/V transfer真正的大 tensor 在后面走；control metadata 和 data bytes 是两条不同职责的路径。

toy 脚本的 descriptor 只是几个整数，故意不使用真实地址、rkey 或 NIXL descriptor。它只负责教学：先协商语义，再搬字节。

02 · COMPLETION IS A MEMORY RULE

“send() 已经调用”不等于 source KV 现在就能被覆盖。

GENERATION 1region 7 owns request 501descriptor → accept → transfer
must wait →
COMPLETIONconsumer doneack(request, region, generation)

Producer 只有收到 completion 后，才把 toy region 从 generation 1 推进到 generation 2。这里的 region_id / generation 是我们人为设计的教学协议，但它表达的生命周期约束是真实的：异步 transfer 尚未结束时，源/目标 memory 不能被 allocator 当成普通空闲空间随意复用。

这不是 RDMA memory registration 模拟器。

真实 NIXL registration 会把可传输 memory region 注册给实际 transport，并产生真实 agent/descriptor 信息。这里没有 rkey、NIC、UCX、GPU Direct，也不尝试伪装成它们；只把 handshake 与 lifetime 的必要性变成可执行状态机。

04 · WHAT CURRENT VLLM REALLY EXCHANGES

现在看 NIXL metadata，字段不再是一堆莫名其妙的工程噪声。

COMPATIBILITYNixlHandshakePayload先带 compatibility hash，再带 encoded agent metadata；源码明确用两阶段解码避免不兼容 schema 直接炸掉。
MEMORY / LAYOUTNixlAgentMetadata包含 engine id、agent metadata、KV base addresses、device、block 数量/长度/stride、KV layout、block size 等。
REQUESTRemoteMeta / ReqMeta把 remote block ids、engine/request identity、host/port、expiry 与本地 block mapping 连到某次请求。

注意这里的关键升级：B2 的 block table 解决“逻辑 KV 放在本机哪里”；B5 开始回答“远端哪个 engine 的哪些 blocks、以什么 layout、在什么生命周期内，能被我安全地搬过来”。

05 · SOURCE READING ORDER

进入 NIXL 时先看 metadata，再看 transport；否则很容易只剩 API 名词。

① v1/base.py：看 register_kv_caches()、get_handshake_metadata()、load/save/completion 的抽象契约。
② nixl/metadata.py：看 compatibility hash、NixlAgentMetadata、NixlHandshakePayload、request remote metadata。
③ nixl/base_worker.py：再追 memory registration、peer metadata、TP mapping、transfer handle 与 lease/completion。
④ 最后才问 UCX/RDMA/GPUDirect 怎么把这些 descriptor 变成真正的数据移动。
