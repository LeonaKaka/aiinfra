LAB A7 · PROVE THE OVERLAP

async_op=True 只能制造机会。
Profiler 才能告诉你机会有没有变成真实重叠。

A5 已经把 W2 bucket 的 reduce-scatter 提前到 W1 backward 之前，A6 又加入 TP×DP process groups。现在补上最重要的证据层：脚本用 torch.profiler 和 record_function() 把 forward、gradient-ready、collective launch、继续 backward、wait 全部标到时间线上。CPU/Gloo 只验证事件顺序；只有 GPU/NCCL timeline 真正出现通信 kernel 与 compute kernel 时间区间重叠，才可以说 overlap 发生了。

03 · WHAT COUNTS AS PROOF

GPU 上至少要同时满足三件事，才值得写“communication overlap”。

LAUNCHcollective returns earlyW2 reduce-scatter 被发起后，CPU/host 没有立即在同一位置把整个操作等完。
TIMELINENCCL ∩ computeNCCL reduce-scatter kernel 与后续 backward GEMM / elementwise kernel 在时间轴上真的有重叠区间。
CRITICAL PATHwait shrinks最终 wait 不再承担完整通信时间；最好再比较同步版本与 overlap 版本的 step time。

如果只看到异步 API，却没有第二条 stream 上的 NCCL kernel 与 compute 同时存在，就只能说“代码允许异步”，不能说“性能上隐藏了通信”。
