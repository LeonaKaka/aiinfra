LAB B · PREFILL / DECODE

让 Prefill 算 KV，
让另一进程直接接着 Decode。

KV Connector 最核心的 correctness contract 不是“网络很快”，而是：Decode 收到的远端 KV 必须等价于自己对同一 prompt 重新计算出来的 KV。这个实验先把 Scheduler、paged blocks、NIXL、RDMA 全部拿掉，只验证这条最小契约。

01 · DATA FLOW

两个 rank，分别扮演 Prefill 与 Decode。

RANK 0 · PRODUCERprompt → K,V只对 prompt 做 K/V projection，代表 Prefill 已经完成的状态。
P2P HANDOFFsend K · send V当前用 torch.distributed P2P；真实生产系统可替换成 NIXL/RDMA。
RANK 1 · CONSUMERreceived KV → decode只计算新 token 的 q/k/v，再让 q attend 已收到的 prompt KV。

Rank 1 同时会偷偷做一遍 dense reference：重新从 prompt 计算 K/V。最后比较两条路径的 attention output。如果 handoff 没破坏状态，最大误差应该接近 0。

04 · WHAT IS STILL MISSING

它证明了 KV handoff 的核心，但还不是 vLLM KV Connector。

没有 paged KV block / block table：这里直接传连续的 [S,H] tensor。
没有 Scheduler-side metadata：两边事先知道 shape、src/dst 和请求身份。
没有 async layer-by-layer load/save：send/recv 是显式阻塞式教学路径。
没有 remote block lifetime、lease、failure policy、preemption 与 prefix-cache 协调。
没有 NIXL memory registration、UCX/RDMA、GPUDirect，也没有异构 TP mapping。
这正是实验的用途。

先让“KV 是模型状态，可以由另一执行实体接着消费”变成亲眼可见的事实；然后 08.2–08.5 里的接口、metadata、block mapping 和 transport 才不会混成一团。

06 · UPGRADE PATH

下一步不是立刻写 RDMA，而是逐层增加真实约束。

① 把 KV 切成固定 token blocks，传 block IDs 而不是一个连续 tensor。
② 加 request_id + metadata message，让 consumer 不依赖硬编码 shape。
③ 用 batch_isend_irecv / CUDA stream 做异步传输，测 compute-transfer overlap。
④ 在同机 2 GPU 上记录 P2P timing，再区分 PCIe 与 NVLink 拓扑。
⑤ 最后才换成 vLLM NixlConnector，观察 register_kv_caches、handshake、pull/push worker。
