LAB A11 · EP

EP 的核心不是“有很多专家”。
而是 token 被路由器分流以后，必须去专家真正所在的 rank。

这个实验用 2 个 EP ranks、4 个专家。每个原始 rank 都产生自己的 tokens；确定性路由器为每个 token 指定专家 owner。随后 all-to-all 把 token features 发到远端专家，专家本地计算，再 reverse all-to-all 把结果送回原来的 token owner。最终输出必须与“不分布式、直接按 expert_id 计算”的 reference 一致。

01 · 先路由，再分发

路由器决定“该去哪个专家”，EP communication 负责“真的把 token 搬过去”。

专家归属关系EP=2 · 4 专家
Rank 0 owns Expert 0, Expert 1
Rank 1 owns Expert 2, Expert 3

source tokens
   │
   ├─ router: token -> expert_id -> owner rank
   │
   └─ all-to-all dispatch -> local expert compute
                          -> reverse all-to-all -> source token order

这就是为什么 “专家 Parallel = All-to-All” 仍然是不完整的说法：EP 是专家归属关系 / 路由的并行策略；all-to-all 是一种常见分发器 communication mechanism。

02 · 教学版简化

为了只看通信生命周期，这里故意把路由做成完全均衡。

路由器expert_id = token_id mod 4每个 source rank 恰好有一半 tokens 去 rank 0 专家、一半去 rank 1 专家。
ALL-TO-ALLfixed equal splits不引入 variable split size，先让分发 / 合并的数据对应关系清楚。
专家计算different deterministic function per 专家不同专家得到不同结果，所以错误路由无法悄悄通过 reference check。

真实 MoE 还要面对路由 weights、top-k、capacity、token dropping / padding、load balancing、permutation、TP 与专家-TP 等问题。这个 Lab 明确不模拟这些复杂度。
