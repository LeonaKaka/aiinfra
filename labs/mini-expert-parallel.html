LAB A11 · EXPERT PARALLEL

EP 的核心不是“有很多 experts”。
而是 token 被 router 分流以后，必须去 expert 真正所在的 rank。

这个实验用 2 个 EP ranks、4 个 experts。每个原始 rank 都产生自己的 tokens；确定性 router 为每个 token 指定 expert owner。随后 all-to-all 把 token features 发到远端 expert，expert 本地计算，再 reverse all-to-all 把结果送回原来的 token owner。最终输出必须与“不分布式、直接按 expert_id 计算”的 reference 一致。

01 · ROUTE THEN DISPATCH

router 决定“该去哪个 expert”，EP communication 负责“真的把 token 搬过去”。

EXPERT OWNERSHIPEP=2 · 4 experts
Rank 0 owns Expert 0, Expert 1
Rank 1 owns Expert 2, Expert 3

source tokens
   │
   ├─ router: token -> expert_id -> owner rank
   │
   └─ all-to-all dispatch -> local expert compute
                          -> reverse all-to-all -> source token order

这就是为什么 “Expert Parallel = All-to-All” 仍然是不完整的说法：EP 是 expert ownership / routing 的并行策略；all-to-all 是一种常见 dispatcher communication mechanism。

02 · TEACHING SIMPLIFICATION

为了只看通信生命周期，这里故意把 routing 做成完全均衡。

ROUTERexpert_id = token_id mod 4每个 source rank 恰好有一半 tokens 去 rank 0 experts、一半去 rank 1 experts。
ALL-TO-ALLfixed equal splits不引入 variable split size，先让 dispatch / combine 的数据对应关系清楚。
EXPERT COMPUTEdifferent deterministic function per expert不同 expert 得到不同结果，所以错误路由无法悄悄通过 reference check。

真实 MoE 还要面对 routing weights、top-k、capacity、token dropping / padding、load balancing、permutation、TP 与 expert-TP 等问题。这个 Lab 明确不模拟这些复杂度。
