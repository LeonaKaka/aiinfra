LAB B4 · LAYER-BY-LAYER PIPELINE

不要等所有层 KV 都搬完。
第 L 层只需要在“用到它之前” ready。

B3 已经把 transfer 拆成 launch 与 wait，但仍然把整个 KV 当一个阶段。真实模型有几十层，每层都有自己的 KV。当前 vLLM KVConnectorBase_V1 明确提供 start_load_kv() 与 wait_for_layer_load(layer_name)，并说明后者用于 layer-by-layer pipelining。这个实验把那条依赖关系单独做出来。

01 · PER-LAYER DEPENDENCY

Prefill 生产得越早，Decode 就越不需要等“整车货物”。

PREFILLcompute KV[L]第 L 层 prompt KV 一算完，立即 isend；然后 Prefill 继续算 L+1。
TRANSFERKV[L] in flight后续层的 Prefill compute 与前一层 KV 传输存在并行机会。
DECODEwait only for layer L真正进入 attention layer L 前，才要求 KV[L] 已经 ready。

依赖从“Decode 必须等所有 KV 完成”变成“Decode layer L 只依赖 KV layer L”。这给系统调度出了更多 overlap 空间。

02 · TWO PIPELINES

你要同时想两条流水线：模型层与网络传输。

CONCEPTUAL TIMELINEP / D
Prefill:  compute L0 ─ send L0 ─ compute L1 ─ send L1 ─ ...
                         ╲             ╲
Network:                  transfer L0   transfer L1   ...
                             ╲             ╲
Decode:                  wait L0 → use L0 → wait L1 → use L1 → ...

如果 Decode 到达 L1 时它已经在后台传完，wait_for_layer_load("L1") 可能很短；如果网络跟不上，wait 会直接暴露在关键路径上。性能问题因此会变成“哪一层、哪一段 transfer 没被隐藏”。

这里的 layer pipeline 是教学抽象，不等于 vLLM/NIXL 的实际线程、stream 与 transport 结构。

真正系统还要处理 paged KV layout、request batching、每层 cache group、CUDA stream、registered memory、peer metadata、失败与 preemption。我们这里只验证“per-layer ready dependency”这个最核心的契约。
