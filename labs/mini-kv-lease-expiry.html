LAB B7 · RELEASE WITHOUT CORRUPTION OR LEAKS

远端 KV 释放太早会读坏。
永远不释放又会把显存慢慢吃光。

B5 解决“transfer 没完成前不能复用 memory”，B6 解决“哪块 allocation / region 真正在被传”。最后还缺一个生产系统必须回答的问题：如果 Consumer 挂了、网络断了，Producer 难道永远把 blocks 钉住吗？Lease 给 memory lifetime 加上一个有期限的承诺；heartbeat 表示“我还需要它”，completion 表示“我已经用完”，expiry 则是失联后的 leak-safe fallback。

01 · THE STATE MACHINE

一块远端 KV 只有两条安全释放路径：明确完成，或者租约到期。

PINNEDlease startsProducer 暂时不能把这些 blocks 还给 allocator；同时记录一个 expiry deadline。
ALIVEheartbeat renewsConsumer 仍在使用远端 KV 时周期性续约，把安全窗口继续向后推。
RELEASEcomplete OR expire正常完成可以提前释放；失联时则等 deadline 到期后回收，避免永久泄漏。

这里最重要的不是某个固定 TTL 数字，而是不变量：在仍可能有合法远端读取时不能释放；在对端永久消失时又必须最终能够回收。

03 · STALE MESSAGE

旧请求的 heartbeat 不能把已经复用的新 memory 又“续活”。

脚本用 generation 显式演示这个 ABA-style 风险。generation 是教学字段，不是说当前 vLLM 就用同样的 generation protocol。真正要记住的是：异步系统里的 completion / heartbeat 必须绑定到正确的 request / block lifetime，迟到消息不能影响已经被重新分配的资源。

04 · MAP TO CURRENT VLLM NIXL

当前代码已经能找到这套 lifetime 机制的几个关键锚点。

LEASEkv_lease_duration当前 NIXL scheduler 默认读取 30 秒 lease，并把 heartbeat interval 设成 lease_duration // 6。
PINrequest_finished()需要远端读取的 request 会延迟释放 blocks，并记录基于 perf_counter() 的 expiry deadline。
HEARTBEATheartbeat_by_engineScheduler 按 remote engine 聚合仍需续约的 request，并节流后把 heartbeat metadata 交给 worker。

正常 receive 完成后，scheduler 还会停止对应 request 的 heartbeat。换句话说，lease 不是“定时器小功能”，而是 request lifecycle、block allocator 与远端 transfer completion 之间的资源所有权协议。

05 · CLOCK DOMAIN TRAP

perf_counter() 是进程本地时钟，不能把另一个进程的 deadline 原样拿来比较。

CURRENT SOURCE IDEAcontrol plane
scheduler: stamp expiry in its perf_counter domain
           + attach scheduler_clock

handshake: estimate peer clock offset from round trip

worker: rebase / reason about lifetime in its own clock domain

这是一个非常典型的分布式坑：即使两个数都叫“seconds”，也不代表零点相同。当前 vLLM 的 connector metadata 明确携带 scheduler_clock，NIXL handshake 还会用往返时间估计 peer clock offset。B7 的 virtual clock 故意只有一个时间域，避免把这个工程问题藏在 toy 代码里。

06 · INFERENCE SOFTWARE CAPSTONE

到这里，KV Connector 的软件心智模型已经闭合。

① Scheduler 决定远端 KV 是否可用、需要哪些 blocks。
② Block table / region descriptor 决定逻辑 KV 对应哪块可传输 memory。
③ Handshake 检查兼容性并交换远端 agent/layout 信息。
④ Async / layer-wise transfer 追踪“什么时候发起、什么时候真正需要”。
⑤ Completion + lease / heartbeat / expiry 决定“什么时候可以安全释放”。

再往后就不是继续发明 toy 协议，而是把同一套问题放到真实 NIXL / UCX / RDMA / GPUDirect 环境里验证 transport、带宽、并发与失败恢复。没有对应硬件时，网站会停在源码级解释，不伪造 benchmark。
