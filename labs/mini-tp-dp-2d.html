LAB A6 · 二维进程组

一个 global rank 可以同时属于多个“世界”。
TP 通信和 DP 通信绝不能混在一起。

前五个训练实验每次只盯一个并行维度。真正的 Megatron 会同时有 TP、DP、PP、CP、EP。这里先做最小二维拓扑：4 个进程组成 TP=2 × DP=2。每个 DP 副本内，两张卡一起算同一个样本的 TP layer；而相同 TP 分片的两个副本，再通过另一组 DP 进程组同步参数梯度。

01 · 先画出进程组

同样四个 rank，按不同问题会被切成两套进程组。

GLOBAL RANKSTP=2 · DP=2
                 TP rank 0     TP rank 1
DP replica 0        R0  ←──TP──→  R1
                    ↑             ↑
                    DP            DP
                    ↓             ↓
DP replica 1        R2  ←──TP──→  R3

TP groups = [0,1] [2,3]
DP groups = [0,2] [1,3]

R0 的身份不是单纯“global rank 0”。它同时是 TP 进程组 [0,1] 的 TP-rank 0，也是 DP 进程组 [0,2] 的 DP-rank 0。后面看 Megatron 的 get_tensor_model_parallel_group() / data-parallel 进程组时，必须带着这种二维坐标思考。

02 · 两种不同集合通信

同一个反向传播里，两个 all-reduce 回答的是完全不同的问题。

TP 进程组[0,1] or [2,3]Row-parallel 输出 partial y 要求和；dX 也是来自不同 weight 分片的 contribution，要在副本内求和。
LOCAL 分片 GRADdW1[t] · dW2[t]参数梯度本身仍属于 TP 分片 t，不需要和另一个 TP 分片拼成同一个梯度 tensor。
DP 进程组[0,2] or [1,3]相同 TP 分片在不同数据副本上得到不同 dW；只和“同分片的副本”做 DP 梯度 sync。

这是理解多维并行最重要的一条：先问这次 collective 在哪个 process 进程组里，再问它是什么 collective。只看到 all_reduce 这个函数名，不足以知道它在解决什么问题。

04 · 映射到 Megatron

现在 parallel_state.py 不再是“初始化样板代码”，而是一张通信坐标系。

OUR LABglobal rank → (dp_rank, tp_rank)new_group(TP rows) · new_group(DP columns)
maps to →
MEGATRONcore/parallel_state.pyTP / DP / PP / CP / EP groups and ranks

之后读 tensor_parallel/ 时只盯 TP 进程组；读 distributed_data_parallel.py / distributed 优化器时，再追 DP / DP+CP 等进程组。真实 Megatron 的拓扑远比 2×2 丰富，但所有复杂组合都建立在“一个 rank 同时处于多个正交进程组”这个概念上。

05 · 检查点

如果这四问能不看答案说清，Megatron 的并行坐标系就真正建立了。
