TRACK A · TRAINING INFRA
LAB A1 · TP FORWARD

Mini Megatron TP

Column Parallel W1 + Row Parallel W2。每个 rank 只做自己的 GEMM，最后 all-reduce partial output。

核心问题为什么 forward 在这里通信？
 LAB A2 · TP BACKWARD

Mini TP Backward

手算 dW2、dW1、dX，再和 dense autograd 对照；看清哪些 gradient 保持 sharded，哪些必须求和。

核心问题为什么 backward 的通信位置不同？
 LAB A3 · DATA PARALLEL

DP + Gradient Accumulation

两个 rank 持有相同参数、处理不同样本；先本地累计多个 microbatch，再只做一次 gradient all-reduce。

核心问题“累积”和“同步”为什么是两件事？
 LAB A4 · OPTIMIZER SHARDING

Mini Distributed Optimizer

reduce-scatter 让 global gradient 直接落成 shard；每个 rank 只保留本地 momentum，再 all-gather 更新后的参数。

核心问题为什么 optimizer state 不必每卡复制？
 LAB A5 · COMMUNICATION OVERLAP

Bucketed Async Reduce-Scatter

W2 gradient 先 ready 就先发 async reduce-scatter；backward 继续计算 W1。第一次把“gradient readiness”和“通信启动时机”放到同一条时间线上。

核心问题为什么 bucket ready 后要尽早 launch，而不是等整个 backward？
TRACK B · INFERENCE INFRA
LAB B1 · RAW KV HANDOFF

Mini KV Handoff

Rank 0 Prefill 产生连续 K/V；Rank 1 接收后直接 Decode，并与本地重算 prompt KV 的 reference 对齐。

核心问题远端 KV 能否等价接管模型状态？
 LAB B2 · BLOCK KV

Mini Block KV Handoff

加入 request metadata、固定 token blocks、physical KV pool 和 logical→physical block table。

核心问题逻辑序列如何脱离物理显存位置？
 LAB B3 · ASYNC DATA PLANE

Mini Async KV Transfer

把 block transfer 拆成 isend/irecv launch → independent work → Work.wait()，先建立异步依赖模型。

核心问题什么时候可以不等 KV？
 LAB B4 · LAYER PIPELINE

Layer-wise KV Streaming

Prefill 每算完一层就发送 KV[L]；Decode 只在进入 layer L 前等待该层，形成 per-layer ready dependency。

核心问题为什么不必等所有层 KV 都到齐？
“异步”与“流水”页面都没有把 CPU timing 当成性能结论。

9 个脚本目前的第一验收标准仍是 correctness 与依赖结构。代码在 ≥2 张 CUDA GPU 时自动切 NCCL，但要证明 communication/compute overlap，必须在 GPU 上用 profiler 看到时间区间真正重叠；NIXL/RDMA 则还需要对应硬件与软件栈。
