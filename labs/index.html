TRACK A · TRAINING INFRA
LAB A1 · TP FORWARD

Mini Megatron TP

Column Parallel W1 + Row Parallel W2。每个 rank 只做自己的 GEMM，最后 all-reduce partial output。

核心问题为什么 forward 在这里通信？
 LAB A2 · TP BACKWARD

Mini TP Backward

手算 dW2、dW1、dX，再和 dense autograd 对照；看清哪些 gradient 保持 sharded，哪些必须求和。

核心问题为什么 backward 的通信位置不同？
 LAB A3 · DATA PARALLEL

DP + Gradient Accumulation

两个 rank 持有相同参数、处理不同样本；先本地累计多个 microbatch，再只做一次 gradient all-reduce。

核心问题“累积”和“同步”为什么是两件事？
 LAB A4 · OPTIMIZER SHARDING

Mini Distributed Optimizer

reduce-scatter 让 global gradient 直接落成 shard；每个 rank 只保留本地 momentum，再 all-gather 更新后的参数。

核心问题为什么 optimizer state 不必每卡复制？
 LAB A5 · COMMUNICATION OVERLAP

Bucketed Async Reduce-Scatter

W2 gradient 先 ready 就先发 async reduce-scatter；backward 继续计算 W1。第一次把“gradient readiness”和“通信启动时机”放到同一条时间线上。

核心问题为什么 bucket ready 后要尽早 launch，而不是等整个 backward？
 LAB A6 · 2D PROCESS GROUPS

TP × DP 2D Topology

4 ranks 组成 TP=2 × DP=2。TP rows 负责 layer 内 partial output/dX，DP columns 只同步相同 TP shard 的参数梯度。

核心问题为什么同一个 rank 会同时属于多个通信 group？
 LAB A7 · PROFILER EVIDENCE

Profiler-ready Overlap

用 torch.profiler 标出 gradient-ready、async reduce-scatter、继续 backward 与 wait；CPU 验顺序，GPU/NCCL 才能证明真实 overlap。

核心问题怎样证明 async 真的隐藏了通信？
 LAB A8 · SEQUENCE PARALLEL

Mini Sequence Parallel

TP partial output 不先复制成 full activation，而是 reduce-scatter 直接落成 sequence shard，再与 dense reference 对齐。

核心问题SP 为什么通常和 TP 的 layout transition 绑在一起？
 LAB A9 · PIPELINE PARALLEL

Mini Pipeline Parallel

两个 stages 分别拥有模型的一半；microbatch forward 传 activation，backward 把 activation gradient 送回来。

核心问题PP 的 stage boundary 到底传什么？
 LAB A10 · CONTEXT PARALLEL

Mini Context Parallel

Q shard 保持本地，KV chunks 轮转；用 global positions 保持 causal semantics，并对齐 dense attention。

核心问题sequence 切开后，Attention 怎样仍看到全局 context？
 LAB A11 · EXPERT PARALLEL

Mini Expert Parallel

router → all-to-all dispatch → local experts → reverse combine；同时验证数值和 token identity。

核心问题token 为什么必须去 expert owner，再回到原顺序？
 LAB A12 · TRAINING CAPSTONE

Mini Training System

把 TP×DP、gradient readiness、async reduce-scatter、sharded optimizer update 与 parameter all-gather 串成一次完整 training step。

核心问题这些并行机制在一次 step 里如何真正接起来？
TRACK B · INFERENCE INFRA
LAB B1 · RAW KV HANDOFF

Mini KV Handoff

Rank 0 Prefill 产生连续 K/V；Rank 1 接收后直接 Decode，并与本地重算 prompt KV 的 reference 对齐。

核心问题远端 KV 能否等价接管模型状态？
 LAB B2 · BLOCK KV

Mini Block KV Handoff

加入 request metadata、固定 token blocks、physical KV pool 和 logical→physical block table。

核心问题逻辑序列如何脱离物理显存位置？
 LAB B3 · ASYNC DATA PLANE

Mini Async KV Transfer

把 block transfer 拆成 isend/irecv launch → independent work → Work.wait()，先建立异步依赖模型。

核心问题什么时候可以不等 KV？
 LAB B4 · LAYER PIPELINE

Layer-wise KV Streaming

Prefill 每算完一层就发送 KV[L]；Decode 只在进入 layer L 前等待该层，形成 per-layer ready dependency。

核心问题为什么不必等所有层 KV 都到齐？
 LAB B5 · CONTROL PLANE

KV Handshake + Lifetime

在 NIXL/RDMA 前先跑通 compatibility descriptor → accept → data transfer → completion；理解 metadata 与 memory lifetime 为什么必须存在。

核心问题为什么高速搬内存之前必须先握手，结束后还要 completion？
 LAB B6 · MEMORY REGISTRATION MODEL

Registered Region Descriptor

让多个 layer view 共享一个 storage allocation，再分开描述 region base、block length 与 block stride，理解 NIXL registration 前的内存几何。

核心问题为什么 allocation 和 transfer region 不是一回事？
 LAB B7 · RESOURCE LIFETIME

KV Lease / Expiry

用 heartbeat、completion 与 expiry 状态机解决两个相反风险：远端仍在读时不能释放，对端失联后又不能永久钉住 blocks。

核心问题怎样既不提前释放，也不永久泄漏 KV？
 LAB B8 · INFERENCE CAPSTONE

Mini Inference Engine

把 local KV hit、remote KV、cold prefill 放进同一个 scheduler token budget，再接上 block table、async load、decode 与 completion lifetime。

核心问题一个 request 从“可调度”到“可安全释放”经历哪些系统状态？
“异步”“profiler”“handshake”页面都没有把 CPU timing 当成性能结论。

20 个脚本目前的第一验收标准仍是 correctness 与依赖结构。代码会在可见 CUDA GPU 数量不少于当前实验 world size 时自动切 NCCL；要证明 communication/compute overlap，必须在 GPU profiler 里看到时间区间真正重叠。NIXL/RDMA 仍需要对应硬件与软件栈。
