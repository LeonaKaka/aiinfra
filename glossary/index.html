下面不是百科全书式定义，而是这门课里的“工作定义”。当你在 Megatron / vLLM 源码里撞到一个词，先用这一句恢复上下文，再回对应课程页深挖。

HOW TO USE先找类别，再找词。模型与张量 → GPU → 分布式 → Megatron → 推理 → vLLM / KV Connector。不要按字母顺序背。

Tensor / Model

SHAPE[B, S, H]

Batch、Sequence、Hidden 三个最常见维度；后面几乎所有切分、显存和通信分析都从 shape 开始。

先问：哪个维度被切了？
GEMMGeneral Matrix Multiply

大多数 Linear / MLP 的核心矩阵乘；LLM 训练与 Prefill 的大量算力最终都落成 GEMM。

不要把“模型层”与“GPU kernel”混成一个层级。
ATTENTIONQ / K / V

Query 用来查询历史，Key 用来匹配，Value 提供被聚合的信息；KV Cache 保存的是历史 token 的 K/V。

Decode 时新 token 的 Q 是新的，历史 K/V 可以复用。
GQAGrouped-Query Attention

多个 Q heads 共享更少的 KV heads，用较小 KV Cache 换取近似的注意力能力。

影响 KV Cache 大小，也影响 TP / KV layout。

GPU Systems

HBMHigh Bandwidth Memory

GPU 主显存。容量决定“塞不塞得下”，带宽常决定 Decode / memory-bound kernel 能跑多快。

容量和带宽是两个不同问题。
KERNELCUDA kernel

真正被 GPU 执行的一段并行程序。一个 PyTorch op 可能触发一个或多个 kernel。

Python function 不等于一次 GPU kernel。
COMPUTE BOUND算力受限

瓶颈主要在数学运算吞吐，例如大型 GEMM 已经把 Tensor Cores 吃满。

加带宽不一定有用。
MEMORY BOUND带宽受限

GPU 大量时间在搬数据而不是做算术；Decode 小 batch 常更容易落到这里。

这也是 KV Cache 工程重要的原因。

Distributed

RANK进程编号

分布式进程在某个 process group 里的身份。global rank 与 TP/DP/PP group rank 可能不同。

先问“在哪个 group 里的 rank”。
ALL-REDUCE聚合后每个 rank 都拿到结果

典型用途是 DP 梯度同步，或 Row Parallel 输出求和。

通信结果是 replicated。
ALL-GATHER把各 rank 的 shard 拼回来

每个 rank 提供一块，最后大家都得到完整结果。

常见代价是临时显存上升。
REDUCE-SCATTER先聚合，再把结果切开

非常适合“结果本来就不需要每个 rank 都完整保存”的场景，例如 sharded optimizer / sequence parallel。

可以看成 all-reduce 的“只留自己那片”。
ALL-TO-ALL每个 rank 给每个 rank 发不同数据

MoE token dispatch 的典型通信模式，因为不同 token 会被路由到不同 expert。

比 all-reduce 更依赖流量分布与负载均衡。
NCCLNVIDIA Collective Communications Library

GPU 集群里常用的 collective / P2P 通信库，PyTorch distributed 与 Megatron 都大量依赖它。

NCCL 不是网络硬件本身。

Megatron / Training

DPData Parallel

每个 rank 有模型副本，吃不同数据，再同步梯度。

主要切 batch，不切单个 layer 的权重。
TPTensor Parallel

把一个 layer 内的大矩阵按维度切到多张 GPU，让单层也能并行和分摊显存。

代价是 layer 内出现 collective。
PPPipeline Parallel

把不同层放到不同 stage，通过 microbatch 让多个 stage 同时工作。

核心敌人是 pipeline bubble。
SPSequence Parallel

在 TP 基础上进一步减少某些 activation 的复制，让 sequence 相关张量分片保存。

常与 reduce-scatter / all-gather 配对。
CPContext Parallel

针对长上下文，把 sequence/context 维度的 attention 工作和状态分到多 GPU。

目标不是一般 activation，而是长 context 的 attention 成本。
EPExpert Parallel

MoE 的 experts 分散在不同 rank，token 按 router 结果跨 rank dispatch。

通常会引入 all-to-all。
1F1BOne Forward One Backward

Pipeline steady state 里交替做一个 microbatch forward 与一个 backward，以降低 bubble / activation 峰值。

这是调度策略，不是新的并行维度。
DISTRIBUTED OPTIMIZER优化器状态分片

让 DP ranks 不再各自保存完整 optimizer state / grad buffer，从而显著降低显存复制。

与 ZeRO 思路相近，但要看具体实现细节。

Inference / vLLM

PREFILL一次处理整个 prompt

prompt token 并行进入 Transformer，通常更像大矩阵计算，主要产出首轮 hidden 与 KV Cache。

常直接影响 TTFT。
DECODE一次生成一个新 token

每步只新增少量计算，但要持续读取历史 KV，因此经常更受 memory bandwidth / batching 影响。

常直接影响 ITL。
TTFTTime To First Token

从请求进入系统到用户看到第一个 token 的端到端延迟。

包含 queue、Prefill、KV handoff、Decode admission 等。
ITL / TPOTInter-Token Latency

生成阶段相邻 token 的延迟，用来描述用户看到流式输出有多“顺”。

平均值之外还要看 p95/p99。
CONTINUOUS BATCHING动态重组正在生成的请求

请求不用等整批一起结束；每个 step 都可以让新请求加入、旧请求退出。

它把调度变成推理性能核心。
PAGED KV把 KV Cache 按 block 管理

请求的逻辑 token 序列不要求占一大段连续 GPU 显存，而是映射到物理 KV blocks。

类似虚拟内存思想，但不是操作系统页表本身。
PREFIX CACHE复用已算过的前缀 KV

多个请求共享相同 prompt prefix 时，不必重复做全部 Prefill。

需要 block hash、引用计数与正确的失效逻辑。
PREEMPTION为了资源让某请求暂时退出运行

KV block 不够或调度压力过大时，系统可能回收资源并让请求以后 resume / recompute。

会直接影响 tail latency。

KV Connector / Network

KV CONNECTOR跨执行实体加载 / 保存 KV 的接口层

把 Scheduler 的“外部 KV 在哪里”与 Worker 的“怎么实际搬 KV”连接起来。

Connector 不等于某一种 transport。
P/D DISAGGREGATIONPrefill / Decode 分离

让不同实例专门做 Prefill 与 Decode，并通过 KV handoff 连接两阶段。

主要用于独立调 TTFT / ITL 与尾延迟，不会天然提高吞吐。
RDMARemote Direct Memory Access

让一台机器直接读写另一台机器注册好的内存区域，尽量绕开远端 CPU 的数据复制路径。

它是一类远程内存访问机制，不是单一产品名。
GPUDIRECT RDMANIC 直接访问 GPU memory

减少 GPU↔CPU staging，让跨节点 GPU tensor 传输更直接。

需要硬件、驱动、NIC、拓扑和软件栈共同支持。
UCXUnified Communication X

统一多种高速 transport 的通信框架，NIXL 可以用它作为后端之一。

UCX 与 NCCL 解决的抽象层次不同。
NIXLNVIDIA Inference Xfer Library

为 AI inference 数据传输提供 memory registration、agent / metadata、异步 transfer 等能力，vLLM NixlConnector 用它搬 KV。

在 vLLM 里还要叠加 Scheduler / Connector 协议。
HANDSHAKE传输前交换能力与地址信息

双方确认 engine、rank、memory region、layout、compatibility 等，才能安全建立后续 transfer。

控制面成功不代表数据面一定成功。
LEASE / TTL远端 KV 的生命周期

Producer 不能无限期占着 blocks 等 Consumer；lease / TTL 用来决定什么时候可以安全回收。

这是 correctness + capacity 问题，不只是超时参数。
