张量到底是什么？

先别急着记PyTorch应用程序编程接口（API）。人工智能（AI）基础设施里最先要学会的，其实是一种“看形状”的能力：数据现在是什么形状、下一步会变成什么形状、它占多少内存、如果把它切到多张图形处理器（GPU）上该怎么切。

这节课结束时，你应该能做到：
  • 看到 [B, S, H] 不再把它当成神秘缩写。
  • 区分标量、向量、矩阵与更高维张量。
  • 用一个实际句子解释批次、序列长度、隐藏维度。
  • 区分张量的逻辑形状与底层存储/布局，理解视图（view）、步长（stride）和连续存储（contiguous）为什么会影响 GPU 内核与数据搬运。
  • 理解为什么以后学Megatron时，“沿哪个维度切张量”会成为核心问题。
01 · 什么是张量

先把张量想成“带形状的一块数字”。

如果你只记一句话，就记这句。张量不需要一开始就从抽象数学定义理解。对我们这条AI基础设施学习路线来说，它首先是一块被组织成某种形状的数据。

0D标量3.14
1D向量[0.2, 0.8, -1.1]
2D矩阵[[1,2],[3,4]]
3D+张量[B, S, H]

严格说，标量、向量、矩阵也都可以看作张量，只是维数分别是0、1、2。深度学习里我们经常处理3维、4维甚至更高维的数据，所以大家统一叫张量。

Infra视角：张量的“数字是什么”当然重要，但系统工程里你会频繁关心另外三件事：形状、数据类型、设备。

02 · 第一件事：看形状

[B, S, H] 是以后最常见的三维形状。

先看Transformer里非常典型的一块数据。假设它的形状是：

X.形状 = [B, S, H]
B · 批次一次同时处理多少条样本
S · sequence每条样本有多少个token
H · hidden每个token用多少个数字表示

比如 [2, 5, 8]，你可以把它读成：这批数据有2条句子；每条句子暂时统一成5个token；每个token当前由8个数字表示。

批次ITEM 0
我在学AIInfra

5个token，每个token背后不是一个数字，而是一条长度为H的向量。

批次ITEM 1
GPU正在计算这个张量

把两条样本叠在一起，于是最外层多出批次这个维度。

如果 H = 8，那么每个token对应8个浮点数；如果现实模型里 H = 4096，每个token就会对应4096个数。现在先不要管这些数到底代表什么，只要先把形状读顺。

03 · 在 PyTorch 里看张量

用4行代码亲手造出它。

下面这段代码不用背。它只是把刚才的概念变成一个你可以运行的对象。

python01_tensor.py
# shape = [batch, sequence, hidden]
import torch

X = torch.randn(2, 5, 8)
print(X.shape)       # torch.Size([2, 5, 8])
print(X.dtype)       # usually torch.float32
print(X.device)      # cpu, or cuda:0 on GPU

现在你第一次看到了我们刚才说的三个系统属性：

形状

给出各个维度的长度；总元素数由这些维度长度的乘积决定。它决定后面矩阵乘法怎么做，也决定能不能沿某一维切分。

数据类型

每个数字用 FP32、FP16、BF16 还是别的格式存。它直接影响显存占用和计算性能。

设备

这块数据现在在中央处理器（CPU）、GPU 0还是GPU 1。分布式系统里，“数据在哪里”会极其重要。

04 · 从 AI Infra 角度看张量

为什么Infra工程师这么在意形状？

因为形状一旦确定，很多系统问题就开始可以计算了。假设 X.shape = [2, 5, 8]，总元素数就是：

mental math内存
elements = 2 × 5 × 8 = 80

if FP32: 80 × 4 bytes = 320 bytes
if FP16: 80 × 2 bytes = 160 bytes

这个玩具例子当然很小。但当形状变成 [8, 131072, 8192] 时，你会立刻意识到：只是激活值就可能非常大。以后学Context Parallel、Sequence Parallel时，本质上都在继续问一个熟悉的问题：

这块大张量，能不能沿某个维度切开，让不同GPU各保存一部分？

05 · 存储、视图与步长

同一个形状，不一定以同一种方式躺在内存里。

到目前为止，我们一直把张量当成“带形状的数字块”。这对读模型计算已经够用，但读AI基础设施还差一层：形状描述的是逻辑索引空间，存储与布局描述这些元素怎样映射到底层内存。两块张量可以拥有相同形状，却有不同的步长，甚至共享同一块存储。

python形状vs布局
x = torch.arange(12).reshape(3, 4)
y = x.transpose(0, 1)

print(x.shape, x.stride())  # [3,4], (4,1)
print(y.shape, y.stride())  # [4,3], (1,4)
print(y.is_contiguous())    # False

z = y.contiguous()
print(z.stride())           # materialize a contiguous layout
存储

底层真正拥有内存的分配。多个张量/视图可以引用同一块存储，而不是每次都复制数据。

步长

某一维索引增加1时，在底层存储里要跨过多少个元素。它把“逻辑坐标”映射到“物理位置”。

连续存储

元素是否按当前逻辑维度顺序紧密排列。某些kernel或传输 path可以处理任意步长，另一些路径会要求或更偏好连续存储缓冲区。

transpose 常常只改变视图的形状/步长，而不立即复制存储；contiguous() 则可能真的分配新内存并重排数据。以后看到re形状、permute、视图、copy时，要开始问：这是只改了“怎么看”，还是实际搬了数据？

为什么这对后面重要：07.4的block table和08.4的registered 内存 / 传输 region都会把“逻辑张量”继续落到更具体的地址、offset、步长与lifetime。现在先建立一个底线：logical形状 ≠ physical布局。

06 · 这些概念后面会用到哪里

这就是它和Megatron的第一条连接线。

现在你还不用学张量并行。但可以先偷看未来的问题。一个Linear层通常会出现类似：

next conceptlinear algebra
X: [B, S, H]
W: [H, 4H]

Y = X @ W

# Megatron 的问题：
# W 太大时，能不能把它切给 GPU 0 和 GPU 1？
# 如果切了，X / Y 要不要跟着切？
# 中间需要 all-reduce 还是 all-gather？

所以我们今天学 [B,S,H] 不是为了记符号。它是在搭后面所有“怎么切、怎么搬、怎么通信”的地基。

CHECKPOINT不要跳过

能答出来，再进下一课。

1. [4, 1024, 4096] 里的4096是什么意思？
它是隐藏维度：当前每个token用一个长度为4096的向量表示。
2. 为什么FP16张量通常比同形状的FP32张量少一半显存？
因为元素数量完全相同，但每个FP32元素通常占4 bytes，FP16占2 bytes。
3. 为什么“这块张量在cuda:0还是cuda:1”以后会很重要？
因为跨GPU使用数据往往意味着通信或拷贝。AI基础设施的大量性能问题，就是在研究哪些数据必须移动、移动多少、什么时候移动。
4. 两个张量的形状一样，是否意味着它们的底层内存布局也一定一样？
不一定。形状只说明各维长度；transpose/视图等操作可以让张量拥有不同步长，甚至共享同一存储。是否连续存储、是否需要实际copy，是另一层问题。
