Tensor 到底是什么？

先别急着记 PyTorch Application Programming Interface (API，应用程序编程接口)。Artificial Intelligence (AI，人工智能) Infra 里最先要学会的，其实是一种“看形状”的能力：数据现在是什么 shape、下一步会变成什么 shape、它占多少内存、如果把它切到多张 Graphics Processing Unit (GPU，图形处理器) 上该怎么切。

这节课结束时，你应该能做到：
  • 看到 [B, S, H] 不再把它当成神秘缩写。
  • 区分 scalar、vector、matrix 与更高维 tensor。
  • 用一个实际句子解释 batch、sequence length、hidden size。
  • 区分 tensor 的逻辑 shape 与底层 storage/layout，理解 view、stride、contiguous 为什么会影响 kernel 与数据搬运。
  • 理解为什么以后学 Megatron 时，“沿哪个维度切 tensor”会成为核心问题。
01 · WHAT IS A TENSOR

先把 Tensor 想成“带形状的一块数字”。

如果你只记一句话，就记这句。Tensor 不需要一开始就从抽象数学定义理解。对我们这条 AI Infra 学习路线来说，它首先是一块被组织成某种形状的数据。

0DScalar3.14
1DVector[0.2, 0.8, -1.1]
2DMatrix[[1,2],[3,4]]
3D+Tensor[B, S, H]

严格说，scalar、vector、matrix 也都可以看作 tensor，只是维数分别是 0、1、2。深度学习里我们经常处理 3 维、4 维甚至更高维的数据，所以大家统一叫 tensor。

Infra 视角：Tensor 的“数字是什么”当然重要，但系统工程里你会频繁关心另外三件事：shape、dtype、device。

02 · THE FIRST SHAPE

[B, S, H] 是以后最常见的三维形状。

先看 Transformer 里非常典型的一块数据。假设它的 shape 是：

X.shape = [B, S, H]
B · batch一次同时处理多少条样本
S · sequence每条样本有多少个 token
H · hidden每个 token 用多少个数字表示

比如 [2, 5, 8]，你可以把它读成：这批数据有 2 条句子；每条句子暂时统一成 5 个 token；每个 token 当前由 8 个数字表示。

BATCH ITEM 0
我在学AIInfra

5 个 token，每个 token 背后不是一个数字，而是一条长度为 H 的向量。

BATCH ITEM 1
GPU正在计算这个Tensor

把两条样本叠在一起，于是最外层多出 batch 这个维度。

如果 H = 8，那么每个 token 对应 8 个浮点数；如果现实模型里 H = 4096，每个 token 就会对应 4096 个数。现在先不要管这些数到底代表什么，只要先把 shape 读顺。

03 · SEE IT IN PYTORCH

用 4 行代码亲手造出它。

下面这段代码不用背。它只是把刚才的概念变成一个你可以运行的对象。

python01_tensor.py
# shape = [batch, sequence, hidden]
import torch

X = torch.randn(2, 5, 8)
print(X.shape)       # torch.Size([2, 5, 8])
print(X.dtype)       # usually torch.float32
print(X.device)      # cpu, or cuda:0 on GPU

现在你第一次看到了我们刚才说的三个系统属性：

shape

给出各个维度的长度；总元素数由这些维度长度的乘积决定。它决定后面矩阵乘法怎么做，也决定能不能沿某一维切分。

dtype

每个数字用 32-bit Floating Point (FP32，32 位浮点)、16-bit Floating Point (FP16，16 位浮点)、Brain Floating Point 16 (BF16，BF16 16 位浮点) 还是别的格式存。它直接影响显存和计算性能。

device

这块数据现在在 Central Processing Unit (CPU，中央处理器)、GPU 0 还是 GPU 1。分布式系统里，“数据在哪里”会极其重要。

04 · INFRA VIEW

为什么 Infra 工程师这么在意 shape？

因为 shape 一旦确定，很多系统问题就开始可以计算了。假设 X.shape = [2, 5, 8]，总元素数就是：

mental mathmemory
elements = 2 × 5 × 8 = 80

if FP32: 80 × 4 bytes = 320 bytes
if FP16: 80 × 2 bytes = 160 bytes

这个玩具例子当然很小。但当 shape 变成 [8, 131072, 8192] 时，你会立刻意识到：只是 activation 就可能非常大。以后学 Context Parallel、Sequence Parallel 时，本质上都在继续问一个熟悉的问题：

这块大 Tensor，能不能沿某个维度切开，让不同 GPU 各保存一部分？

05 · STORAGE / VIEW / STRIDE

同一个 shape，不一定以同一种方式躺在内存里。

到目前为止，我们一直把 tensor 当成“带 shape 的数字块”。这对读模型计算已经够用，但读 AI Infra 还差一层：shape 描述的是逻辑索引空间，storage/layout 描述这些元素怎样映射到底层内存。两块 tensor 可以拥有相同 shape，却有不同的 stride，甚至共享同一块 storage。

pythonshape vs layout
x = torch.arange(12).reshape(3, 4)
y = x.transpose(0, 1)

print(x.shape, x.stride())  # [3,4], (4,1)
print(y.shape, y.stride())  # [4,3], (1,4)
print(y.is_contiguous())    # False

z = y.contiguous()
print(z.stride())           # materialize a contiguous layout
storage

底层真正拥有内存的 allocation。多个 tensor/view 可以引用同一块 storage，而不是每次都复制数据。

stride

某一维索引增加 1 时，在底层 storage 里要跨过多少个元素。它把“逻辑坐标”映射到“物理位置”。

contiguous

元素是否按当前逻辑维度顺序紧密排列。某些 kernel 或 transfer path 可以处理任意 stride，另一些路径会要求或更偏好 contiguous buffer。

transpose 常常只改变 view 的 shape/stride，而不立即复制 storage；contiguous() 则可能真的分配新内存并重排数据。以后看到 reshape、permute、view、copy 时，要开始问：这是只改了“怎么看”，还是实际搬了数据？

为什么这对后面重要：07.4 的 block table 和 08.4 的 registered memory / transfer region 都会把“逻辑 tensor”继续落到更具体的地址、offset、stride 与 lifetime。现在先建立一个底线：logical shape ≠ physical layout。

06 · WHERE THIS LEADS

这就是它和 Megatron 的第一条连接线。

现在你还不用学 Tensor Parallel。但可以先偷看未来的问题。一个 Linear 层通常会出现类似：

next conceptlinear algebra
X: [B, S, H]
W: [H, 4H]

Y = X @ W

# Megatron 的问题：
# W 太大时，能不能把它切给 GPU 0 和 GPU 1？
# 如果切了，X / Y 要不要跟着切？
# 中间需要 all-reduce 还是 all-gather？

所以我们今天学 [B,S,H] 不是为了记符号。它是在搭后面所有“怎么切、怎么搬、怎么通信”的地基。

CHECKPOINT不要跳过

能答出来，再进下一课。

1. [4, 1024, 4096] 里的 4096 是什么意思？
它是 hidden size：当前每个 token 用一个长度为 4096 的向量表示。
2. 为什么 FP16 tensor 通常比同 shape 的 FP32 tensor 少一半显存？
因为元素数量完全相同，但每个 FP32 元素通常占 4 bytes，FP16 占 2 bytes。
3. 为什么“这块 tensor 在 cuda:0 还是 cuda:1”以后会很重要？
因为跨 GPU 使用数据往往意味着通信或拷贝。AI Infra 的大量性能问题，就是在研究哪些数据必须移动、移动多少、什么时候移动。
4. 两个 tensor 的 shape 一样，是否意味着它们的底层内存布局也一定一样？
不一定。shape 只说明各维长度；transpose/view 等操作可以让 tensor 拥有不同 stride，甚至共享同一 storage。是否 contiguous、是否需要实际 copy，是另一层问题。
