张量到底是什么？

先别急着记 PyTorch（深度学习框架） API（应用程序编程接口）。PyTorch 是本课程用来演示 tensor、自动求导和训练代码的主要框架；API 是软件组件之间约定的调用方式。这里的 AI（人工智能） Infra 指支撑大模型训练和推理的计算基础设施。最先要学会“看 tensor（张量）”：tensor 是多维数组，也是模型中数据和参数的基本载体。先看 shape（形状），它描述每一维的长度；再估算 memory（内存），它是保存数据和模型状态的存储空间；最后判断是否要切到多张 GPU（图形处理器），GPU 是执行大规模并行计算的主要设备。

这节课结束时，你应该能做到：
  • 看到 [B, S, H] 不再把它当成神秘缩写。
  • 区分标量、向量、矩阵与更高维张量。
  • 用一个实际句子解释批次、序列长度、隐藏维度。
  • 区分 tensor 的逻辑 shape 与底层存储方式，理解“怎么看数据”和“数据实际怎么放”为什么会影响 GPU 计算与数据搬运。
  • 理解为什么以后学习模型并行时，“沿哪个维度切张量”会成为核心问题。
01 · 什么是张量

先把张量想成“带形状的一块数字”。

如果你只记一句话，就记这句。张量不需要一开始就从抽象数学定义理解。对我们这条AI基础设施学习路线来说，它首先是一块被组织成某种形状的数据。

0D标量3.14
1D向量[0.2, 0.8, -1.1]
2D矩阵[[1,2],[3,4]]
3D+张量[B, S, H]

严格说，标量、向量、矩阵也都可以看作张量，只是维数分别是0、1、2。深度学习里我们经常处理3维、4维甚至更高维的数据，所以大家统一叫张量。

Infra 视角：tensor 里的数值当然重要，但系统工程里会频繁直接检查 shape、dtype（数据类型）和 device（设备位置）。dtype 规定每个元素用什么数值格式存储；device 表示 tensor 当前位于 CPU、哪张 GPU 或其它设备。CPU（中央处理器）主要承担 Python 控制流、调度、数据准备与部分通信控制。这些名字和下面 PyTorch 代码中的属性名完全一致。

02 · 第一件事：看形状

[B, S, H] 是以后最常见的三维形状。

先看 Transformer（Transformer 模型）里非常典型的一块数据。Transformer 是现代大语言模型常用的基础网络结构。再认识四个名字：token（词元）是语言模型处理文本时使用的基本离散单位；batch（批次）表示一次并行送入模型处理的一组样本；sequence（序列）是一串按顺序排列的 token；hidden dimension（隐藏维度）表示每个 token 隐藏表示的向量宽度。假设这块 tensor 的 shape 是：

X.shape = [B, S, H]
B · batch一次同时处理多少条样本
S · sequence每条样本有多少个token
H · hidden每个token用多少个数字表示

比如 [2, 5, 8]，你可以把它读成：这批数据有2条句子；每条句子暂时统一成5个token；每个token当前由8个数字表示。

BATCH ITEM 0
我在学AIInfra

5个token，每个token背后不是一个数字，而是一条长度为H的向量。

BATCH ITEM 1
GPU正在计算这个Tensor

把两条样本叠在一起，于是最外层多出 batch 这个维度。

如果 H = 8，那么每个token对应8个浮点数；如果现实模型里 H = 4096，每个token就会对应4096个数。现在先不要管这些数到底代表什么，只要先把形状读顺。

03 · 在 PyTorch 里看张量

用4行代码亲手造出它。

下面这段代码不用背。它只是把刚才的概念变成一个你可以运行的对象。

python01_tensor.py
# shape = [batch, sequence, hidden]
import torch

X = torch.randn(2, 5, 8)
print(X.shape)       # torch.Size([2, 5, 8])
print(X.dtype)       # usually torch.float32
print(X.device)      # cpu, or cuda:0 on GPU

现在你第一次看到了刚才说的三个 PyTorch 属性：

shape

给出各个维度的长度；总元素数由这些维度长度的乘积决定。它决定后面矩阵乘法怎么做，也决定能不能沿某一维切分。

dtype

常见格式包括 FP32（32 位浮点）、FP16（16 位浮点）和 BF16（16 位脑浮点）。FP32 每个元素通常占 4 bytes；FP16 和 BF16 通常占 2 bytes，其中 BF16 的指数范围更接近 FP32。dtype 会直接影响显存占用和计算性能。

device

这块数据现在在 CPU、GPU 0 还是 GPU 1。分布式系统里，“数据在哪里”会极其重要。

04 · 从系统角度看张量

为什么 Infra 工程师这么在意 shape？

因为形状一旦确定，很多系统问题就开始可以计算了。假设 X.shape = [2, 5, 8]，总元素数就是：

mental math内存
elements = 2 × 5 × 8 = 80

if FP32: 80 × 4 bytes = 320 bytes
if FP16: 80 × 2 bytes = 160 bytes

这个玩具例子当然很小。但当形状变成 [8, 131072, 8192] 时，你会立刻意识到：只是激活值就可能非常大。以后学习上下文并行、序列并行时，本质上都在继续问一个熟悉的问题：

这块大张量，能不能沿某个维度切开，让不同 GPU 各保存一部分？

05 · 存储、视图与步长

同一个 shape，不一定以同一种内存布局躺在内存里。

到目前为止，我们一直把 tensor 当成“带 shape 的数字块”。读 AI Infra 还差一层：storage（底层存储）是真正承载 tensor 数据的内存区域；layout（内存布局）描述逻辑维度怎样映射到底层 storage；stride（步长）表示某一维索引增加 1 时底层地址要跨多少元素。两块 tensor 可以拥有相同 shape，却有不同 stride，甚至共享同一块 storage。

下面代码还会遇到 reshape（重塑形状）、transpose（转置）和 contiguous（连续存储）。reshape 改变 tensor 的逻辑 shape，必要时可能发生数据重排；transpose 交换维度顺序，通常只先改变访问方式；contiguous 表示数据是否按当前逻辑维度顺序紧密排列。

pythonshape vs layout
x = torch.arange(12).reshape(3, 4)
y = x.transpose(0, 1)

print(x.shape, x.stride())  # [3,4], (4,1)
print(y.shape, y.stride())  # [4,3], (1,4)
print(y.is_contiguous())    # False

z = y.contiguous()
print(z.stride())           # materialize a contiguous layout
storage

多个 tensor 可以通过 view（视图）引用同一块 storage。view 用不同的逻辑 shape 解释同一份底层数据，而不必复制它。

stride

某一维索引增加 1 时，在底层 storage 里要跨过多少个元素。它把“逻辑坐标”映射到“物理位置”。

contiguous

元素是否按当前逻辑维度顺序紧密排列。某些 kernel（GPU 内核）可以直接处理任意 stride；kernel 是提交到 GPU 上执行的一段并行计算。某些 transfer（传输） path 会要求或更偏好 contiguous buffer（缓冲区）；transfer 负责搬数据，buffer 是暂存 tensor 或传输数据的一块内存。

transpose 常常只改变 view 的 shape/stride，而不立即复制 storage；contiguous() 则可能真的分配新内存并重排数据。以后看到 permute（维度重排）和 copy（复制）时，要开始问：permute 只是重新排列 tensor 的维度顺序，还是触发了真正的数据移动？copy 则明确意味着生成或写入一份新的数据副本。

为什么这对后面重要：07.4 的块表和 08.4 的 transfer region（内存区域）都会把“逻辑 tensor”继续落到更具体的地址、偏移、stride 与生命周期。region 是传输层注册或操作的一段内存范围。现在先建立一个底线：logical shape ≠ physical layout。

06 · 这些概念后面会用到哪里

这就是它和模型并行源码的第一条连接线。

这里先认识 Megatron（大模型训练框架）。它是后面学习多维并行和分布式训练的重要源码实现。现在你还不用学正式的张量并行，只先偷看一个 Linear（线性层）：Linear 会对输入做矩阵乘法，并可再加一个偏置项。

next conceptlinear algebra
X: [B, S, H]
W: [H, 4H]

Y = X @ W

# Megatron 的问题：
# W 太大时，能不能把它切给 GPU 0 和 GPU 1？
# 如果切了，X / Y 要不要跟着切？
# 中间需要 all-reduce 还是 all-gather？

所以我们今天学 [B,S,H] 不是为了记符号。它是在搭后面所有“怎么切、怎么搬、怎么通信”的地基。

CHECKPOINT不要跳过

能答出来，再进下一课。

1. [4, 1024, 4096] 里的4096是什么意思？
它是隐藏维度：当前每个token用一个长度为4096的向量表示。
2. 为什么 FP16 张量通常比同形状的 FP32 张量少一半显存？
因为元素数量完全相同，但每个FP32元素通常占4 bytes，FP16占2 bytes。
3. 为什么“这块张量在cuda:0还是cuda:1”以后会很重要？
因为跨GPU使用数据往往意味着通信或拷贝。AI基础设施的大量性能问题，就是在研究哪些数据必须移动、移动多少、什么时候移动。
4. 两个张量的形状一样，是否意味着它们的底层内存布局也一定一样？
不一定。形状只说明各维长度；transpose/视图等操作可以让张量拥有不同步长，甚至共享同一存储。是否连续存储、是否需要实际copy，是另一层问题。
