LESSON 01.4 · FOUNDATION约 40 min

自动求导与优化器：梯度从哪里来，显存又花在哪里？

上一课的训练循环里，loss.backward() 和 optimizer.step() 还是两个黑盒。这一课把它们打开：梯度到底是什么，PyTorch 怎么把它算出来，Adam 优化器比 SGD 好在哪、又多花了多少显存。最后你会算出一个 7B 模型训练时光训练状态就要 112 GB，并看到多张卡怎样分摊这笔账。

学完这节课，你能：
  • 用一个具体数字说清楚梯度的含义，不需要微积分。
  • 手算一个最小计算图的反向传播，知道为什么训练要存激活值。
  • 知道推理时为什么要关掉梯度计算。
  • 正确地做梯度累积（loss 要除以累积次数）。
  • 说清楚 SGD 和 Adam 的区别、各自用在哪、Adam 多花多少显存。
  • 算出一个模型训练时的显存账，以及分片后每张卡要放多少。
01 · 梯度是什么

梯度就是：参数动一点点，loss 跟着变多少。

还用上一课那种最小模型，只看一个样本 x = 3，y = 7，参数只有 w。那么 loss 就是 w 的函数：

loss = (3w − 7)²

现在 w = 2，loss = (6 − 7)² = 1。把 w 加一点点，变成 2.001，再算一次：

算一下w 从 2 变到 2.001
w = 2      → loss = (6     − 7)² = 1
w = 2.001  → loss = (6.003 − 7)² = 0.994009

loss 变化 / w 变化 = (0.994009 − 1) / 0.001 ≈ −6

这个 −6 就是 w 的梯度：w 每增加一点，loss 大约减少它的 6 倍。所以：

符号：往哪边改

梯度是负的，说明 w 变大 loss 会变小，所以应该增大 w。梯度是正的就减小。

大小：有多敏感

梯度绝对值越大，这个参数对 loss 的影响越大。离最优点越远，梯度通常越大。

更新规则

SGD 就是 w = w − lr × 梯度：梯度负就往大走，梯度正就往小走。

梯度在数学上叫导数（多个参数时叫偏导数），但你不需要会求导：PyTorch 会自动算，而且算出来的值就是上面这种“动一点点、看变化”的比值的精确版本。

02 · 计算图与反向传播

PyTorch 前向时记下每一步，反向时倒着乘回去。

前向计算 loss = (w × x − y)² 其实是三步：乘、减、平方。PyTorch 在前向时把这三步按顺序记下来，这个记录叫计算图。loss.backward() 时，它从 loss 出发倒着走，每经过一步就乘上这一步的“本地变化率”：

每一步只需要知道自己的本地规则，整条链乘起来就是最终的梯度，这叫链式法则。模型再大，几十层、几十亿参数，原理也一样，只是图更大。用代码验证：

pythonautograd_minimal.py
import torch

w = torch.tensor(2.0, requires_grad=True)   # 告诉 PyTorch：这个要算梯度
x = torch.tensor(3.0)
y = torch.tensor(7.0)

loss = (w * x - y) ** 2
print(w.grad)       # None：还没 backward
loss.backward()
print(w.grad)       # tensor(-6.)  和手算一样

requires_grad=True 表示“这个张量要算梯度”。nn.Linear 这类层里的参数默认就是 True，输入数据默认是 False。

推理时要关掉：torch.no_grad()

记录计算图、保存中间结果都要占显存。推理只做前向、不需要梯度，所以要关掉：

python推理
with torch.no_grad():        # 或 torch.inference_mode()，更快一点
    output = model(x)        # 不记计算图，不存中间结果

训练时千万不能这样写，否则 backward 时没有计算图，会直接报错。推理时忘了写，结果不会错，但会白白多占显存。

03 · 梯度存在哪

每个参数旁边都有一个一样大的 .grad。

backward 算出的梯度会存在参数的 .grad 里，shape 和参数完全一样：

python.grad 的大小
linear = nn.Linear(4096, 4096)
linear(torch.randn(8, 4096)).sum().backward()

print(linear.weight.shape)        # [4096, 4096]
print(linear.weight.grad.shape)   # [4096, 4096]  一样大

所以训练时显存里至少要放两份一样大的东西：参数和梯度。再加上优化器自己的状态，就是后面要算的显存账。一个参数文件 14 GB 的模型，训练时需要的显存远不止 14 GB。

04 · 梯度累积

显存放不下大 batch：拆成几小份，梯度加起来再更新。

上一课说过，backward() 是把梯度加到 .grad 上的。利用这一点：想用 batch = 32 训练，但显存只放得下 8，就拆成 4 份，每份做一次 backward，最后只更新一次：

python梯度累积
steps = 4
optimizer.zero_grad()
for micro_x, micro_y in zip(x.chunk(steps), y.chunk(steps)):   # 每份 8 个样本
    loss = loss_fn(model(micro_x), micro_y) / steps   # ← 要除以份数
    loss.backward()                                   # 梯度累加到 .grad
optimizer.step()                                      # 4 份都算完才更新一次

拆出来的每一小份叫 microbatch（微批次）。为什么要除以份数？用上一课的数字验证：4 个样本拆成 2 份，每份 2 个：

验证w = b = 0
第 1 份（x = 0, 1）的梯度：  w: −3     b: −4
第 2 份（x = 2, 3）的梯度：  w: −31    b: −12

直接累加：                  w: −34    b: −16    ✗ 是正确值的 2 倍
每份 loss 先除以 2 再累加：   w: −17    b: −8     ✓ 和一次用 4 个样本算的一样

因为每份的 loss 已经是那一份的平均，直接加起来就多算了几倍，相当于偷偷把学习率放大了。如果每份大小不一样（比如最后一份不满），要按样本数（大模型里常按 token 数）加权，不能简单除以份数。

什么时候用：想要的 batch 大小放不进显存时。代价是速度：几份是一份一份串行算的，不会更快，只是省显存。后面 05 模块的流水线并行也会用到 microbatch。

05 · 优化器

梯度由 autograd 算，怎么用梯度改参数由优化器决定。

不同优化器的区别在于“拿到梯度之后怎么走这一步”，以及为此要额外记住什么：

优化器怎么走每个参数额外存
SGDw −= lr × 梯度无
SGD + 动量（momentum）记住过去梯度的平均方向 m，按 m 走。梯度方向来回抖动时更稳。1 份（m）
Adam / AdamW除了 m，还记住梯度平方的平均 v。按 lr × m / √v 走：每个参数的步长会按它自己梯度的大小自动调整。2 份（m 和 v）

“按自己梯度的大小自动调整”是 Adam 最关键的地方。看一个例子：两个参数，一个梯度是 100，一个是 0.01，学习率都是 0.001：

第一步走多远lr = 0.001
            梯度 = 100      梯度 = 0.01
SGD         0.1             0.00001        ← 差了 1 万倍
Adam        0.001           0.001          ← m / √v 把梯度大小“除掉”了

用 SGD 时只有一个学习率：调到适合大梯度的参数，小梯度的参数几乎不动；调到适合小梯度的参数，大梯度的参数会冲过头。大模型里不同层、不同参数的梯度大小差别很大，所以 Adam 好调得多。

场景用什么为什么
大语言模型、TransformerAdamW几乎是标准选择。AdamW 是 Adam 加上正确实现的权重衰减（防止参数变得过大）。实践中用纯 SGD 很难把 Transformer 训好。
传统图像模型（比如 ResNet）SGD + 动量 也很常见这类模型用 SGD 能训得很好，而且省显存。
显存特别紧张考虑更省状态的优化器Adam 的 m 和 v 是真金白银的显存开销，下一节会算到底有多大。

07 · 分片

每张卡都存一整份完全一样的训练状态，太浪费了。

上一课的数据并行里，每张卡都有一份完整的模型。现在知道了训练状态有多大：8 张卡就存了 8 份一模一样的 112 GB。既然各卡更新时用的梯度是一样的（同步过了），那每张卡其实只需要负责一部分参数的更新，只存这部分的优化器状态就够了。试试看：

分片方式什么时候用代价
不分片模型小，单卡放得下最简单，通信最少
分片优化器状态最常用的第一步，省得最多（占大头的 12 字节被分掉了）几乎没有额外通信：原来要做的梯度同步换一种方式做，总通信量不变
再分片梯度还想再省一些通信量仍然基本不变
再分片参数模型大到连参数都放不下每次前向、反向都要临时把参数从其他卡收集回来，通信量约为原来的 1.5 倍

这几种做法统称 ZeRO（Zero Redundancy Optimizer，零冗余优化器），三档依次叫 ZeRO-1、ZeRO-2、ZeRO-3；PyTorch 自带的 FSDP 相当于 ZeRO-3。Megatron 的分布式优化器也是这个思路，05.5 会详细讲它的通信怎么安排。

核心思路：多卡训练需要协作，但不代表每张卡都要存一整份训练状态。存什么、分给谁、什么时候通信，是后面整个 Megatron 模块反复要回答的问题。

CHECKPOINTFOUNDATIONS

过这一关，再进入 Transformer。

1. loss = (3w − 7)²，w = 2 时梯度是 −6。这告诉你什么？
w 增加一点，loss 会减少大约 6 倍那么多。所以应该增大 w，SGD 的 w − lr × (−6) 正好让 w 变大。
2. 为什么训练时必须保存前向的中间结果？
反向时每一步的本地规则要用到前向的值，比如乘法 ŷ = w × x 反向时要乘 x。不存就没法算梯度（除非反向时重新算一遍前向，也就是激活值重算）。
3. 推理时为什么要用 torch.no_grad()？
推理不需要梯度。关掉后不记录计算图、不保存中间结果，省显存也更快。
4. 梯度累积分 4 份，每份的 loss 为什么要除以 4？
每份的 loss 已经是那一份的平均，4 份的梯度直接相加会是一次大 batch 的 4 倍。除以 4 后才和一次大 batch 的梯度一样。
5. 用混合精度 + Adam 训练一个 13B 模型，参数、梯度和优化器状态大约要多少显存？
13B × 16 字节 = 208 GB，还不算激活值。
6. 上题的模型用 8 张卡做数据并行，只分片优化器状态，每张卡要放多少？
参数 2 + 梯度 2 + 优化器状态 12 / 8 = 5.5 字节/参数，13B × 5.5 = 71.5 GB。
