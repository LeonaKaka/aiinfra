矩阵乘法与 Linear：模型到底在算什么？

上一课学会了读 shape。这一课把 X @ W 彻底看懂：每个输出数是怎么算出来的，shape 怎么变，Linear 层里到底存了什么。大模型的计算量绝大部分都花在这种矩阵乘法上；后面 Megatron 的张量并行，问的也正是“这个矩阵乘法怎么拆到多张 GPU 上”。

学完这节课，你能：
  • 给两个 shape，马上判断能不能相乘、结果是什么 shape。
  • 说清楚每个输出数是“X 的一行”和“W 的一列”做点积得到的。
  • 知道 nn.Linear 存了什么，为什么它的 weight shape 是反着的，什么时候不要 bias。
  • 估算一次矩阵乘法要做多少次运算，在 GPU 上大概要多久。
  • 知道权重按列切和按行切之后，结果分别要怎么合起来。
01 · 点积

一切从“对应位置相乘再相加”开始。

假设一个 token 现在用 3 个数表示，再准备 3 个权重：

x = [2, 1, -1]·w = [3, 4, 5]= 2×3 + 1×4 + (−1)×5 = 5

两个一样长的向量，对应位置相乘再加起来，得到一个数，这就是点积（dot product）。

w 里的每个数决定了输入对应位置对结果的影响有多大：权重大的位置，输入的影响就大；权重是负数，影响就是反向的。“权重”这个名字就是这么来的。训练模型，本质上就是在调这些权重。

一个输出数 = 一次点积。想得到 4 个输出数，就准备 4 组不同的权重，各做一次点积。

02 · 矩阵乘法

把很多组权重并排放，就是矩阵乘法。

把 4 组权重竖着并排放，就是一个 3 行 4 列的矩阵 W，第一列就是上面的 [3, 4, 5]。输入也可以不止一行，比如 2 个 token 就是 2 行 3 列的 X。

Y 里的每一格，都是 X 的某一行和 W 的某一列做一次点积。Y[i, j] 就是“X 的第 i 行”点乘“W 的第 j 列”。所以有一条必须记住的 shape 规则：

[M, K]@[K, N]→[M, N]

中间的 K 必须相等，因为 X 的一行和 W 的一列要一样长才能做点积。做完点积，K 这一维就被加掉了，剩下外面的 M 和 N。对不上就会直接报错：

pythonshape 对不上
A = torch.randn(10, 64)
B = torch.randn(32, 128)
A @ B
# RuntimeError: mat1 and mat2 shapes cannot be multiplied (10x64 and 32x128)
M · 有多少行输入

在模型里通常就是 token 的个数。

K · 每行多长

每次点积要乘多少对数，算完就消失了。

N · 要几个输出

W 有几列，就有几组权重，每行输入就得到几个输出数。

03 · 回到 [B, S, H]

三维的输入怎么乘二维的权重？先摊平，算完再还原。

模型里的输入不是二维的 [M, K]，而是上一课的 [B, S, H]。权重 W 是 [H, D]。PyTorch 的做法是：只用最后一维 H 去和 W 相乘，前面的维度全部保留。

你可以把它理解成：先把 B 和 S 摊平成一维，变成 [B×S, H] 的普通矩阵，乘完再还原。这不只是一种理解方式，底层实际也是这样算的，变成一次大的二维矩阵乘法：

python两种写法结果完全一样
X = torch.randn(2, 5, 8)
W = torch.randn(8, 32)

Y1 = X @ W                                      # [2, 5, 32]
Y2 = (X.reshape(10, 8) @ W).reshape(2, 5, 32)  # 先摊平，算完还原
print(torch.allclose(Y1, Y2))                   # True

所以后面讲矩阵乘法时，常把 B 和 S 合起来写成 N = B × S，也就是这一批里一共有多少个 token。

04 · Linear 层

Linear 层 = 矩阵乘法 + 加一个 bias。

PyTorch 的 nn.Linear(in_features, out_features) 做的就是：

Y = XW + b
X输入
W · weight权重矩阵，训练时会被更新
b · bias每个输出加一个数，也会被更新
python02_linear.py
import torch
from torch import nn

X = torch.randn(2, 5, 8)
linear = nn.Linear(8, 32)
Y = linear(X)

print(Y.shape)              # [2, 5, 32]
print(linear.weight.shape)  # [32, 8]  ← 注意：是 [输出, 输入]，反过来的
print(linear.bias.shape)    # [32]

# 自己手算一遍，和 linear(X) 完全一样
Y2 = X @ linear.weight.T + linear.bias
print(torch.allclose(Y, Y2))  # True

有两点要注意：

weight 的 shape 是 [输出, 输入]

数学上写 X @ W 时，W 是 [8, 32]。但 PyTorch 把 weight 存成 [32, 8]，计算时再转置（.T）。结果完全一样，只是存法不同。读源码看到 weight 的 shape 和你推的反过来，就是这个原因。本课程讲原理时一律用数学写法 [输入, 输出]。

bias：默认有，大模型里通常不要

bias 的 shape 是 [32]：每个输出特征加一个数，所有 token 共用同一组。

场景bias为什么
自己写小模型、做实验用默认值（有）nn.Linear 默认 bias=True，不用改。
大语言模型（PaLM、LLaMA 系列等）bias=Falsebias 参数很少：一个 4096 → 4096 的 Linear，weight 有约 1678 万个数，bias 只有 4096 个，占 0.02%。去掉基本不影响效果；PaLM 论文还报告去掉 bias 后大模型训练更稳定。

所以读大模型源码时，到处看到 bias=False 不用奇怪。

05 · 计算量

一次矩阵乘法要算多少次？在 GPU 上要多久？

[M, K] @ [K, N] 一共要算 M × N 个输出数，每个输出数是一次长度为 K 的点积，也就是 K 次乘法加 K 次加法。所以总运算次数约为：

运算次数 ≈ 2 × M × K × N

浮点运算次数的单位叫 FLOP。用一个大模型里真实大小的例子算一下：

计算[8192, 4096] @ [4096, 16384]
2 × 8192 × 4096 × 16384 ≈ 1.1 × 10¹² 次 = 1.1 TFLOP

H100 用 BF16 算矩阵乘法，理论峰值约 989 TFLOP/秒
→ 理想情况下约 1.1 毫秒；实际达不到峰值，会再慢一些

这只是一个矩阵乘法。LLaMA 这类模型每层有 7 个 Linear（Q、K、V、输出投影，加上 MLP 里的 3 个），模型有几十层；训练时还要做反向计算，反向的计算量大约是前向的 2 倍。大模型训练要几千张 GPU 跑几个月，时间主要就花在这里。

GPU 里有专门算矩阵乘法的硬件单元，叫 Tensor Core，而且它对 16 位格式特别快：H100 用 Tensor Core 算 BF16 约 989 TFLOP/秒，不走 Tensor Core 的普通 FP32 只有约 67 TFLOP/秒。这就是 01.1 里说“BF16 算得更快”的原因。

大模型代码里常说的 GEMM（General Matrix Multiply，通用矩阵乘法）指的就是这种矩阵乘法。以后用性能分析工具（profiler）看训练的时间线，你会发现大片时间都是 GEMM。

06 · 第一次接触张量并行

W 太大一张卡放不下，就把它切开。有两种切法。

假设有两张 GPU。W 可以按列切，也可以按行切，切完后合起来的方式完全不同：

用上面的数字验证一下按行切。Y[0, 0] = 5，把点积拆成两段：

按行切Y[0, 0]
GPU 0：x 的前 2 个数 · W 第 0 列的前 2 个数 = 2×3 + 1×4 = 10
GPU 1：x 的第 3 个数 · W 第 0 列的第 3 个数 = (−1)×5    = −5
相加：10 + (−5) = 5   ✓

切完以后，多张卡之间就要传数据了：按列切要把各卡的结果拼起来（这种通信叫 all-gather），按行切要把各卡的结果加起来（叫 all-reduce）。这两种通信在 04 模块讲。

实际不一定马上合起来。Megatron 的做法是：MLP 的第一个 Linear 按列切，结果先不拼；第二个 Linear 按行切，正好直接拿各卡手里的那一半继续算，最后只做一次求和。这样两个 Linear 之间就省掉了一次通信。05.2 会完整推一遍。

CHECKPOINT不要跳过

能用 shape 推出来，才算真的学会。

1. [10, 64] @ [64, 128] 的结果是什么 shape？
[10, 128]。中间的 64 对上了，在点积里被加掉；外面的 10 和 128 留下来。
2. 输入 [2, 5, 8] 经过 nn.Linear(8, 32)，输出为什么是 [2, 5, 32]？
每个 token 的 8 个数都和同一个权重矩阵相乘，变成 32 个数。B=2 和 S=5 不参与乘法，原样保留。
3. nn.Linear(8, 32, bias=False) 有多少个参数？weight 的 shape 是什么？
8 × 32 = 256 个参数。weight 的 shape 是 [32, 8]，PyTorch 按 [输出, 输入] 存。
4. [1024, 4096] @ [4096, 4096] 大约要多少次浮点运算？
2 × 1024 × 4096 × 4096 ≈ 344 亿次，约 34 GFLOP。
5. W 按列切给两张卡和按行切给两张卡，最后分别要怎么得到完整的 Y？
按列切：每张卡算出 Y 的一部分列，拼起来（all-gather）。按行切：每张卡算出和 Y 一样形状的部分和，加起来（all-reduce）。
