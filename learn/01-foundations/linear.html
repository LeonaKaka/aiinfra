LESSON 01.2 · FOUNDATION约 30 min

Matrix Multiply 与 Linear：模型到底在算什么？

上一课我们学会了看 tensor 的 shape。这一课只做一件事：把 X @ W 真正看懂。因为 Transformer 里最重的一大类计算就是矩阵乘法，而 Megatron 的 Tensor Parallel，本质上就是在问：这个巨大的矩阵乘法，怎样拆到多张 GPU 上？

这节课结束时，你应该能做到：
  • 看到 [M,K] @ [K,N] → [M,N]，立刻判断能不能相乘、输出是什么 shape。
  • 理解一个 Linear 层就是 Y = XW + b，不是某种神秘“神经网络操作”。
  • 知道为什么大模型训练里会反复出现 GEMM。
  • 第一次看懂 Megatron 为什么可以把一个 Linear 的权重按列或按行切到不同 GPU。
01 · START WITH ONE DOT PRODUCT

矩阵乘法先从“两条向量做一次点积”开始。

假设一个 token 现在由 3 个数字表示：

x = [2, 1, -1]·w = [3, 4, 5]= 2×3 + 1×4 + (-1)×5 = 5

这就是 dot product。它把两个同长度向量压成一个数字。你可以把 w 想成一个“小问题”：它按照自己的权重，把输入的 3 个数字混合成 1 个新数字。

关键直觉：一个输出数字，对应一次 dot product；要得到很多输出数字，就准备很多组不同的权重。

02 · FROM ONE OUTPUT TO MANY

把很多组权重并排放起来，就得到矩阵乘法。

如果输入 x 长度是 3，而我们想一次得到 4 个新数字，就可以准备 4 组权重。把它们排成一个 [3,4] 的矩阵 W：

inputx[1 × 3]
21-1
×
weightW[3 × 4]
=
outputy[1 × 4]

这里真正必须记住的是 shape 规则：

[M, K]@[K, N]→[M, N]

中间的 K 必须对得上。它是“每次 dot product 要乘多少对数字”。相乘后，K 这个维度被求和消掉，外面的 M 和 N 留下来。

M

有多少行输入。以后它常常可以理解成很多 token 被摊平后的数量。

K

每个输入向量有多长，也是每次点积真正累加的维度。

N

我们想得到多少个输出特征，也就是 W 有多少列。

03 · BACK TO [B,S,H]

Transformer 里的 [B,S,H] 怎么参加矩阵乘法？

真实模型里，输入通常不是二维的 [M,K]，而是上一课看到的 [B,S,H]。如果权重是 [H,D]，PyTorch 会把最后一个维度 H 当作矩阵乘法的输入维度：

INPUTX [B, S, H]
×
WEIGHTW [H, D]
→
OUTPUTY [B, S, D]

直观地说：batch 和 sequence 里的每一个 token，都拿自己那条长度为 H 的向量，去乘同一个 W。所以 B 和 S 都保留下来，最后的 hidden 维从 H 变成 D。

shape traceTransformer-like example
X = [2, 5, 8]      # 2 条样本，5 个 token，hidden=8
W = [8, 32]        # 把 hidden 从 8 投影到 32

Y = X @ W
Y = [2, 5, 32]
04 · LINEAR LAYER

Linear 层，就是矩阵乘法再加一个 bias。

PyTorch 的 nn.Linear(in_features, out_features) 从概念上就是：

Y = XW + b
X输入 activation
W模型要学习的权重
b可选的 bias

注意 PyTorch 内部存储 nn.Linear 权重时，参数张量通常是 [out_features, in_features]；数学表达里我们为了直观常写成 X @ W、把 W 看作 [in_features, out_features]。代码实现会使用等价的转置形式。别把“数学里怎么写 W”和“框架里参数内存怎么摆”混为一谈。

python02_linear.py
import torch
from torch import nn

X = torch.randn(2, 5, 8)
linear = nn.Linear(8, 32)
Y = linear(X)

print(X.shape)             # [2, 5, 8]
print(linear.weight.shape) # [32, 8]
print(Y.shape)             # [2, 5, 32]

这段代码非常值得你自己跑一次。不是为了学 API，而是要把“输入最后一维 8 → 输出最后一维 32”这件事和 Linear 牢牢绑在一起。

05 · WHY GPU CARES

为什么 AI Infra 里总在说 GEMM？

GEMM 可以先粗略理解成“大块矩阵乘法”。现代 Transformer 中，Q/K/V 投影、Attention 的部分计算、MLP 的两个大 Linear，都大量依赖矩阵乘法。GPU 和 Tensor Core 正是特别擅长把这种规则、密集的运算做得非常快。

EXAMPLE[8192, 4096] @ [4096, 16384]
ROUGH MULTIPLY-ACCUMULATE SCALE8192 × 4096 × 16384

数字一大，计算量会非常惊人。这里先不追求 FLOPs 公式的精确定义，只建立一个系统直觉：矩阵越大，计算越重；矩阵分给多张 GPU 后，又会引入通信。

以后看 profiler：你会经常看到 GEMM kernel 占据大片 GPU 时间线。Megatron 的很多优化，就是想让这些大 GEMM 高效运行，同时尽量把必要通信藏到计算后面。

06 · FIRST LOOK AT TENSOR PARALLEL

如果 W 太大，一张 GPU 放不下，最自然的问题就是：把它切开。

先不学正式的 Tensor Parallel 算法。只做一个思想实验：W = [H, 4H]，我们有两张 GPU。

ORIGINAL WEIGHTW [H, 4H]
split columns →
GPU 0W₀ [H, 2H]
GPU 1W₁ [H, 2H]

同一个 X 分别乘 W₀ 和 W₁：

conceptcolumn split
Y₀ = X @ W₀     # GPU 0 得到一半输出特征
Y₁ = X @ W₁     # GPU 1 得到另一半输出特征

Y = concat(Y₀, Y₁, dim=hidden)  # 如果需要恢复完整输出

别先形成错误印象：实际 Megatron 并不总会立刻把两半输出拼回完整 Y。很多时候会让输出继续保持分片，直接交给下一层，以减少通信。这里的 concat 只是说明“完整结果在数学上怎样恢复”。

你现在已经第一次碰到 Megatron 的核心思想了：不是“把模型复制两份”，而是让不同 GPU 各算同一个大矩阵乘法的一部分。下一阶段真正学 Tensor Parallel 时，我们再回答：X 要不要复制？输出什么时候需要聚合？为什么 Row Parallel 又会出现 all-reduce？

CHECKPOINT不要跳过

能用 shape 推出来，才算真的学会。

1. [10, 64] @ [64, 128] 的输出 shape 是什么？为什么？
[10, 128]。中间的 64 对齐并在点积中被求和，外面的 10 和 128 留下来。
2. 输入 X=[2,5,8]，Linear 是 8 → 32，输出为什么是 [2,5,32]？
每个 token 的最后一维长度 8 都经过同一个 Linear 映射成长度 32；batch=2 和 sequence=5 没有被改变。
3. 把 W 按输出列切成两半后，两张 GPU 分别算出了什么？
它们分别得到输出 hidden/features 的一半。需要完整 Y 时可以按输出特征维拼接；实际并行实现也可能继续保持分片，避免不必要的通信。
