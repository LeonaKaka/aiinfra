LESSON 01.3 · FOUNDATION约 35 min

PyTorch 的最小训练循环：参数是怎么真的变掉的？

前两课我们只看“数据怎么表示”和“Linear 怎么计算”。但模型为什么会越来越会做题？答案并不神秘：不断做 forward，算出错多少，再把这个错误反向传回参数，最后让 optimizer 改一点参数。训练就是把这套循环重复很多次。

这节课结束时，你应该能做到：
  • 从头到尾讲清一次 training step 的数据流。
  • 知道 model(x)、loss.backward()、optimizer.step() 分别在做什么。
  • 理解为什么每轮通常要先 zero_grad()。
  • 看懂“单卡训练循环”以后，分布式训练到底多出来了什么问题。
01 · THE WHOLE LOOP

先把训练看成一个不断重复的闭环。

先不碰公式。一次最小训练 step 可以压缩成五件事：

1 · INPUTx, target
→
2 · FORWARDprediction
→
3 · LOSSerror
4 · BACKWARDgradients
→
5 · STEPupdate params
→
REPEATnext batch

真正训练一个大模型时，外面会套上数据加载、混合精度、梯度累积、分布式通信、checkpoint 等复杂系统；但最里面这个闭环没有变。

先记住一句：forward 产生预测，loss 衡量错误，backward 产生梯度，optimizer 根据梯度修改参数。

02 · A TINY PROBLEM

我们让一个只有两个参数的模型学会 y = 2x + 1。

模型先完全不知道答案。我们只给它一个最简单的 Linear：

ŷ = wx + b
w一开始是随机值
b一开始也是随机值
goal最后接近 w=2, b=1

训练的工作不是直接把 w=2, b=1 填进去，而是只告诉模型“你刚才预测得有多错”，让它根据梯度一步步靠近正确参数。

03 · THE MINIMAL PYTORCH VERSION

完整代码其实很短，先看全貌再拆。

python03_training_loop.py
import torch
from torch import nn

# y = 2x + 1 的四个训练样本
x = torch.tensor([[0.], [1.], [2.], [3.]])
y = torch.tensor([[1.], [3.], [5.], [7.]])

model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.05)

for step in range(200):
    prediction = model(x)            # 1. forward
    loss = loss_fn(prediction, y)    # 2. measure error

    optimizer.zero_grad()            # 3. clear old gradients
    loss.backward()                  # 4. compute gradients
    optimizer.step()                 # 5. update w and b

print(model.weight.item(), model.bias.item())
# 应该逐渐接近 2 和 1

这里没有魔法。训练 200 次只是重复同一套数据流。现实里当然会换成成千上万个 batch，但核心顺序仍然相同。

04 · TRACE ONE STEP

把一轮训练逐行追一遍。

① Forward

prediction = model(x)。输入经过 Linear，得到当前参数下的预测。为了之后反向传播，PyTorch 还会记录必要的计算关系。

② Loss

MSELoss 把预测和真实 y 比较，压成一个标量 loss。loss 越大，说明当前预测越差。

③ zero_grad

PyTorch 默认会把新梯度累加到已有 .grad 上，所以普通训练 step 通常先清掉上一次的梯度。

④ Backward

loss.backward() 从 loss 反向沿计算图计算每个可训练参数的梯度，结果放到参数的 .grad 中。

⑤ Optimizer step

optimizer.step() 读取这些梯度，再按 SGD 的更新规则修改参数。参数真的在这一行发生改变。

⑥ Repeat

参数变了一点，下一轮 forward 的 prediction 就会不同。只要更新方向总体有效，loss 会逐渐下降。

05 · WATCH PARAMETERS MOVE

别只盯 loss，直接看参数真的被改了。

你可以在训练前后打印参数：

debug habitinspect parameters
print("before", model.weight.item(), model.bias.item())

# ... run training loop ...

print("after", model.weight.item(), model.bias.item())
BEFORE

随机参数

例如 w≈-0.4、b≈0.2。预测自然很差，loss 比较大。

AFTER

接近目标

经过许多小步更新后，w 会逼近 2、b 会逼近 1，预测也越来越准。

以后调大模型时，“参数有没有 grad”“grad 是不是异常”“optimizer 有没有真的 step”仍然是最基本的 debugging 思路，只是参数数量从 2 个变成几十亿个。

06 · INFRA VIEW

一旦模型和 batch 变大，这五步就都变成系统问题。

FORWARD需要算大量 GEMM，还要保存 backward 之后会用到的 activation。
BACKWARD通常计算量很大，还会生成与参数相关的 gradients。
OPTIMIZER除了参数和梯度，还可能维护额外 optimizer states，占据大量显存。
DISTRIBUTED多张 GPU 各自算出梯度以后，哪些梯度必须同步？什么时候同步？

这就是为什么我们先学训练循环再学 AI Infra。以后遇到 activation checkpointing、gradient accumulation、distributed optimizer、Data Parallel 时，你可以明确知道它们在改造循环的哪一部分，而不是只记名词。

07 · FIRST DISTRIBUTED QUESTION

两张 GPU 各训练一半 batch，会发生什么？

GLOBAL BATCH8 samples
split batch →
GPU 04 samples → grad₀
GPU 14 samples → grad₁

如果两张 GPU 都拥有同一份模型参数，却各自只看一半数据，那么 backward 后会得到不同梯度。为了让两份模型继续保持一致，更新参数前通常要把各卡梯度聚合成一致的结果。

先埋一个伏笔：这就是 Data Parallel 为什么会需要 gradient synchronization，也是以后学习 all-reduce 的第一个真实动机。

CHECKPOINT不要跳过

你应该能自己把训练循环讲顺。

1. loss.backward() 和 optimizer.step() 是同一件事吗？
不是。backward() 负责计算梯度并写到参数的 .grad；optimizer.step() 才读取这些梯度并修改参数。
2. 为什么普通训练循环里要调用 zero_grad()？
因为 PyTorch 默认会累加梯度。如果不清零，本轮梯度会叠到之前的 .grad 上。梯度累积是有意利用这个机制，但普通 step 通常需要清零。
3. Data Parallel 中，两张 GPU 各算出自己的梯度以后，为什么通常不能各自直接更新？
因为它们看到的数据不同，梯度也不同。如果各自直接更新，参数副本就会逐渐分叉。通常需要先同步/聚合梯度，再让各卡做一致的参数更新。
