PyTorch 的最小训练循环：参数是怎么真的变掉的？

前两课我们只看“数据怎么表示”和“Linear 怎么计算”。但模型为什么会越来越会做题？答案并不神秘：先做 forward（前向计算：用当前 parameter 从输入算出模型输出和中间状态），再得到 loss（损失：衡量模型预测与目标之间的误差），接着做 backward（反向传播：沿计算图反向计算各 parameter 的 gradient），最后由 optimizer（优化器：根据 gradient 更新模型 parameter）执行 optimizer.step()。训练就是把这套循环重复很多次。

这节课结束时，你应该能做到：
  • 从头到尾讲清一次训练步骤的数据流。
  • 知道 model(x)、loss.backward()、optimizer.step() 分别在做什么。
  • 理解为什么每轮通常要先 zero_grad()。
  • 看懂“单卡训练循环”以后，分布式训练到底多出来了什么问题。
01 · 先看完整训练循环

先把训练看成一个不断重复的闭环。

先不碰公式。一次最小训练步骤可以压缩成五件事：

1 · INPUTx, target
→
2 · forwardprediction
→
3 · 损失error
4 · backwardgradients
→
5 · STEPupdate params
→
REPEATnext batch

真正训练一个大模型时，外面会套上数据加载、混合精度、gradient accumulation（梯度累积：多个小批次的 gradient 先累加，再统一更新 parameter）、分布式通信、checkpoint（检查点：保存模型和训练状态，便于中断后继续训练）等复杂系统；但最里面这个闭环没有变。

先记住一句：forward 产生预测结果，loss 衡量错误，backward 产生 gradient（梯度：表示 loss 对 parameter 变化的敏感方向），optimizer.step() 根据 gradient 修改 parameter（参数：训练中会被 optimizer 更新的可学习数值）。

02 · 从一个最小问题开始

我们让一个只有两个 parameter 的模型学会 y = 2x + 1。

模型先完全不知道答案。我们只给它一个最简单的 Linear：

ŷ = wx + b
w一开始是随机值
b一开始也是随机值
goal最后接近w=2, b=1

训练的工作不是直接把 w=2, b=1 填进去，而是只告诉模型“你刚才预测得有多错”，让它根据 gradient 一步步靠近正确 parameter。

03 · 最小 PyTorch 实现

完整代码其实很短，先看全貌再拆。

python03_training_loop.py
import torch
from torch import nn

# y = 2x + 1 的四个训练样本
x = torch.tensor([[0.], [1.], [2.], [3.]])
y = torch.tensor([[1.], [3.], [5.], [7.]])

model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.05)

for step in range(200):
    prediction = model(x)            # 1. forward
    loss = loss_fn(prediction, y)    # 2. measure error

    optimizer.zero_grad()            # 3. clear old gradients
    loss.backward()                  # 4. compute gradients
    optimizer.step()                 # 5. update w and b

print(model.weight.item(), model.bias.item())
# 应该逐渐接近 2 和 1

这里没有魔法。训练200次只是重复同一套数据流。现实里当然会换成成千上万个批次，但核心顺序仍然相同。

04 · 跟踪一次训练步骤

把一轮训练逐行追一遍。

① forward

prediction = model(x)。输入经过 Linear，得到当前 parameter 下的预测。为了之后 backward，PyTorch 还会记录必要的计算关系。

② loss

MSELoss（均方误差损失：把预测值与目标值之差的平方汇总成 loss）把预测和真实 y 比较，压成一个标量 loss。loss 越大，说明当前预测越差。

③ zero_grad()（清零梯度：清掉 parameter 上一次累积的 .grad）

PyTorch 默认会把新 gradient 累加到已有 .grad 上，所以普通训练步骤通常先清掉上一次的 gradient。

④ backward

loss.backward()（执行反向传播：从 loss 沿计算图计算各 parameter 的 gradient）会把结果累积到对应 parameter 的 .grad 中。

⑤ optimizer.step()

optimizer.step()（执行参数更新：读取 gradient 并修改 parameter）在这里按 SGD（随机梯度下降：按 gradient 方向更新 parameter 的经典优化方法）规则更新参数。parameter 真的在这一行发生改变。

⑥ repeat

parameter 变了一点，下一轮 forward 的预测结果就会不同。只要更新方向总体有效，loss 会逐渐下降。

05 · 看参数怎样更新

别只盯损失，直接看参数真的被改了。

你可以在训练前后打印参数：

debug habitinspect parameters
print("before", model.weight.item(), model.bias.item())

# ... run training loop ...

print("after", model.weight.item(), model.bias.item())
BEFORE

随机参数。 例如w≈-0.4、b≈0.2。预测自然很差，损失比较大。

AFTER

接近目标。 经过许多小步更新后，w会逼近2、b会逼近1，预测也越来越准。

以后调大模型时，“parameter 有没有 .grad”“.grad 是否异常”“optimizer 有没有真的 step()”仍然是最基本的调试思路，只是 parameter 数量从 2 个变成几十亿个。

06 · 从系统角度看训练循环

一旦模型和批次变大，这五步就都变成系统问题。

forward需要算大量通用矩阵乘法（GEMM），还要保存反向传播时会用到的激活值。
backward通常计算量很大，还会生成与参数相关的梯度。
optimizer除了参数和梯度，还可能维护额外优化器状态，占据大量显存。
DISTRIBUTED多张图形处理器（GPU）各自算出梯度以后，哪些梯度必须同步？什么时候同步？

这就是为什么我们先学训练循环再学 AI Infra。以后遇到 activation checkpointing、gradient accumulation、分布式 optimizer、Data Parallel 等技术时，你可以明确知道它们在改造循环的哪一部分，而不是只记名词。

07 · 第一个分布式问题

两张GPU各训练一半批次，会发生什么？

GLOBAL BATCH8 samples
split batch →
GPU 04 samples → grad₀
GPU 14 samples → grad₁

如果两张GPU都拥有同一份模型参数，却各自只看一半数据，那么反向传播后会得到不同梯度。为了让两份模型继续保持一致，更新参数前通常要把各卡梯度聚合成一致的结果。

先埋一个伏笔：这就是 Data Parallel（数据并行：不同 replica 处理不同数据，再同步训练状态）为什么需要梯度同步。具体用什么 collective，后面到 Distributed 再学。

CHECKPOINT不要跳过

你应该能自己把训练循环讲顺。

1. loss.backward() 和 optimizer.step() 是同一件事吗？
不是。backward() 负责计算梯度并写到参数的 .grad；optimizer.step() 才读取这些梯度并修改参数。
2. 为什么普通训练循环里要调用 zero_grad()？
因为PyTorch默认会累加梯度。如果不清零，本轮梯度会叠到之前的 .grad 上。梯度累积是有意利用这个机制，但普通 training step 通常需要清零。
3. 数据并行中，两张GPU各算出自己的梯度以后，为什么通常不能各自直接更新？
因为它们看到的数据不同，梯度也不同。如果各自直接更新，参数副本就会逐渐分叉。通常需要先同步/聚合梯度，再让各卡做一致的参数更新。
