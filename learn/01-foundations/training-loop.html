LESSON 01.3 · FOUNDATION约 35 min

PyTorch 的最小训练循环：参数是怎么真的变掉的？

上一课的 Linear 里，权重一开始是随机数。模型是怎么“学会”的？答案是一个很短的循环：用当前参数算出预测，看错了多少，算出每个参数该往哪边改，改一点，然后重复。这一课用一个只有 2 个参数的模型，把这个循环一步一步跑给你看。

学完这节课，你能：
  • 说清楚训练循环里五行代码各自做什么，读写了哪些数据。
  • 手算出第一步的 loss 和梯度，看懂参数是怎么变的。
  • 知道学习率选大了、选小了分别会出现什么现象。
  • 知道为什么每一步要先 zero_grad()，以及什么时候故意不清。
  • 明白两张 GPU 各训一半数据时，为什么更新前必须先同步梯度。
01 · 一个最小的问题

让一个只有 2 个参数的模型学会 y = 2x + 1。

我们准备 4 个样本：x 是 0、1、2、3，对应的正确答案 y 是 1、3、5、7。模型就是一个最小的 Linear：

ŷ = w·x + b
w, b模型的参数，一开始不知道该是多少
ŷ模型的预测
目标训练完 w ≈ 2，b ≈ 1

注意，我们不会直接告诉模型 w 应该是 2。我们只告诉它每次预测错了多少，让它自己一点点调整。大模型训练也是这样，只是参数从 2 个变成了几十亿个。

02 · 完整代码

整个训练过程就是这十几行。

python03_training_loop.py
import torch
from torch import nn

x = torch.tensor([[0.], [1.], [2.], [3.]])
y = torch.tensor([[1.], [3.], [5.], [7.]])

model = nn.Linear(1, 1)
nn.init.zeros_(model.weight)   # 为了让结果可复现，先把 w、b 设成 0
nn.init.zeros_(model.bias)     # 实际训练里一般是随机初始化

loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.05)

for step in range(200):
    prediction = model(x)            # 1. 前向：用当前的 w、b 算预测
    loss = loss_fn(prediction, y)    # 2. 算 loss：预测错了多少
    optimizer.zero_grad()            # 3. 清掉上一步的梯度
    loss.backward()                  # 4. 反向：算出每个参数的梯度
    optimizer.step()                 # 5. 更新：按梯度改 w、b

print(model.weight.item(), model.bias.item())   # ≈ 2.0  1.0

这五步每一步都有名字，后面会反复出现：

前向（forward）

用当前参数从输入算出预测。

损失（loss）

一个数，表示预测错了多少。这里用 MSE（均方误差）：每个样本“预测减目标”的平方，再取平均。

反向（backward）

算出每个参数的梯度（gradient）：这个参数往哪边改、loss 会下降得多快。

最后一步由优化器（optimizer）完成：它读梯度，按规则改参数。这里用的是最简单的 SGD（随机梯度下降），规则是“参数 −= 学习率 × 梯度”。

这个例子预测的是一个数，所以用 MSE。大语言模型预测的是“下一个 token 是哪个”，用的是交叉熵（cross-entropy）损失。思路一样：预测越错，loss 越大。

03 · 手算第一步

把第一步的数字算出来，就没有任何神秘感了。

一开始 w = 0，b = 0，所以 4 个预测全是 0：

第 1 步前向 + loss
预测   ŷ = 0, 0, 0, 0
目标   y = 1, 3, 5, 7
误差 ŷ−y = −1, −3, −5, −7

loss = 平均((ŷ−y)²) = (1 + 9 + 25 + 49) / 4 = 21

接着 loss.backward() 算梯度。对这个模型，梯度的公式是（怎么来的下一课讲）：

第 1 步反向：算梯度
w 的梯度 = 平均(2 × 误差 × x) = 2 × (−1×0 − 3×1 − 5×2 − 7×3) / 4 = −17
b 的梯度 = 平均(2 × 误差)     = 2 × (−1 − 3 − 5 − 7) / 4       = −8

梯度是负数，意思是“把这个参数调大，loss 会变小”。最后 optimizer.step() 按 SGD 的规则更新，学习率是 0.05：

第 1 步更新
w = 0 − 0.05 × (−17) = 0.85
b = 0 − 0.05 × (−8)  = 0.4

用新参数再算一次 loss：21 → 7.06

一步就从 21 降到了 7.06。之后每一步都重复同样的计算，只是数字不同。

04 · 学习率

学习率决定每一步走多远：太小走不动，太大会飞出去。

下面这个小程序和上面的代码算法完全一样，在浏览器里实时算。左边是 4 个数据点和模型当前这条直线，右边是 loss 的变化（纵轴是对数刻度）。换几个学习率试试：

学习率现象
0.01：太小方向是对的，但每步走得太少，要 44 步 loss 才降到 0.01 以下。在大模型上，这意味着白白浪费大量算力。
0.05：合适8 步 loss 就降到 0.01 以下。
0.3：太大每一步都冲过头，而且越冲越远：第 10 步 loss 已经涨到约 9 万。这叫发散。真实训练里看到的就是 loss 突然暴涨，甚至变成 NaN。

学习率没有通用的默认值，要按模型和优化器来调。大模型一般用 Adam 类优化器（下一课讲），学习率在 10⁻⁴ 这个量级，比如 LLaMA 7B 用的是 3 × 10⁻⁴。而且一开始不直接用这个值，而是从很小慢慢升上去（叫 warmup），训练后期再逐渐降下来，目的都是避免一开始就发散。

05 · 为什么要 zero_grad()

PyTorch 会把新梯度加到旧梯度上，不清就会越加越多。

loss.backward() 不是把梯度写进 .grad，而是加到 .grad 上。用上面的例子看看忘了清会怎样：

第 2 步w = 0.85，b = 0.4
这一步真正的梯度：         w: −9.85    b: −4.65

清了再 backward：.grad =   w: −9.85    b: −4.65     ✓
忘了清：        .grad =   w: −17 + (−9.85) = −26.85
                          b: −8  + (−4.65) = −12.65 ✗ 混进了上一步的梯度

这样更新的步子会越来越大，而且方向也不对。所以普通训练每一步都要先清零。

那 PyTorch 为什么要设计成“累加”？因为有时候是故意的：显存放不下一个大 batch 时，可以把它拆成几小份，每份各做一次 backward，让梯度累加起来，最后只更新一次。这叫梯度累积（gradient accumulation），下一课细讲。

06 · 从系统角度看

模型变大以后，这五步每一步都变成了系统问题。

步骤模型变大以后的问题
前向大量矩阵乘法；还要把中间结果（叫激活值，activation）留在显存里给反向用，batch 和序列越长，留得越多。
反向计算量大约是前向的 2 倍；算出来的梯度和参数一样多，也要占显存。
更新优化器除了参数和梯度，可能还要存额外的状态（下一课讲 Adam 时会看到，可能比参数本身还大）。
多卡每张卡算出的梯度不一样，更新前要同步。

后面学到的很多技术，都是在改造这个循环的某一步：

技术改的是哪一步解决什么问题
激活值重算（activation checkpointing）前向 / 反向前向时不留全部激活值，反向用到时再算一遍。多花计算，省显存。
梯度累积反向 / 更新几次 backward 才更新一次，用小显存实现大 batch。
数据并行（DP）反向之后、更新之前多张卡各算一部分数据，同步梯度后再更新。
分布式优化器更新每张卡只存、只更新一部分优化器状态，省显存。
07 · 第一个分布式问题

两张 GPU 各训一半数据，为什么必须先同步梯度？

还是这 4 个样本，现在分给两张 GPU，每张卡上都有一份完全一样的模型。各自算完梯度后会发生什么：

两点要记住：

  • 不同步就会分叉。两张卡看到的数据不同，梯度不同，各自更新后两份模型就不一样了，而且会越差越远。
  • 求平均后的结果和单卡完全一样。因为 loss 本来就是取平均，两张卡各拿一半（数量相等）样本，梯度的平均就等于全部样本的梯度。所以数据并行在数学上和单卡训练等价，只是更快。

这个“所有卡一起求平均，每张卡都拿到结果”的通信叫 all-reduce，04 模块会讲它具体怎么实现、要传多少数据。

CHECKPOINT不要跳过

你应该能自己把训练循环讲顺。

1. loss.backward() 和 optimizer.step() 是一回事吗？
不是。backward() 只算梯度、写进 .grad；optimizer.step() 才读梯度、真正修改参数。
2. w = b = 0 时，如果只用一个样本 (x=1, y=3)，loss 和 b 的梯度是多少？
预测是 0，误差是 −3。loss = (−3)² = 9；b 的梯度 = 2 × (−3) = −6。
3. 训练时 loss 突然暴涨甚至变成 NaN，最先该怀疑什么？
学习率太大导致发散。每一步更新冲过头，而且越冲越远。
4. 忘了写 zero_grad() 会怎样？什么时候是故意不清？
新梯度会加到旧梯度上，更新用的是混在一起的错误梯度。做梯度累积时才故意连着几次 backward 再清。
5. 数据并行时，为什么每张卡不能用自己的梯度直接更新？
各卡数据不同、梯度不同，直接更新会让各卡的模型分叉。要先把梯度求平均（all-reduce），所有卡用同一个梯度更新，结果也和单卡训练一样。
