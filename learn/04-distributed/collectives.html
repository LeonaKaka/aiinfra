LESSON 04.2 · DISTRIBUTED约 60 min

Collectives：每张 GPU 开始有什么，结束又得到什么？

all-reduce、all-gather、reduce-scatter 这些名字很像，背定义特别容易混。我们只用一个方法学：固定 4 个 ranks，画出通信前每个 rank 手里的 tensor，再画通信后每个 rank 得到什么。只要这个状态变化看懂，Megatron 里大部分 collective 名字就不再神秘。

这节课结束时，你应该能做到：
  • 不用背英文定义，直接画出 broadcast、all-reduce、all-gather、reduce-scatter 的输入/输出。
  • 区分“聚合数值”“收集 shards”“分发结果”这几种不同语义。
  • 解释 Data Parallel 为什么常用 all-reduce / reduce-scatter 处理 gradients。
  • 解释 Tensor Parallel 为什么经常需要 gather / reduce 一类通信。
  • 理解 Mixture of Experts (MoE，混合专家模型) token dispatch 为什么天然会遇到 all-to-all。
  • 知道 collective 是 group-level contract：参与 ranks、调用顺序、tensor 元信息不匹配都可能造成错误或 hang。
01 · ONE RULE FOR ALL COLLECTIVES

不要先背 API 名字。固定 process group，然后看 before → contract → after。

WHO哪些 ranks 参加？global group 还是某个 Tensor Parallel (TP，张量并行) / Data Parallel (DP，数据并行) / Pipeline Parallel (PP，流水线并行) 子 group？
BEFORE每个 rank 手里有什么？完整 tensor、一个 shard，还是各自不同的数据？
AFTER每个 rank 要拿到什么？完整聚合结果、拼接后的完整 tensor，还是一个 reduced shard？

下面把四个最常用 collective 放进同一张画布。你会看到：名字看似相近，本质只是不同的 ownership/state transformation。

COLLECTIVES · BEFORE → CONTRACT → AFTERfixed process group · 4 ranks
选择 collective 的核心不是名字，而是目标数据状态。所有人都要完整 reduced result → all-reduce；只需要 reduced shards → reduce-scatter；不做 reduction、只是让所有人拿齐 shards → all-gather；一个 source 复制给整个 group → broadcast。
02 · BROADCAST

一个 rank 有数据，把同一份数据发给所有 ranks。

BEFORE · source rank = 0
R0[A]
R1[?]
R2[?]
R3[?]
broadcast ↓
R0[A]
R1[A]
R2[A]
R3[A]

注意 broadcast 没有“求和”这一步，它只是从一个 source 复制/传播。典型直觉是某个 rank 先拥有配置、随机种子或 tensor，其它参与 ranks 最后都拿到同一份。

03 · ALL-REDUCE

每个 rank 都有一份贡献：先 reduce，再让所有 rank 都拿到完整聚合结果。

SUM EXAMPLE
R0[1]
R1[2]
R2[3]
R3[4]
all-reduce(sum) ↓
R0[10]
R1[10]
R2[10]
R3[10]

Reduce 表示按某个 op 聚合，例如 SUM、MAX；all-reduce 的关键是聚合后的完整结果最后出现在所有参与 ranks 上。

Data Parallel 的经典场景：各 rank 看不同 mini-batch，backward 得到不同 gradients；对应 gradients 必须聚合，模型副本才能继续做数学上一致的更新。

04 · ALL-GATHER

每个 rank 只有一个 shard，最后所有 rank 都拿到完整拼接结果。

SHARDS → FULL TENSOR
R0[A]
R1[B]
R2[C]
R3[D]
all-gather ↓
R0
ABCD
R1
ABCD
R2
ABCD
R3
ABCD

这里没有 reduce；只是把各 rank 的 shard 收集并按约定排列成完整数据。以后 Tensor Parallel / Sequence Parallel 中，经常会遇到“某个维度当前被 shard，但下一步需要完整 tensor”的情况。

05 · REDUCE-SCATTER

先 reduce，但最后每人只留一个结果 shard。

用一个能看见“不同输出 shard”的例子。四个 ranks 分别持有：

ELEMENTWISE SUM → SCATTER
R0[1,2,3,4]
R1[10,20,30,40]
R2[100,200,300,400]
R3[1000,2000,3000,4000]
reduce-scatter(sum) ↓
R0[1111]
R1[2222]
R2[3333]
R3[4444]

完整逐元素 SUM 是 [1111,2222,3333,4444]，但 reduce-scatter 不要求每个 rank 保存整条结果：每个 rank 只拿自己的 reduced shard。这个语义正适合“最终本来就只需要每 rank 一部分”的场景。

06 · ALL-REDUCE VS REDUCE-SCATTER + ALL-GATHER

把 all-reduce 从数据状态角度拆开，会更容易理解现代分布式训练。

STARTlocal contributions
→
REDUCE-SCATTERreduced shards
→
ALL-GATHERfull reduced tensor

从数学数据状态看，一个 all-reduce 的最终效果可以理解为先得到 reduced shards，再让所有 ranks gather 完整 reduced tensor。这不是说 NVIDIA Collective Communications Library (NCCL，NVIDIA 集体通信库) 内部永远机械地调用两个独立 Application Programming Interface (API，应用程序编程接口)；它只是非常有用的语义分解，能帮助理解 Zero Redundancy Optimizer (ZeRO，零冗余优化器) / Fully Sharded Data Parallel (FSDP，全分片数据并行) / Megatron 的 sharded states。

07 · ALL-TO-ALL

每个 rank 都要把不同的一部分发给不同 peers。

R0A0 A1 A2 A3
R1B0 B1 B2 B3
R2C0 C1 C2 C3
R3D0 D1 D2 D3
all-to-all
↔ ↔ ↔
R0 GETSA0 B0 C0 D0
R1 GETSA1 B1 C1 D1
R2 GETSA2 B2 C2 D2
R3 GETSA3 B3 C3 D3

它更像一次 destination-dependent reshuffle：每个 sender 给不同 destination 不同数据。MoE 的 Expert Parallel 是自然例子——router 决定 token 去哪个 expert，于是 token 要跨 ranks dispatch，再把 expert outputs 发回来。

08 · SEND / RECV IS NOT A COLLECTIVE

Point-to-point：明确的 sender 和 receiver。

send / recv 不是“整个 group 一起变换 tensor”，而是某些 ranks 直接点对点传数据。Pipeline Parallel 相邻 stages 之间传 activations / gradients 时，就很容易出现 Peer-to-Peer (P2P，点对点通信) 语义。

RANK 0 · PIPE STAGE 0activation
send → recv
RANK 1 · PIPE STAGE 1activation

所以后面 Megatron 的不同 parallelism 会对应不同通信模式：TP 经常是 collectives，PP 很多时候更像相邻 stage 的 P2P。

09 · RUN ONE ALL-REDUCE

四个进程，每人一个数字，亲手把它们求和。

python05_all_reduce.py
import os
import torch
import torch.distributed as dist

local_rank = int(os.environ["LOCAL_RANK"])
torch.cuda.set_device(local_rank)
dist.init_process_group("nccl")

rank = dist.get_rank()
world = dist.get_world_size()

x = torch.tensor([rank + 1.], device=f"cuda:{local_rank}")
dist.all_reduce(x, op=dist.ReduceOp.SUM)

print(f"rank={rank}, sum={x.item()}")
# world=4 时，每个 rank 都打印 sum=10

x /= world
print(f"rank={rank}, mean={x.item()}")
# 每个 rank 都得到 2.5

dist.destroy_process_group()
shelllaunch
torchrun --standalone --nproc-per-node=4 05_all_reduce.py

注意：all_reduce(SUM) 是求和，不会自动除以 world size。Distributed Data Parallel (DDP，分布式数据并行) 梯度同步里的具体 averaging 行为由 DDP 的实现语义处理，不应该把“all-reduce API 本身”记成“自动求平均”。

官方参考：PyTorch torch.distributed collective APIs。
10 · MAP COLLECTIVES TO AI INFRA

现在把几个 primitive 放回真实系统。

Pattern典型数据状态你以后会在哪见
all-reduce每 rank 有完整 shape 的不同值 → 每 rank 得到聚合后的完整结果经典 DP gradient sync；部分 TP reduction 边界
all-gather每 rank 有 shard → 每 rank 得到完整拼接结果sharded parameters / sequence shards 在需要完整视图时
reduce-scatter每 rank 有完整贡献 → reduce 后每人只留结果 shardsharded gradients / sequence-parallel outputs 等
all-to-all不同数据发往不同 peersMoE expert token dispatch / combine 的典型路径
send / recv一个 peer → 另一个 peerPipeline Parallel stage-to-stage activation / gradient

这里的“在哪见”是建立路线感，不表示每个框架在所有配置下都固定使用唯一一种 collective。Megatron 会根据 parallel mode、Sequence Parallel、dispatcher 和 overlap 策略组合不同通信操作。

11 · COMMUNICATION HAS A COST MODEL

同一个 collective，tensor 越大、group 越大、拓扑越差，代价通常越值得担心。

LATENCY一次通信启动的固定成本小 tensor / 高频 collective 时尤其显眼。
BANDWIDTH大量 bytes 搬运的吞吐上限大 tensor 时决定传输时间的主要部分。

真正通信量并不等于简单“tensor 大小 × peers”。下一课学 NCCL、ring/tree、NVLink/Peripheral Component Interconnect Express (PCIe，高速外设组件互连)/InfiniBand 时，我们再追 collective 怎样映射到真实链路。

12 · A COLLECTIVE IS A CONTRACT

参与者必须对“现在要做什么通信”有一致理解。

典型错误：

rank 0 进入 all-reduce，rank 1 却进入 all-gather；某些 ranks 根本没进入 collective；process group 不一致；tensor shape / count 不满足 API 要求。结果可能是 runtime error，也可能表现成一直等待。

所以 debugging 分布式代码时，一个有效方法是为每个 rank 打印collective 序号、group、shape、dtype，先确认所有 peers 对通信协议的理解一致。

CHECKPOINT04.2

别背名字，直接画输入和输出。

1. 四个 ranks 分别持有 A、B、C、D 四个 shards，最后希望每个 rank 都得到 [A,B,C,D]，最像哪个 collective？
all-gather。每个 rank 起初只有自己的 shard，结束时所有参与 ranks 都拥有完整拼接结果。
2. 为什么 reduce-scatter 比“先 all-reduce 再丢掉 3/4 结果”更符合 sharded state 的目标？
因为最终每个 rank 本来只需要 reduced result 的一个 shard。reduce-scatter 的语义直接产生分片后的聚合结果，不要求每 rank 都保留完整 reduced tensor。
3. MoE 为什么更容易出现 all-to-all，而不是简单 broadcast？
不同 token 会被 router 分配到不同 experts/ranks，所以每个 sender 需要把不同 token 子集发给不同 destinations；这更像全体之间的重排，而不是把同一份数据复制给所有人。
