LESSON 05.2 · MEGATRON约 70 min

Tensor Parallel：把一个 Linear 真正拆到两张 GPU 上。

这一课是整个 Megatron 部分最重要的地基。不要先背 ColumnParallelLinear 和 RowParallelLinear 两个类名。我们从最熟悉的 Y = XW 开始，自己推导：权重沿哪个维度切？每张 GPU 本地算什么？什么时候必须通信？最后再区分“最基础 TP 数学”与启用 Sequence Parallel 后真实实现会怎样改变 collective 边界。

这节课结束时，你应该能做到：
  • 从 [N,H] @ [H,4H] 推导 Column Parallel 的 local shapes。
  • 解释 Column Parallel 为什么可以暂时不 gather 输出。
  • 从 [N,4H] @ [4H,H] 推导 Row Parallel 为什么需要把 partial outputs 做 SUM reduction。
  • 理解 MLP 的 Column → Row 配对为什么能避免中间的 full all-gather。
  • 知道“Row Parallel = all-reduce”只是基础 TP 心智模型；Sequence Parallel 会把这个边界改成 reduce-scatter / all-gather 配对。
  • 把 QKV projection / attention output projection 映射到同一套 TP 模式。
  • 打开 Megatron Core 文档时能看懂 ColumnParallelLinear、RowParallelLinear 的关键参数。
01 · START FROM ONE LINEAR

没有 TP 时，一个 Linear 是一次完整 GEMM。

把 batch 和 sequence 先合并成 N = B×S，考虑 MLP 的第一个 Linear。为了图小一点，设 H=8，中间维度 4H=32：

INPUTX[N, 8]
@
WEIGHTW[8, 32]
X [N,8]@W [8,32]→Y [N,32]

注意这里为了推导清楚，使用数学上常见的 W=[in,out] 记法。PyTorch nn.Linear 内部参数张量常存成 [out,in]，底层会做等价的转置乘法。Megatron 文档描述 Y=XA+b 时也是按输入维与输出维讨论切分。别让存储布局把数学切分方向搞混。

02 · COLUMN PARALLEL

第一种切法：沿输出特征切 W，让每张 GPU 负责一部分输出列。

TP=2 时，把 W [8,32] 沿输出维切成两块：

W · OUTPUT DIMENSION SPLIT
GPU0GPU0GPU1GPU1W₀[8,16]W₁[8,16]
基础 TP：同一个 X 发给两个 TP ranks每个 rank 只保存一半输出列
TP RANK 0Y₀ = X @ W₀[N,8] @ [8,16] → [N,16]
TP RANK 1Y₁ = X @ W₁[N,8] @ [8,16] → [N,16]

把 Y₀ 和 Y₁ 沿最后一维拼起来，就等于原来的完整 Y [N,32]。所以最直观实现是：

GPU0Y₀ [N,16]
all-gather / concat
FULLY [N,32]
from
GPU1Y₁ [N,16]

但是这里出现 TP 的第一个关键优化：如果下一层本来就能直接消费这个 partitioned Y，就没有必要现在把它 gather 成完整 tensor。

03 · MEGATRON: COLUMNPARALLELLINEAR

这正是 ColumnParallelLinear 的核心语义。

ColumnParallelLinear把 Linear 权重沿输出方向分片；每个 TP rank 生成一部分 output features。
gather_output=False保持输出分片，不立刻 all-gather；这是把后续 Row Parallel 接起来的关键。
gather_output=True需要完整输出时，可以把各 rank 的输出 gather 回来；但这会产生额外通信和显存。

NVIDIA 当前 Megatron Core API 仍提供 core.tensor_parallel.layers.ColumnParallelLinear。真实类还会处理 bias、sequence parallel、gradient accumulation、异步通信和 Transformer Engine 等路径；这里先抓住 partition contract。

官方 API：Megatron Core · core.tensor_parallel.layers。当前页面列出 ColumnParallelLinear 与 RowParallelLinear 两个核心类。
04 · ROW PARALLEL

第二个 Linear 反过来：沿输入维切 W，并让每张 GPU 吃自己那份输入。

MLP 第二个 Linear 把 [N,32] 压回 [N,8]。现在假设前一层的输出还保持 TP 分片：GPU0 有 X₀=[N,16]，GPU1 有 X₁=[N,16]。

W · INPUT DIMENSION SPLIT
W₀[16,8]W₁[16,8]input halfGPU0input halfGPU1
每个 rank 只看一半输入特征每个 rank 都产生完整宽度的 partial output
TP RANK 0Z₀ = X₀ @ W₀[N,16] @ [16,8] → [N,8]
TP RANK 1Z₁ = X₁ @ W₁[N,16] @ [16,8] → [N,8]

但是 Z₀ 和 Z₁ 都只是完整矩阵乘法结果的一部分贡献。因为完整输出满足：

Z = Z₀ + Z₁
rank 0input shard 0 的贡献
rank 1input shard 1 的贡献
sum恢复完整数学结果

所以数学上必须对 partial outputs 做 SUM reduction。在最基础、不开 Sequence Parallel 的 TP 心智模型里，常把它画成 all-reduce：

local partial outputs → all-reduce SUM → replicated full output

别把“Row Parallel”与“永远执行 all-reduce”绑定。启用 Sequence Parallel 时，Megatron 可以把这段 reduction 与 sequence sharding 合并成 reduce-scatter，让每个 TP rank 只留下自己的 sequence shard；下一次需要完整 sequence 输入时再 all-gather。05.3 会专门推这条路径。

05 · WHY COLUMN → ROW IS THE MAGIC PAIR

前一层不 gather，后一层直接吃 shard，中间就省掉一次“拼完整”的通信。

COLUMN PARALLELlocal Y shard
no gather
ACTIVATIONlocal shard stays local
feed directly
ROW PARALLELlocal partial Z

在基础 TP 中，Row Parallel 末端通过 SUM reduction 恢复 replicated 输出；启用 SP 时，同一个数学 reduction 可以落成 sequence reduce-scatter。这种 Column → Row 布局非常适合 Transformer MLP：

FC1 / UPH → 4H · Column
→
ACTIVATIONpartitioned 4H
→
FC2 / DOWN4H → H · Row

这也是为什么理解 TP 不能只记“把矩阵切两半”。真正高效的设计会把相邻算子一起看，让一个算子的分片输出正好成为下一个算子的分片输入，并把 collective 放在最有利的边界。

06 · THE SAME IDEA INSIDE ATTENTION

Attention 里也能找到同样的 Column → local attention → Row 结构。

在典型 Megatron Transformer Attention 中，QKV projection 可以按输出/head 维度做 Tensor Parallel；每个 TP rank 负责一部分 query heads，以及由模型配置和实现支持决定的 K/V 分片。本地完成这部分 attention 后，output projection 再用 Row Parallel 合并各 shard 的贡献。

QKV PROJECTIONColumn Parallel
→
ATTENTIONlocal heads / shards
→
OUTPUT PROJRow Parallel

GQA 会让 K/V head 的切分约束更复杂。不要从“Q heads 等分”直接推出 K/V 也一定一模一样地等分；实际 mapping 取决于 query heads、query groups / KV heads、TP degree 和当前实现支持。

07 · TP SAVES MEMORY, BUT CREATES A NEW TAX

每张 GPU 的 Linear 变小了，但 collective 进入了 layer 的关键路径。

YOU GAINsmaller local weights每个 rank 只保存自己的权重 shard，单卡参数显存降低。
YOU GAINsmaller local GEMM每张 GPU 只算一部分矩阵乘法，理想情况下计算被并行分摊。
YOU PAYcommunication为了恢复正确的 layer 结果，需要 collective；TP 越大并不保证越快。

这正好把 04.3 的 NCCL/topology 接回来：TP 通信频率高，所以 TP group 通常应该优先放在高带宽、低延迟互连的近邻 GPU 上。跨慢网络盲目增大 TP，可能让 GPU 大量时间都在等通信。

08 · BACKWARD ALSO COMMUNICATES

刚才只画 forward，但训练中的 backward 也必须保持分片数学一致。

不同 TP Linear 在 backward 会涉及 input-gradient / weight-gradient 的局部计算与必要通信。Megatron Core 的实现不是简单“forward all-reduce 一次就结束”；它还有 gradient accumulation、async communication、sequence parallel、communication overlap 等工程路径。

初学阶段先把 forward 的两个切分推导牢。下一课 Sequence Parallel 会改变 activation 在 sequence 维的分布，并重新安排 all-gather / reduce-scatter 与 TP Linear 的 forward/backward 边界。

09 · OPEN THE REAL MEGATRON API

现在类名已经不再是黑盒。

FILE / MODULEcore.tensor_parallel.layersmegatron/core/tensor_parallel/layers.py核心 Linear class 所在模块。
CLASSColumnParallelLinearoutput dimension shard关注 gather_output：输出是否保持 TP partition。
CLASSRowParallelLinearinput dimension shard关注 input_is_parallel，以及 sequence-parallel 路径怎样改变 output reduction。
MAPPINGStensor_parallel.mappingscollective helpers理解 copy/reduce/scatter/gather 在 autograd forward/backward 中怎样配对。

Megatron 的 API 文档对 RowParallelLinear 明确写着：权重沿输入方向并行，输入也沿对应维度切成 X₁…Xₚ。这就是我们刚才自己推导的 partial-output SUM；至于 SUM 结果是 replicated 还是顺手 sequence-shard，要继续看当前配置和 mapping。

官方参考：core.tensor_parallel.layers；包结构参考：core.tensor_parallel。
10 · MINI-TP PSEUDOCODE

先写最基础的 TP 版本，再在 05.3 改成 SP 版本。

python-like pseudocodeTP=2 · SP off · MLP forward
# baseline TP: every TP rank sees the same X: [N, H]

# FC1: output-dimension shard
W1_local = shard(W1, dim=output)
h_local = X @ W1_local
h_local = gelu(h_local)

# FC2: input-dimension shard matches h_local
W2_local = shard(W2, dim=input)
y_partial = h_local @ W2_local

# SP disabled: every TP rank receives the summed output
y = all_reduce_sum(y_partial)

真实 Megatron 会处理 bias、autograd、RNG、Transformer Engine、FP8、async overlap、sequence parallel 等。这个伪代码故意标成 SP off，避免以后看到 reduce-scatter 时误以为源码“和 TP 理论矛盾”。

CHECKPOINT05.2

不看答案，自己推一遍两张 GPU。

1. W=[H,4H] 做 Column Parallel，TP=2 后每张 GPU 的 local weight 是什么 shape？
沿输出维切，所以每张是 [H,2H]。基础 TP 里输入 X 可以保持完整，每张卡得到一半 output features；启用 SP 后输入生命周期还会多出 sequence gather/scatter 边界。
2. 为什么 FC1 Column Parallel 后通常不急着 all-gather？
因为 FC2 可以用 Row Parallel，直接让每个 rank 消费自己那份中间特征 shard。这样中间无需恢复完整 4H activation，减少一次 collective 和显存复制。
3. Row Parallel 为什么需要 SUM，而 Sequence Parallel 又可能让你看见 reduce-scatter？
沿输入维拆开后，各 rank 得到的是同一输出坐标的 partial contribution，所以数学上必须 SUM。SP 只是把“SUM 后的输出如何分布”也纳入 collective：用 reduce-scatter 一边求和、一边只保留各自 sequence shard。
