LESSON 05.6 · MEGATRON约 65 min

Context Parallel：当 sequence 长到一张 GPU 连 Attention activation 都放不下。

Sequence Parallel 已经在 LayerNorm、dropout、residual 等区域把 tokens 分着放，但 Attention 仍然需要跨 token 的全局 context。Context Parallel 再往前一步：让不同 ranks 负责不同 sequence chunks，连 Attention 本身也跨 chunks 并行；至于 chunks 怎样交换，并不只有 ring 一种实现。

这节课结束时，你应该能做到：
  • 解释 CP 和 SP 都切 sequence，但为什么不是同一个东西。
  • 理解 CP 下每个 rank 只保存/计算自己的一段 query tokens。
  • 解释为什么 local Q 仍然需要整个可见 context 的 K/V 信息。
  • 理解 cp_comm_type='p2p' 时 ring KV exchange 的基本思路。
  • 知道当前 Megatron 还支持 all_gather、a2a、a2a+p2p，不能把 CP 定义成 ring。
  • 知道 GQA/MQA 为什么能直接降低以 K/V 为主的数据交换量。
  • 正确计算 dense Transformer grid 的 TP/PP/CP/DP rank 关系，并把 EP 当成另一套 expert grid 来理解。
01 · LONG CONTEXT CHANGES THE MEMORY SCALE

sequence 从 4K 变 32K，不只是“多算八倍 tokens”。

训练长上下文时，大量 activation 会随 sequence length 增长；Attention 还要求每个 query 根据 mask 规则访问其它 tokens 的 K/V。即便 FlashAttention 避免显式物化巨大 S×S score matrix，Q/K/V 与其它 activation 的保存、计算和通信仍然随 S 增长。

0–4K4–8K8–12K12–16K16–20K20–24K24–28K28–32K

一种粗暴办法是继续增大 TP，但这会把 Linear GEMM 也切得越来越小，通信占比可能上升。CP 的想法是：既然真正变长的是 sequence，就沿 sequence/context 维增加并行度。

02 · CP SPLITS THE NETWORK INPUT AND ACTIVATIONS

CP=2：一条 8K sequence，每个 CP rank 先只处理 4K tokens。

CP RANK 0local sequence chunk Atokens 0…4095
CP RANK 1local sequence chunk Btokens 4096…8191

Linear、LayerNorm、MLP 这些没有跨 token 依赖的模块，可以直接对 local sequence chunk 工作。真正特殊的是 Attention：rank 0 的 query tokens 不能只看 chunk A；只要 causal/window mask 允许，它们还需要其它 chunks 对应的 K/V 信息。

CP 的难点不是 split 本身。难点是怎样让 local Q 获得正确的 global-context K/V，同时不把每张卡重新撑成“持有完整 sequence 的单卡 Attention”。

03 · LOCAL Q, GLOBAL-CONTEXT KV

每张 GPU 保留自己的 Q chunk，但要通过 CP 通信获得其它 context chunks 的 K/V 信息。

LOCAL QUERYQ₀ for chunk A[S/CP, heads, d]
attends to →
visible context KV
KV CONTEXTK/V from A + B + ...stream / gather / redistribute

最容易理解的教学版是先 all-gather K/V，再算 attention。它很直观，但会让每个 rank 临时拿到更大的 K/V view。另一类做法是流式交换 K/V；还有 Ulysses 风格的 A2A 重排。这些是不同通信算法，都可以服务同一个 CP 数学目标。

04 · P2P MODE: RING KV EXCHANGE

当 cp_comm_type='p2p' 时，可以把 K/V 一块块沿 ring 流过来。

CP=4 · P2P MODE · ONE RANK'S VIEWlocal Q stays; KV chunks rotate
ROUND 0local KV₀Q₀ × KV₀
ROUND 1receive KV₁Q₀ × KV₁
ROUND 2receive KV₂Q₀ × KV₂
ROUND 3receive KV₃Q₀ × KV₃

这个模式的直觉是：本地 Q 不动，K/V chunks 轮转；收到一块就消费一块，而不是要求长期常驻全部 K/V。Backward 还要处理对应的 K/V gradient 聚合与分片。它是理解 CP 最好的第一张图，但不是 CP 的定义本身。

官方说明：Megatron Core · Context Parallel；当前配置中的具体通信模式见 TransformerConfig.cp_comm_type。
05 · P2P COMMUNICATION CAN OVERLAP ATTENTION COMPUTE

P2P ring 的系统价值之一，是给“边收下一块、边算当前块”留下空间。

NETWORK / P2Preceive KV chunk n+1异步传下一块 context。
∥
ATTENTIONcompute Qlocal × KVn当前 KV chunk 被 attention kernel 消费。
→
NEXT ROUNDKVn+1 ready继续下一块。
→
MERGEcorrect attention result用数值稳定的分块 attention 逻辑组合各 chunk 贡献。

当前 Megatron cp_comm_type='p2p' 配置说明明确写着 P2P ring 是异步的，并可与 attention compute overlap。“可 overlap”不等于“实际已经完全隐藏”；仍要看 CP degree、KV bytes、互连带宽与 attention kernel 时长。

06 · WHAT MEMORY DOES CP SAVE?

主要收益是：可沿 context partition 的 activation 不必在每张 GPU 完整复制。

CP = 1~ S × activation-per-token单 rank 处理整个 sequence。
→
CP = p~ (S/p) × activation-per-token可分片 activation 在每个 rank 上约随 CP degree 下降。

实际峰值还包含 K/V exchange buffers、attention backend workspace、TP/PP/DP 状态等，所以不能把“整个 GPU 显存”简单除以 CP。

07 · GQA / MQA CAN REDUCE KV TRAFFIC

K/V heads 越少，每个 token 的 K/V representation 越窄。

02.2 已经学过 GQA：很多 Q heads 共享较少的 KV heads。对于以 K/V exchange 为主的 CP 模式，这会减少每个 context chunk 需要搬的 K/V bytes；具体收益还受 attention backend、TP/CP layout 和通信算法影响。

MHANkv = NqKV 最宽。
GQANkv < Nq共享 KV heads，K/V 更窄。
MQANkv = 1KV 最窄，但模型质量与实现权衡由架构决定。

这条线以后会直接通向 vLLM KV Connector。训练 CP 和推理 KV transfer 的协议不同，但都必须先从 KV tensor 的 shape 计算真实 bytes。

08 · CP GROUPS ARE ORTHOGONAL TO DENSE TP

TP=4、CP=2 时，同一个 dense Transformer grid 可以看成 4 个 TP coordinates × 2 个 context chunks。

用 8 GPU 直觉图：GPU0–3 处理一个 sequence chunk，GPU4–7 处理另一个；对应 CP peers 是相同 TP coordinate 的 ranks：

TP GROUP · CHUNK AG0G1G2G3G4G5G6G7
TP GROUP · CHUNK BG0G1G2G3G4G5G6G7
CP PAIRS0↔41↔52↔63↔74↔05↔16↔27↔3

坐标感很重要：dense TP 分 hidden/features；CP 分 context。一个 rank 会同时有 TP coordinate、CP coordinate、PP stage 和 DP replica 身份。

当前 parallel_state.py 的 dense grid 直接用 model_size = TP × PP × CP（还可能包含实验性的额外轴），再由 DP = world_size / model_size 得到 data-parallel degree。
09 · CP IS NOT LIMITED TO ONE COMMUNICATION ALGORITHM

当前 Megatron 的 cp_comm_type 支持四类主要选择。

P2Pring KV exchange异步 P2P；可与 attention compute overlap。
ALL_GATHERgather full KV先获得完整 K/V view 再算；当前配置说明里不是异步 overlap 路径。
A2Ahead / sequence redistribution类似 Ulysses：在 CP group 内用 all-to-all 在 head 与 sequence 分布之间重排。
A2A + P2Phierarchical CP把两种方式组合到不同层级的拓扑上。

TransformerConfig.cp_comm_type 当前明确列出 p2p、all_gather、a2a、a2a+p2p，而且可以按 layer 指定列表。学习时先掌握数学 invariant：local Q 必须获得正确的远端 context 信息；通信算法是实现选择。

源码配置：TransformerConfig.cp_comm_type。
10 · SP VS CP, ONE LAST TIME

最稳的区别：Attention 本身是否保持 context partition。

SEQUENCE PARALLELTP 区域之间分片部分 activation重点减少 LayerNorm、dropout、residual 等区域的 replication；进入相应 TP compute 边界时通过 gather / reduce-scatter 配合。
CONTEXT PARALLELAttention 本身也沿 sequence/context 分布network input 与 attention activation 继续保持 context partition，并用 P2P/A2A/all-gather 等方式补齐跨 chunk 依赖。
11 · READ THE CONFIG PHYSICALLY

先算 dense grid，再单独理解 MoE expert grid；不要把所有缩写机械相乘。

shellconceptual Megatron setup
--seq-length 32768
--tensor-model-parallel-size 4
--context-parallel-size 4
--cp-comm-type p2p

# dense-grid intuition:
# local context ≈ 32768 / 4 = 8192 tokens
# dense model_size = TP × PP × CP
# DP = world_size / (TP × PP × CP)

这里修正一个很容易写错的公式：不要把 TP × PP × CP × EP × DP 当成 Megatron 的统一总 GPU 公式。当前 parallel_state.py 对 dense Transformer grid 的基础关系是 world_size = TP × PP × CP × DP（忽略实验性额外轴时）。MoE 又构造 expert grid：它使用 expert tensor parallel、EP、PP 与 expert-DP 的关系。EP 会改变 expert ranks 如何组织，并不是简单在 dense grid 外再无条件乘一个独立因子。

读多维并行最安全的方法不是背乘法口诀。打开 parallel_state.py，分别找 dense rank generator 和 expert rank generator，然后问“这个 rank 在哪套 grid 里、每个轴的 size 是多少”。

CHECKPOINT05.6

确认你已经能把“数学目标”和“通信算法”分开。

1. CP=4 时，一个 rank 只负责 S/4 个 query tokens，为什么不能只保留本地 K/V 就结束？
因为 self-attention 的 local query 仍可能按 mask 规则访问其它 context chunks。必须通过某种 CP communication 获得相应 K/V 信息。
2. 为什么不能说“CP 就是 Ring Attention”？
Ring P2P 是当前 Megatron 的一个 CP communication mode。cp_comm_type 还支持 all_gather、a2a、a2a+p2p。CP 定义的是 context partition 与 attention 的跨-chunk 正确性，不是某个固定 collective。
3. 为什么 TP×PP×CP×EP×DP 不是一个可以无脑使用的总 GPU 公式？
因为当前 Megatron 分别构造 dense grid 与 expert grid。dense grid 的基础 size 是 TP×PP×CP，再由 world size 得 DP；expert grid 又使用 expert-TP、EP、PP 与 expert-DP。EP 不是永远在 dense grid 外额外乘一次的独立轴。
