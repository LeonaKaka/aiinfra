LESSON 05.6 · MEGATRON约 65 min

Context Parallel：当 sequence 长到一张 GPU 连 Attention activation 都放不下。

Sequence Parallel 已经在 LayerNorm、dropout、residual 等区域把 tokens 分着放，但进入 Attention 时仍会把所需 sequence 视图恢复出来。长上下文继续变大后，真正的瓶颈就在 Attention 本身。Context Parallel 再往前一步：让不同 GPU 始终负责不同 sequence chunks，连 Attention 也跨这些 chunks 并行。

这节课结束时，你应该能做到：
  • 解释 CP 和 SP 都切 sequence，但为什么不是同一个东西。
  • 理解 CP 下每个 rank 只保存/计算自己的一段 query tokens。
  • 解释为什么 local Q 仍然需要看到整个 sequence 的 K/V。
  • 理解 Megatron 用 ring P2P 交换 KV chunks 的基本思路。
  • 知道 GQA/MQA 为什么能直接降低 CP 的 KV 通信量。
  • 看懂 --context-parallel-size 和当前 cp_comm_type 的几个主要选项。
01 · LONG CONTEXT CHANGES THE MEMORY SCALE

sequence 从 4K 变 32K，不只是“多算八倍 tokens”。

训练长上下文时，大量 activation 会随 sequence length 增长；Attention 还需要让每个 query token 与其它 tokens 的 K/V 建立关系。即便使用 FlashAttention 避免显式物化巨大 S×S score matrix，Q/K/V 与其它 activation 的保存和计算仍随 S 增长。

0–4K4–8K8–12K12–16K16–20K20–24K24–28K28–32K

一种粗暴办法是继续增大 TP，但这会把 Linear GEMM 也切得越来越小，通信占比可能上升。CP 的想法是：既然真正变长的是 sequence，就直接沿 sequence 维增加并行度。

02 · CP SPLITS THE NETWORK INPUT AND ACTIVATIONS

CP=2：一条 8K sequence，每个 CP rank 先只处理 4K tokens。

CP RANK 0local sequence chunk Atokens 0…4095
CP RANK 1local sequence chunk Btokens 4096…8191

Linear、LayerNorm、MLP 这些没有跨 token 依赖的模块，可以直接对 local sequence chunk 正常工作。真正特殊的是 Attention：rank 0 的 query tokens 不能只看 chunk A，它们还必须能 attend 到 chunk B 的 K/V；rank 1 同理。

CP 的难点不是“怎么 split tensor”。真正难点是：Attention 的每个 local Q 需要全局 K/V context，怎样交换这些 K/V 才既正确又不把显存重新撑爆。

03 · LOCAL Q, GLOBAL KV

每张 GPU 保留自己的 Q，但需要逐步拿到其它 CP ranks 的 K/V。

LOCAL QUERYQ₀ for chunk A[S/CP, heads, d]
attends to →
all sequence KV
KV CONTEXTK/V from A + B + ...stream / gather across CP

最容易理解的教学版是先 all-gather 全部 K/V，再算 attention。但那会瞬间让每个 rank 都持有全 sequence K/V，削弱 CP 的 activation-memory 优势。

Megatron 的经典 CP 实现更像 Ring Attention：K/V chunks 在 CP ranks 之间按 ring 传递；每个 rank 收到一个 K/V chunk，就让自己的 local Q 与它计算一部分 attention，再继续传下一块。

04 · RING KV EXCHANGE

不要一次收齐所有 K/V，而是一块一块流过来、边通信边算。

CP=4 · ONE RANK'S VIEWlocal Q stays; KV chunks rotate
ROUND 0local KV₀Q₀ × KV₀
ROUND 1receive KV₁Q₀ × KV₁
ROUND 2receive KV₂Q₀ × KV₂
ROUND 3receive KV₃Q₀ × KV₃

官方当前 Context Parallel 文档描述的是：概念上 CP forward 需要收集 full-sequence KV、backward 对 KV activation gradients 做 reduce-scatter；为了省 activation memory，每个 GPU forward 只保留自己的 KV chunk，并在 backward 需要时再次交换。实现中的 all-gather / reduce-scatter 可用 ring topology 的 point-to-point communication 完成。

官方深度说明：Megatron Core · Context Parallel Package。其中明确对比 SP 与 CP，并解释 KV 的 ring P2P exchange。
05 · COMMUNICATION CAN OVERLAP ATTENTION COMPUTE

Ring 的价值不仅是少占显存，还给“边收下一块 KV，边算当前块”留下空间。

NETWORK / P2Preceive KV chunk n+1异步传下一块 context。
∥
ATTENTIONcompute Qlocal × KVn当前 KV chunk 在 attention kernel 中被消费。
→
NEXT ROUNDKVn+1 ready继续下一块。
→
MERGEcorrect attention result组合各 chunk 的 attention contribution。

当前 Megatron cp_comm_type='p2p' 的 API 说明明确指出 P2P ring exchange 是异步的，可以与 attention compute overlap。是否真的隐藏住通信，仍取决于 CP degree、KV 大小、GPU↔GPU / 网络带宽和 kernel 时长。

06 · WHAT MEMORY DOES CP SAVE?

主要收益是：每张 GPU 只常驻自己那一段 sequence activation。

CP = 1~ S × activation-per-token单 rank 处理整个 sequence。
→
CP = p~ (S/p) × activation-per-token可沿 context partition 的 activation 在每个 rank 上约缩到 1/p；Attention 通过通信获得其它 chunks 的信息。

官方 CP 文档将其主要好处概括为：长 sequence 下 activation memory per GPU 随 CP degree 降低，同时 local compute 也因 token 数减少而下降。实际峰值还包含 KV transfer buffers、attention backend workspace、TP/PP/DP 状态等，所以不是整个显存简单除以 CP。

07 · GQA / MQA HELP TWICE

K/V heads 越少，KV Cache 小；在 CP 里，KV 通信量也跟着小。

02.2 已经学过 GQA：很多 Q heads 可以共享较少的 KV heads。到了 CP，这个设计又多了一个系统收益——跨 CP ranks 搬的是 K/V chunks，因此 K/V heads 变少会直接减少需要传输的数据量。

MHANkv = NqKV 较宽，CP 交换数据最多。
GQANkv < Nq共享 KV heads，通信量下降。
MQANkv = 1KV 最窄，但模型质量/实现权衡由架构决定。

这条线以后会直接通向 vLLM KV Connector。无论训练中的 CP 还是推理中的 KV transfer，KV tensor 的 shape 都决定要搬多少 bytes。

08 · CP GROUPS ARE ORTHOGONAL TO TP

TP=4、CP=2 时，不是 GPU0–GPU1 做 CP，而是“相同 TP 位置”的 ranks 跨 context chunks 配对。

官方 parallel_state 给了一个很好用的 8 GPU 例子：TP=4、CP=2。GPU0–3 处理一个 sequence chunk，GPU4–7 处理另一个。CP groups 则是：

TP GROUP · CHUNK AG0G1G2G3G4G5G6G7
TP GROUP · CHUNK BG0G1G2G3G4G5G6G7
CP PAIRS0↔41↔52↔63↔74↔05↔16↔27↔3

这能帮你建立一个很强的坐标感：TP 把同一 chunk 的 hidden/features 分着算；CP 则让相同 TP coordinate 的 ranks 交换不同 sequence chunks 的 context。

官方 API：core.parallel_state 当前对 context_parallel_size 给出了 TP4×CP2 的 rank-group 示例。
09 · CP IS NOT LIMITED TO ONE COMMUNICATION ALGORITHM

当前 Megatron 的 cp_comm_type 已经支持多种通信方式。

P2Pring KV exchange异步 point-to-point；可与 attention compute overlap，是最直观的 CP 心智模型。
ALL_GATHERgather full KV先拿完整 K/V 再算；当前配置说明中是同步路径，不能像 P2P 那样 overlap。
A2Ahead / sequence redistribution类似 Ulysses 思路，用 all-to-all 重排 attention heads 与 sequence。
A2A + P2Phierarchical CP可在低层快速互连用 A2A、跨更慢层级用 P2P，尊重硬件 topology。

当前 TransformerConfig.cp_comm_type 就列出了 p2p、all_gather、a2a、a2a+p2p。初学阶段先把 P2P ring 学透，其他策略以后看性能问题时再展开。

当前配置 API：core.transformer.transformer_config，见 cp_comm_type。
10 · SP VS CP, ONE LAST TIME

最容易混淆的两个概念，用“Attention 是否保持分片”来区分。

SEQUENCE PARALLELAttention/TP 区域外切 sequence重点减少 LayerNorm、dropout、residual 等 activation replication；需要进入 TP compute 时会 gather 相应 sequence view。
CONTEXT PARALLELAttention 本身也切 sequencenetwork inputs 和各层 activation 都沿 sequence partition；local Q 通过 KV exchange 获取全局 context，不再要求一张卡持有全部 sequence attention activation。

官方 CP 文档也明确用这个区别描述两者：SP 只切部分 Dropout/LayerNorm activations；CP 则沿 sequence 对 network inputs 和所有 activations 做 partition。

11 · READ THE CONFIG PHYSICALLY

以后看到 CP 配置，先算“每张卡真正处理多少 tokens”。

shellconceptual Megatron setup
--seq-length 32768
--tensor-model-parallel-size 4
--context-parallel-size 4
--cp-comm-type p2p

# 直觉：
# each CP rank handles ~ 32768 / 4 = 8192 tokens
# within each chunk, TP=4 still shards layer computation
# attention exchanges KV across corresponding CP peers

总 GPU 计数还要把 PP、DP、EP 等其它正交轴考虑进去。官方当前 Parallelism Guide 使用 Total GPUs = TP × PP × CP × EP × DP 作为组合策略的基础计数关系。

CHECKPOINT05.6

确认你已经能解释“为什么必须搬 KV”。

1. CP=4 时，一个 rank 只负责 S/4 个 query tokens，为什么不能只保留本地 K/V 就结束？
因为 self-attention 中本地 query 仍需根据 mask 规则 attend 到同一 sequence 的其它 tokens。其它 chunks 的 K/V 包含这些 token 的 context，因此必须通过 CP 通信获得。
2. 为什么 ring P2P 比“先 all-gather 全部 K/V”更适合建立省显存的 CP 心智模型？
ring 可以让 KV chunks 流式经过当前 rank，收到一块就计算一块，不必长期把整段 sequence 的 K/V 同时物化在本地；同时异步 P2P 还提供和 attention compute overlap 的机会。
3. GQA 为什么会让 CP 更便宜？
CP 跨 ranks 主要交换 K/V context。GQA 减少 KV heads，所以每个 token 的 K/V tensor 更窄；同样 sequence chunk 需要传的 KV bytes 就更少。
