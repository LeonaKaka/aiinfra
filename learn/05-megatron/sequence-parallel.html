LESSON 05.3 · MEGATRON约 60 min

Sequence Parallel：TP 已经切了权重，为什么 activation 还会重复？

上一课 Tensor Parallel 把大 Linear 切开了，但 Transformer 里并不是所有操作都天然沿 hidden/output 维切分。LayerNorm、dropout、residual 等区域如果仍让每个 TP rank 持有整段 sequence 的 activation，就会留下明显重复。Sequence Parallel 的核心就是：在这些区域里，把 sequence 维也分给 TP ranks。

这节课结束时，你应该能做到：
  • 解释为什么 TP 不等于“所有 activation 自动除以 TP degree”。
  • 理解 Sequence Parallel 主要在 TP group 内沿 sequence 维分片某些 activation。
  • 看懂为什么一个 TP all-reduce 可以从概念上拆成 reduce-scatter + all-gather。
  • 知道 LayerNorm / dropout / residual 为什么适合在 sequence shard 上本地计算。
  • 区分 Sequence Parallel 和 Context Parallel：两者都切 sequence，但解决的问题不同。
  • 打开 Megatron tensor_parallel.mappings 时能认出 gather / reduce-scatter 相关接口。
01 · THE MEMORY LEFTOVER AFTER TP

TP 把 Linear 切了，不代表整个 Transformer block 的每一块数据都切了。

假设 TP=4。上一课里，FC1 / QKV 等权重和输出特征可以分到四个 ranks。但一些操作仍然需要处理 hidden size 为 H 的完整 token vectors，例如 LayerNorm、residual connection、dropout。

TP RANK 0same activation[S,B,H]
TP RANK 1same activation[S,B,H]
TP RANK 2same activation[S,B,H]
TP RANK 3same activation[S,B,H]

如果这整块 activation 在四张卡都复制一份，那么 TP 虽然省了参数和部分 GEMM，但这些“非 TP 区域”的 activation 显存并没有跟着降到四分之一。

Sequence Parallel 的出发点不是再切一遍模型权重。它主要是在 TP group 内减少这些重复 activation。

02 · SHARD THE SEQUENCE DIMENSION

既然每个 token 的 LayerNorm 可以独立做，那就让每张 GPU 只负责一段 tokens。

设 sequence length S=4096、TP=4。Sequence Parallel 可以让四个 TP ranks 分别保存大约四分之一 sequence：

RANK 0tokens 0–1023[S/4,B,H]
RANK 1tokens 1024–2047[S/4,B,H]
RANK 2tokens 2048–3071[S/4,B,H]
RANK 3tokens 3072–4095[S/4,B,H]

LayerNorm 是逐 token 处理 hidden dimension；dropout 和 residual 也可以对本地 sequence chunk 做。因此这些操作没必要每张卡都持有全部 S 个 tokens。

WITHOUT SP~ S × B × H每个 TP rank 都保留完整 sequence activation。
→
WITH SP · TP=p~ (S/p) × B × H这类可 sequence-partition 的 activation 在每个 rank 上约缩小到 1/p。

这是一个心智模型，不代表 Transformer 训练总 activation 精确缩小到 1/TP；不同中间 tensor、attention backend、recompute 策略和 kernel 会影响实际峰值。

03 · WHERE DOES THE FULL SEQUENCE COME BACK?

进入某些 Tensor Parallel Linear 前，需要把 sequence shards 重新 gather。

考虑一段典型流程。Sequence-parallel 区域里每个 rank 只有 [S/p,B,H]。当接下来进入需要 TP Linear 处理的区域时，可以先在 TP group 内 all-gather sequence shards，恢复每个 rank 所需的完整输入，然后做本地 weight shard GEMM。

SP REGIONLayerNorm[S/p,B,H]
all-gather →
TP LINEAR INPUTfull sequence[S,B,H]
local TP GEMM →
ROW-PARALLEL PARTIALpartial output[S,B,H]
reduce-scatter →
SP REGIONlocal sequence shard[S/p,B,H]

这里最值得记的是结尾：上一课 Row Parallel 最直观的做法是 all-reduce partial outputs，让每个 TP rank 都拿到完整输出。Sequence Parallel 不需要每个 rank 都保留完整 sequence，于是可以直接做 reduce-scatter：既完成 SUM reduction，又把结果按 sequence 分给 ranks。

04 · ALL-REDUCE ≈ REDUCE-SCATTER + ALL-GATHER

为什么 SP 能省 activation，又不会凭空多出一整轮通信？

从 collective 语义上看，一个常见 ring all-reduce 本来就可以理解为两部分：

CONCEPTUAL DECOMPOSITIONall-reduce ≈ reduce-scatter + all-gather

Sequence Parallel 做的事情，可以理解成把这两半通信“拉开”：Row Parallel 之后先 reduce-scatter，保持 sequence shard；中间在 shard 上做 LayerNorm/dropout/residual；直到下一次需要完整 sequence 输入时再 all-gather。

ROW PARALLELpartial
REDUCE-SCATTERlocal S/p
LN / DROPOUT / RESIDUALlocal S/p
ALL-GATHERreconstruct
NEXT TP LINEARcompute

因此经典 Sequence Parallel 设计的重点是：重排已有 TP 通信边界，让可分片区域的 activation 不再复制。实际通信时间是否完全等价，还会受到实现、消息大小、拓扑和 overlap 影响，不能只靠公式判断性能。

05 · BACKWARD IS THE MIRROR IMAGE

Forward 里的 collective 会在 autograd 中配上对应的 backward 语义，但不是所有 gather 都固定反向 reduce-scatter。

Megatron 的 tensor-parallel mappings 用 autograd Function 把 forward/backward 的 collective 配对。当前实现里，最容易被一句话说错的是 gather_from_sequence_parallel_region：它的 backward 取决于 gather 之后的计算是否仍处于 tensor-parallel 模式。

gather_from_sequence_parallel_regionForward: all-gather；Backward: 默认 tensor_parallel_output_grad=True 时 reduce-scatter；若为 false，则只按 sequence split gradient。
reduce_scatter_to_sequence_parallel_regionForward: reduce-scatter；Backward: all-gather。
scatter_to_sequence_parallel_regionForward: split；Backward: all-gather。

为什么会有这个分支？如果 gather 后进入 TP computation，不同 TP partitions 会对输入 gradient 产生需要相加的贡献，所以 backward 要 reduce-scatter；如果 gather 后的 computation 是 duplicated，每个 rank 已经在做同一份计算，就不该再多做一次 reduction，只需要把 gradient 切回各自的 sequence shard。

这就是为什么读 Megatron 时不能只搜索 dist.all_gather 然后数调用次数。很多通信被包装在 autograd mapping 里，forward 和 backward 是成对设计的，而且具体 backward 语义还可能由调用上下文/flag 决定。

源码入口：megatron/core/tensor_parallel/mappings.py。当前 _GatherFromSequenceParallelRegion.backward() 会检查 tensor_parallel_output_grad，再选择 reduce-scatter 或 plain split。
06 · REAL LINEAR IMPLEMENTATION KNOWS ABOUT SP

Sequence Parallel 不是外面套个 split 就完了，Linear 的 backward 也要配合。

Megatron Core 当前 LinearWithGradAccumulationAndAsyncCommunication 文档里明确区分了普通 TP 与 sequence parallel：启用 sequence parallel 时，forward 输入会 all-gather，而 backward 的 input gradients 会 reduce-scatter；同时还能与 weight-gradient 计算做异步 overlap。

FORWARDactivation all-gather从 sequence shard 恢复 TP Linear 所需输入。
BACKWARDdgrad reduce-scatter把 input-gradient reduction 与 sequence partition 一起完成。
OPTIMIZATIONcommunication overlap真实 Megatron 会尝试把 collective 与独立 GEMM 工作重叠，而不是串行等待。
官方 API 参考：core.tensor_parallel.layers。其中 sequence_parallel 参数的说明直接写明 forward all-gather 与 backward reduce-scatter。
07 · DO NOT CONFUSE SP WITH CONTEXT PARALLEL

两者都“切 sequence”，但它们切到 Transformer 的不同深度。

SEQUENCE PARALLEL · SP减少 TP 区域之间的 activation replication主要让 LayerNorm、dropout、residual 等部分只处理本地 sequence shard；进入 TP Linear/attention 计算时会通过 gather 等方式满足数据需求。SP 通常依附于 TP group。
CONTEXT PARALLEL · CP让 Attention 本身也跨 sequence shards 执行用于长上下文，把 sequence 长度真正分到 CP ranks，并交换 K/V 等必要上下文；它直接改变 attention 的数据分布与通信。

所以 SP 不是“长上下文 attention 的最终方案”。它能省一部分 activation memory，但不会仅靠自己把 attention 的长序列问题彻底拆掉。后面的 CP 章节会专门处理这个问题。

08 · WHAT THE FLAG MEANS

--sequence-parallel 不是一个孤立 feature，而是 TP 的搭档。

shellMegatron concept
--tensor-model-parallel-size 4
--sequence-parallel

# 直觉：
# 1) weights / TP compute 沿 tensor dimensions shard
# 2) selected activations between TP regions 沿 sequence shard

NVIDIA 当前 Parallelism Guide 直接建议在使用 TP 时启用 Sequence Parallel，并把它的收益概括为：通过在 LayerNorm 与 Dropout 等位置对 sequence dimension 分片，减少 activation memory。

官方指南：Parallelism Strategies Guide，其中 Sequence Parallel 部分建议在 TP 下启用 --sequence-parallel。
09 · THE MENTAL MODEL TO KEEP

TP 决定“hidden/features 怎么切”，SP 决定“这些间隙里的 tokens 怎么分着放”。

TP REGION大 Linear / Attention 内部：按 tensor dimensions 分工，做 local GEMM。
TRANSITIONreduce-scatter：完成 reduction，同时把 sequence 分回各 rank。
SP REGIONLayerNorm / dropout / residual：每个 rank 只处理自己的 S/p tokens。
NEXT TP REGIONall-gather：需要时再恢复完整 sequence 视图。

如果你把这四步画得出来，后面看到 sequence_parallel=True、gather_from_sequence_parallel_region、reduce_scatter_to_sequence_parallel_region 就不会再只是认单词。

CHECKPOINT05.3

确认你没有把 SP 当成“第二种 TP”。

1. 为什么 TP=4 后，LayerNorm activation 仍可能在四张卡重复？
TP 主要把 Linear/Attention 等 tensor computation 沿 feature/weight 维分片。LayerNorm、dropout、residual 这类非 TP 区域如果不做额外处理，仍可能让每个 TP rank 持有完整 sequence activation。
2. Sequence Parallel 为什么常用 reduce-scatter，而不是 Row Parallel 后先 all-reduce 再手动 split？
reduce-scatter 可以一次完成“把 partial outputs 求和”与“把结果按 sequence 分片”，避免先在每个 rank 物化完整结果再丢掉大部分。
3. SP 和 CP 最关键的区别是什么？
SP 主要减少 TP 区域之间 LayerNorm/dropout/residual 等 activation 的重复，进入 TP compute 时会 gather；CP 则让 Attention 本身也跨 sequence chunks 执行并交换上下文/KV，用于真正的长序列并行。
