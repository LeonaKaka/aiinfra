LESSON 05.1 · MEGATRON约 55 min

为什么要模型并行：8 张 GPU 并不会自动变成一张 640GB 显卡。

到这里我们终于正式进入 Megatron。但第一课先不读源码。先把它要解决的问题钉死：模型、activation、optimizer state 太大时，一张 GPU 放不下；而多张 GPU 的显存彼此独立。所谓模型并行，本质上就是决定“模型的哪一部分放在哪些 rank 上，以及这些部分什么时候通信”。

这节课结束时，你应该能做到：
  • 解释为什么 Data Parallel 不能解决“单份模型本身就放不下”的问题。
  • 区分 TP、PP、DP 分别在切模型的哪个维度。
  • 知道 CP 与 EP 又分别在切 sequence/context 与 MoE experts。
  • 理解 Megatron 为什么要维护多种 process groups，而不是全世界只用一个 group。
  • 看到 tensor_model_parallel_size、pipeline_model_parallel_size 时能把它们映射回具体 GPU 分组。
  • 知道之后读源码时先看 parallel_state.py 和 tensor_parallel/，而不是从仓库第一页一路往下翻。
01 · THE FIRST WALL: IT DOES NOT FIT

70B 模型只算 BF16 权重，就已经大约 140 GB。

先做最粗的一笔账：

每张 GPU 有自己的 device memory。要让一个超过单卡显存的模型运行，必须明确把模型状态或计算拆到多张卡；数据需要跨设备时还要付通信成本。
02 · WHY DATA PARALLEL IS NOT ENOUGH

Data Parallel 擅长“多吃数据”，但默认会复制完整模型。

假设模型完整权重需要 130 GiB，而每张 GPU 只有 80 GiB。你即使有 8 张卡，传统 Data Parallel 仍然要求每个 DP rank 持有一份模型副本——所以第一张卡就已经放不下。

Data Parallel · replica
GPU0: full modelGPU1: full modelGPU2: full modelGPU3: full model
VS
Model Parallel · shard
GPU0: part AGPU1: part BGPU2: part CGPU3: part D

所以要区分两个不同问题：吞吐不够和单份模型放不下。DP 对第一个问题非常有效；模型并行首先解决第二个问题。

03 · THREE MAIN AXES

Megatron 最核心的三个视角：切 batch、切 layer、切 depth。

DATA PARALLEL · DP切 batch每组拥有同一份模型副本，各自处理不同样本；之后同步梯度/参数相关状态。
TENSOR PARALLEL · TP切一个 layer 内部把 Linear / Attention / MLP 里的大 tensor 计算分到多个 ranks；layer 内就会频繁通信。
PIPELINE PARALLEL · PP切模型深度前几层放一个 stage，后几层放另一个 stage；相邻 stages 传 activation / gradient。

这三种并行不是互斥选项。Megatron 的强项恰恰是把它们组合成多维并行：例如 TP=4、PP=8，再在剩余 GPU 上做 DP。

一个非常重要的心智模型：“并行度”不是把同一份工作随便平均分。每一种 parallelism 都选择了不同的数据维度，因此产生完全不同的通信模式。

04 · ONE WORLD, MANY GROUPS

同一个 global rank，会同时属于 TP group、PP group、DP group。

先看一个很小的例子：8 个 ranks，设 TP=2、PP=2，那剩下的 DP degree 就是 2。

ILLUSTRATIVE 2 × 2 × 2 PARALLEL GRID
rank 0tp0 · pp0 · dp0
rank 1tp1 · pp0 · dp0
rank 2tp0 · pp1 · dp0
rank 3tp1 · pp1 · dp0
rank 4tp0 · pp0 · dp1
rank 5tp1 · pp0 · dp1
rank 6tp0 · pp1 · dp1
rank 7tp1 · pp1 · dp1

Megatron 会为不同轴创建不同 process groups。比如某个 TP collective 只应该发生在同一 layer shard group 内，而不能把所有 8 个 rank 都卷进来。

TP GROUP EXAMPLE
[rank 0, rank 1] · 同一个 pipeline stage / data replica 内共同完成 tensor-parallel layer
PP GROUP EXAMPLE
[rank 0, rank 2] · 同一个 tensor shard / data replica 在不同 pipeline stages 之间传 activation
DP GROUP EXAMPLE
[rank 0, rank 4] · 相同模型分片位置的不同 data replicas 之间同步训练状态

具体 rank 排列会受 Megatron 的 parallel order 与初始化配置影响，所以不要死背上面的编号；要记住的是正交并行轴 → 不同 process group。

05 · MEGATRON HAS MORE THAN TP / PP / DP

长上下文和 MoE 又带来了新的切分维度。

CONTEXT PARALLEL · CP切 sequence/context不同 ranks 处理不同 sequence chunks；Attention 仍需交换必要的 context 信息。
EXPERT PARALLEL · EP切 MoE experts不同 ranks 持有不同 experts；token routing 会引入 all-to-all / dispatch 类通信。
SHARDED DATA PARALLEL切 model statesMegatron Distributed Optimizer / Megatron-FSDP 会进一步减少 DP replicas 之间重复保存的状态。

NVIDIA 当前 Megatron Core 的 Parallelism Guide 把 DP、TP、PP、CP、EP 和 Megatron-FSDP 都作为可组合策略。后面课程会按“最能建立系统直觉”的顺序展开，而不是一次把所有开关堆给你。

官方参考：Megatron Core · Parallelism Strategies Guide。当前文档明确列出 DP、TP、PP、CP、EP 与 Megatron-FSDP，并说明它们可以组合用于大规模训练。
06 · PARALLELISM MUST MATCH TOPOLOGY

为什么我们先学 NCCL 再学 Megatron？因为“怎么切”必须考虑“怎么连”。

TP 在单个 Transformer layer 里就会产生 collective，所以通常最希望 TP peers 是高带宽、低延迟的近邻 GPU。PP 更多是 stage 间 P2P；DP 则常跨节点扩展，并通过 overlap 隐藏一部分 gradient / parameter communication。

TP · layer-internal高频通信位于关键路径 → 优先考虑 NVLink/NVSwitch 等快速 GPU fabric。
PP · stage-to-stage相邻 stages 传 activation / gradient → placement 与 microbatch schedule 都会影响效率。
DP · replica-to-replica更容易跨节点扩展 → NIC / RDMA / network bandwidth 与 overlap 很重要。

所以以后看到 “TP=8 比 TP=4 更大，应该更快” 这种说法要警惕。TP degree 增大意味着 local GEMM 变小、通信参与者和通信占比也可能变化；是否更快必须结合模型尺寸与拓扑 benchmark。

07 · READ CONFIG AS A PHYSICAL LAYOUT

看到 Megatron 配置时，先翻译成“GPU 怎么分组”。

shellconceptual Megatron flags
--tensor-model-parallel-size 4
--pipeline-model-parallel-size 8
--context-parallel-size 1

# 如果 world_size = 64 且没有其它正交并行轴：
# TP × PP = 4 × 8 = 32 GPUs per model replica
# DP degree ≈ 64 / 32 = 2

这比单纯记参数名字有用得多：你应该马上意识到，一份模型跨 32 张 GPU；其中每个 pipeline stage 又由 4-way TP group 共同完成；全局还有两份 data replicas。

以后每看到一个 parallel size，都问三件事：它切的是哪个维度？同组 ranks 之间通信什么？它应该尽量放在什么硬件拓扑上？

09 · THE RULE FOR THE REST OF MEGATRON

每一种并行都用同一套四问法。

1 · SHARD到底把哪个 tensor / layer / sequence / expert 切开？
2 · LOCAL COMPUTE每个 rank 本地还要算什么？local GEMM 的 shape 变成什么？
3 · COMMUNICATION为了恢复数学上正确的结果，需要 all-reduce、all-gather、reduce-scatter、all-to-all 还是 send/recv？
4 · TRADE-OFF省了多少显存/计算？新增多少通信？能不能 overlap？

后面 TP、SP、PP、Distributed Optimizer、CP、EP 全部按这四问展开。这样你不是背“Megatron 有很多 feature”，而是学会自己推导 feature 为什么存在。

CHECKPOINT05.1

先确认你知道 Megatron 在解决什么。

1. 8 张 80GB GPU 总计 640GB，为什么一个 130GiB 模型仍然不能直接当成“放进一张 640GB 卡”？
因为每张 GPU 的 device memory 独立。模型必须显式 shard/partition 到多张卡；任何跨 shard 的依赖还需要真实通信。
2. 为什么传统 Data Parallel 不能解决“完整模型单卡放不下”？
传统 DP 在每个 data-parallel rank 上复制完整模型，只切 batch。它提高吞吐，但完整模型仍要在每张卡上存在，所以无法解决单份模型超过单卡容量的问题。
3. TP、PP、DP 最稳定的区分方式是什么？
看“切哪个维度”：DP 切 batch，TP 切一个 layer 内的 tensor/计算，PP 切模型深度。不同切法自然产生不同通信模式。
