LESSON 05.4 · MEGATRON约 70 min

Pipeline Parallel：把 Transformer layers 按深度分到不同 GPU。

TP 是“一个层内大家一起算”，PP 则换了一个维度：前几层放在 pipeline stage 0，中间几层放在 pipeline stage 1，后几层继续往后。这样单张 GPU 不再保存完整模型深度，但代价是 forward activations 要沿 pipeline 向后续 stages 传递，backward gradients 则沿相反方向返回。

这节课结束时，你应该能做到：
  • 解释 PP 与 TP 的切分维度为什么完全不同。
  • 把 24 层 Transformer 按 PP=4 切成四个 pipeline stages。
  • 理解 forward activations 与 backward gradients 在相邻 stages 之间的 P2P 数据流。
  • 解释为什么不切 microbatches 会产生大量流水线空闲。
  • 理解流水线从填充、稳态到排空的执行过程。
  • 知道 Megatron 的两类主要 pipeline schedules 对应哪些源码入口。
01 · 沿模型深度切分

24 层 Transformer，PP=4：每个 pipeline stage 先放 6 层。

STAGE 0Layers 1–6
STAGE 1Layers 7–12
STAGE 2Layers 13–18
STAGE 3Layers 19–24

每个 pipeline stage 只保存自己负责的 Transformer 层及相关 parameters / optimizer states / activations。这样模型深度带来的显存被分摊到多个 ranks。

PP RANK 0L1–L6input → hidden₆
PP RANK 1L7–L12hidden₆ → hidden₁₂
PP RANK 2L13–L18hidden₁₂ → hidden₁₈
PP RANK 3L19–L24hidden₁₈ → logits/loss

和 TP 不同，PP stages 之间通常不是每一层做 all-reduce，而是在 pipeline stage 边界通过 P2P 传 activation。

02 · 前向传激活，反向传梯度

Pipeline 的接口就是 pipeline stage 边界那块 activation tensor。

FORWARD阶段 0 → 阶段 1发送 pipeline stage 0 的输出 activation
activation →
← activation gradient
BACKWARD阶段 1 → 阶段 0把边界 activation 的 gradient 传回去

因此 PP 的核心通信更接近 send / recv，而不是 TP 那种层内 collective。Megatron Core 当前的 P2PCommunicator 就专门管理相邻 pipeline stages 之间的 tensor 交换。

官方 API：core.pipeline_parallel.p2p_communication。当前文档把 P2PCommunicator 定义为负责相邻 pipeline stages 之间张量交换的通信器。

05 · 一前向一反向

1F1B（一次前向一次反向：稳态中每个 pipeline stage 尽量交替执行一个 forward 和一个 backward microbatch）是一种本地执行顺序。

这里先看 non-interleaved 1F1B（非交错 1F1B：一个物理 rank 主要持有一个 pipeline stage）的最小教学模型。执行过程可以分成 warmup（预热阶段：先用 forward microbatches 逐步填满流水线）、steady state（稳态阶段：不同 stages 同时推进 forward 与 backward 工作）和 cooldown（排空阶段：停止注入新的 forward 后完成剩余 backward）。下面用 PP=4、4 个 microbatches、每个 forward/backward 都视为一个等长时间片；通信时间先忽略，只保留真正的数据依赖。绿色是 forward，蓝色是 backward，空格就是无法被消掉的等待。

NON-INTERLEAVED 1F1B · PP=4 · M=4equal-cost teaching model
1F1B 真正的意思是“每个 pipeline stage 的本地顺序尽量交替”，不是所有 stages 同步一起 F、再一起 B。最后一个 pipeline stage 最早拿到 loss gradient，因此最早进入 backward；gradient 再像波一样向前面的 stages 传播。

这个时间图是为了把依赖画清楚，不是性能预测器。真实 Megatron 里 F/B 时长可能不相等，通信也不是零成本，而且 overlap、重计算和后面要讲的交错调度都会改变实际 timeline。

06 · 更多微批次如何降低相对气泡

流水线深度固定时，microbatches 越多，填充/排空成本占比通常越小。

用最简单的 forward-only、每个 pipeline stage 等时长模型举例：有 p 个 stages、m 个 microbatches，完成所有 forward 需要大约 m + p - 1 个 stage 时间片。于是理想化 utilization（利用率：有有效计算工作的时间占总执行时间的比例）可以写成：

SIMPLIFIED FORWARD-ONLY INTUITIONutilization ≈ m / (m + p - 1)

这不是完整 1F1B 训练的通用性能公式，只是用来建立直觉：流水线越深，填充成本越大；microbatches 越多，bubble 的相对占比越容易被摊薄。真实效率还会受 F/B 时长不对称、stage 负载不均、通信、重计算等影响。

07 · 交错 / 虚拟流水线

一个物理 GPU 还可以持有多个虚拟 stages 和模型块。

non-interleaved 1F1B 里，一个 rank 常对应一段连续层。interleaved schedule（交错调度：让同一个物理 rank 持有多个模型块，并交替推进它们）则把模型切成更多 model chunk（模型块：交错流水线里分配给某个 rank 的一段模型层），让 microbatches 在多个 virtual pipeline stage（虚拟流水线阶段：在同一物理 rank 上进一步拆出的逻辑 stage）之间流动。

NON-INTERLEAVED每个 rank 一段连续层
GPU0: L1–L4GPU1: L5–L8GPU2: L9–L12GPU3: L13–L16
INTERLEAVED IDEA每个 rank 多个 model chunks
GPU0: chunk AGPU0: chunk EGPU1: chunk BGPU1: chunk F…

这样可以缩小 virtual pipeline stage 的粒度，增加 overlap 机会、降低某些 bubble，但 schedule 与通信会更复杂。Megatron 当前 Parallelism Guide 使用 --num-layers-per-virtual-pipeline-stage 配置 virtual pipeline stages。

官方指南：Parallelism Strategies Guide；当前 PP 示例包含 --pipeline-model-parallel-size 和 --num-layers-per-virtual-pipeline-stage。
08 · PP 和 TP 如何组合

一个 pipeline stage 本身可以不是一张 GPU，而是一整个 TP 进程组。

例如 PP=4、TP=2，一份模型就需要 8 张 GPU。每个 pipeline stage 由两张 GPU 共同完成内部张量并行：

PP 阶段 0
TP0TP1
PP 阶段 1
TP0TP1
PP 阶段 2
TP0TP1
PP 阶段 3
TP0TP1

pipeline stage 内是 TP collectives，stages 之间是 PP P2P。于是同一个 rank 同时处在 tensor-model-parallel group 和 pipeline-model-parallel group 中。05.1 的“一个 world，多种 process groups”现在真正开始工作。

09 · PP 带来什么，又付出什么

PP 不是“免费把层分开”，它把问题从显存转成流水线调度。

维度收益代价
parameter memory每个 pipeline stage 只保存部分层。stage 划分不均会导致内存 / 计算负载不均。
计算不同 stages 可并行处理不同 microbatches。填充 / 排空会产生 bubble。
通信不需要像 TP 那样每层频繁全组 collective。pipeline stage 边界的 activation / gradient 必须 P2P 传输。
调度1F1B / interleaving 可提高利用率。microbatch 数量、virtual pipeline stage、重计算都会相互影响。

CHECKPOINT05.4

确认你能把流水线当成一条真实的数据生产线。

1. TP 和 PP 最大的区别是什么？
TP 在一个层内沿张量/feature 维分工；PP 沿模型深度分层，把不同 layer ranges 放在不同 pipeline stages。它们因此使用不同通信：TP 更依赖 collectives，PP 更依赖 stages 之间的 P2P。
2. microbatch 为什么能减少 pipeline bubble？
pipeline stage 0 处理完 MB0 并发给 stage 1 后，可以立刻继续 MB1；于是不同 stages 同时处理不同 microbatches，避免只有一个 stage 忙而其它 stages 等待。
3. 1F1B 的三个阶段是什么？
warmup 先灌满流水线；steady state 让各 stages 在依赖允许时尽量交替执行 forward/backward microbatches；cooldown 在 forward 完成后排空剩余 backward。
