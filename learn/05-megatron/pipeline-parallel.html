LESSON 05.4 · MEGATRON约 70 min

Pipeline Parallel：把 Transformer layers 按深度分到不同 GPU。

Tensor Parallel 是“一个 layer 内大家一起算”，Pipeline Parallel 则换了一个维度：前几层放在 stage 0，中间几层放 stage 1，后几层继续往后。这样单张 GPU 不再保存整模型深度，但代价是 activation 必须沿 pipeline 向前传，gradient 又要沿 pipeline 向后传。

这节课结束时，你应该能做到：
  • 解释 PP 与 TP 的切分维度为什么完全不同。
  • 把 24 层 Transformer 按 PP=4 切成四个 pipeline stages。
  • 理解 activation forward send 与 gradient backward send 的 P2P 数据流。
  • 解释为什么不切 microbatch 会产生严重 pipeline bubble。
  • 理解 1F1B 的 warmup / steady state / cooldown 三个阶段。
  • 知道 Megatron 的 non-interleaved / interleaved pipeline schedules 对应哪些源码入口。
01 · SPLIT THE MODEL DEPTH

24 层 Transformer，PP=4：每个 stage 先放 6 层。

STAGE 0Layers 1–6
STAGE 1Layers 7–12
STAGE 2Layers 13–18
STAGE 3Layers 19–24

每个 stage 只保存自己负责的 Transformer layers 及相关参数/optimizer states/activations。这样模型深度带来的显存被分摊到多个 ranks。

PP RANK 0L1–L6input → hidden₆
PP RANK 1L7–L12hidden₆ → hidden₁₂
PP RANK 2L13–L18hidden₁₂ → hidden₁₈
PP RANK 3L19–L24hidden₁₈ → logits/loss

和 TP 不同，PP stage 之间通常不是每一层做 all-reduce，而是在 stage 边界通过 point-to-point 通信传 activation。

02 · FORWARD SENDS ACTIVATIONS, BACKWARD SENDS GRADIENTS

Pipeline 的接口就是 stage 边界那块 activation tensor。

FORWARDStage 0 → Stage 1发送 stage 0 的输出 activation
activation →
← dActivation
BACKWARDStage 1 → Stage 0把对边界 activation 的 gradient 传回去

因此 PP 的核心通信 primitive 更接近 send / recv，而不是 TP 那种 layer-internal collective。Megatron Core 当前的 P2PCommunicator 就专门管理相邻 pipeline stages 的 tensor exchanges。

官方 API：core.pipeline_parallel.p2p_communication。当前文档把 P2PCommunicator 定义为负责 consecutive pipeline stages 之间 tensor exchange 的通信器。

05 · 1F1B

稳态里尽量做到：一次 forward，接一次 backward。

WARMUP先灌 pipeline不同 stage 需要先积累足够的 forward microbatches，才能开始对应 backward。
STEADY STATE1F1B尽量交替执行一个 forward microbatch 和一个 backward microbatch，让 pipeline 保持忙碌。
COOLDOWN排空剩余 backward所有 forward 已完成后，把 pipeline 里尚未完成的 backward 做完。

1F1B 的价值不只是 GPU utilization。相比“先把所有 microbatches 全部 forward 再全部 backward”，1F1B 还可以缩短某些 activation 必须一直存着的时间，从而控制 pipeline activation memory。

不要把 1F1B 理解成每个时钟格所有 stages 同步做同一种事。不同 stage 此刻可能一个在 forward，另一个在 backward；schedule 的任务就是满足依赖同时尽量填满 GPU。

06 · MORE MICROBATCHES, SMALLER RELATIVE BUBBLE

pipeline depth 固定时，microbatches 越多，填充/排空成本占比通常越小。

用最简单的 forward-only、每 stage 等时长模型举例：有 p 个 stages、m 个 microbatches，完成所有 forward 需要大约 m + p - 1 个 stage-time slots。于是理想化 utilization 可以写成：

SIMPLIFIED FORWARD-ONLY INTUITIONutilization ≈ m / (m + p - 1)

这不是完整 1F1B 训练的通用性能公式，只是用来建立直觉：pipeline 越深，填充成本越大；microbatches 越多，bubble 的相对占比越容易被摊薄。真实效率还会受 F/B 时长不对称、stage imbalance、通信、recompute 等影响。

07 · INTERLEAVED / VIRTUAL PIPELINE

一个物理 GPU 还可以持有多个“虚拟 stages / model chunks”。

非 interleaved PP 里，一个 physical rank 常对应一段连续 layers。Interleaved schedule 则把模型切成更多 chunks，让同一个 rank 持有多个不连续 chunks，并让 microbatches 在这些 virtual stages 间流动。

NON-INTERLEAVED每个 rank 一段连续 layers
GPU0: L1–L4GPU1: L5–L8GPU2: L9–L12GPU3: L13–L16
INTERLEAVED IDEA每个 rank 多个 model chunks
GPU0: chunk AGPU0: chunk EGPU1: chunk BGPU1: chunk F…

这样可以缩小 virtual pipeline stage 的粒度，增加 overlap 机会、降低某些 bubble，但 schedule 与通信会更复杂。Megatron 当前 Parallelism Guide 使用 --num-layers-per-virtual-pipeline-stage 配置 virtual pipeline。

官方指南：Parallelism Strategies Guide；当前 PP 示例包含 --pipeline-model-parallel-size 和 --num-layers-per-virtual-pipeline-stage。
08 · PP AND TP COMBINE NATURALLY

一个 pipeline stage 本身可以不是一张 GPU，而是一整个 TP group。

例如 PP=4、TP=2，一份模型就需要 8 张 GPU。每个 stage 由两张 GPU 共同完成内部 Tensor Parallel：

PP STAGE 0
TP0TP1
PP STAGE 1
TP0TP1
PP STAGE 2
TP0TP1
PP STAGE 3
TP0TP1

stage 内是 TP collectives，stage 间是 PP P2P。于是同一个 rank 同时处在 tensor-model-parallel group 和 pipeline-model-parallel group 中。05.1 的“一个 world，多种 groups”现在真正开始工作。

09 · WHAT PP BUYS AND WHAT IT COSTS

PP 不是“免费把 layers 分开”，它把问题从显存转成 pipeline scheduling。

维度收益代价
Parameter memory每个 stage 只保存部分 layers。stage 划分不均会导致 memory / compute imbalance。
Compute不同 stages 可并行处理不同 microbatches。fill / drain 会产生 bubble。
Communication不需要像 TP 那样每层频繁全组 collective。stage boundary activation / gradient 必须 P2P 传输。
Scheduling1F1B / interleaving 可提高利用率。microbatch 数、virtual stages、recompute 都会相互影响。

CHECKPOINT05.4

确认你能把 pipeline 当成一条真实的数据生产线。

1. TP 和 PP 最大的区别是什么？
TP 在一个 layer 内沿 tensor/feature 维分工；PP 沿模型深度分层，把不同 layer ranges 放在不同 stages。它们因此使用不同通信：TP 更依赖 collectives，PP 更依赖 stage 间 P2P。
2. microbatch 为什么能减少 pipeline bubble？
stage 0 处理完 MB0 并发给 stage 1 后，可以立刻继续 MB1；于是不同 stages 同时处理不同 microbatches，避免只有一个 stage 忙而其他 stages 等待。
3. 1F1B 的三个阶段是什么？
Warmup 先灌 pipeline；steady state 尽量交替执行 forward/backward microbatches；cooldown 在 forward 完成后排空剩余 backward。
