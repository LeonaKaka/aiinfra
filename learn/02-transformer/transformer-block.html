LESSON 02.3 · TRANSFORMER约 55 min

Transformer Block：Attention、MLP、Residual、Norm 怎么拼起来？

到现在我们已经把 Attention 拆开看过了。但真正的大模型不是只有 Attention：每一层还要做归一化、残差连接和 Multi-Layer Perceptron (MLP，多层感知机)。把这些模块拼起来，你第一次能看见“一个 Transformer layer 到底在执行什么”，也终于有资格开始讨论它为什么要被切到多张 Graphics Processing Unit (GPU，图形处理器)。

这节课结束时，你应该能做到：
  • 从输入到输出讲清一个常见 pre-norm decoder block 的完整数据流。
  • 理解 Residual 为什么要求分支输出保持 [B,S,H]。
  • 知道 MLP 主要也是大 Linear，并能估算标准两层 MLP 的参数规模。
  • 区分“一个 block 的 forward”和外层 training loop / optimizer。
  • 解释 token position 如何进入 Attention，并理解可复用 Key-Value (KV，键-值) 还依赖一致的位置与模型语义。
  • 指出 Tensor Parallel、Pipeline Parallel、Key-Value (KV，键-值) Cache 分别会落在 block 的什么位置。
01 · THE WHOLE BLOCK

先看全貌：一个常见现代 decoder block 有两条大分支。

INPUTx[B,S,H]
↓
NORM 1Norm(x)→ Attention →[B,S,H]
RESIDUALx───────────────┐
＋ add
HIDDENh[B,S,H]
↓
NORM 2Norm(h)→ MLP →[B,S,H]
RESIDUALh───────────────┐
＋ add
OUTPUTy[B,S,H]

把它压成两行伪公式，就是：

pre-norm viewone block
h = x + Attention(Norm(x))
y = h + MLP(Norm(h))

架构并不只有这一种。原始 Transformer 常被描述为 post-norm；很多现代 decoder Large Language Model (LLM，大语言模型) 使用 pre-norm，并且 Norm、MLP、Attention 细节也各有差异。我们先掌握共同的数据流，再学具体模型。

02 · RESIDUAL CONNECTION

为什么 Attention 和 MLP 最后都要回到 [B,S,H]？因为要和输入直接相加。

x [B,S,H]+branch(x) [B,S,H]→output [B,S,H]

Residual connection 就是“保留原来的 x，再加上分支学到的新变化”。要逐元素相加，shape 必须一致。这也是上一课 Multi-Head Attention (MHA，多头注意力) 最后需要 merge heads 并经过 output projection 回到 H 的原因之一。

shape 稳定

每个 block 输入输出保持同样主形状，几十层可以直接堆起来。

信息直通

分支不必每层都重新创造全部表示，而是在已有表示上学习增量。

训练更稳

Residual 为深层网络提供更直接的信息与梯度路径，是深 Transformer 能训练起来的重要结构之一。

03 · NORMALIZATION

Norm 不负责“理解语言”，它主要让数值尺度更可控。

你会在模型里看到 LayerNorm、RMSNorm 等。现在不用背公式，只要知道它们通常沿 hidden dimension 对每个 token 的向量做归一化/缩放相关操作，输出 shape 不变：

BEFORE NORM[B,S,H]
→
NORMALIZEper token hidden vector
→
AFTER NORM[B,S,H]

现代 LLM 中 RMSNorm 很常见，但具体选择属于模型架构。对 Infra 来说，先记住两点：它是一个额外 kernel/算子；它不像大 Linear 那样有巨大 H×H 权重矩阵，却会参与每层的数据流和 kernel 调度。

04 · THE MLP BRANCH

MLP 看起来叫“前馈网络”，本质上还是你已经学过的大 Linear。

最经典的两层 MLP 可以先画成：

INPUTH
Linear ↑
INTERMEDIATE4H
activation
NONLINEARGELU / …
Linear ↓
OUTPUTH

忽略 bias，如果 intermediate size 恰好是 4H：

UP PROJECTIONH × 4H = 4H² parameters
DOWN PROJECTION4H × H = 4H² parameters

合计约 8H² 个权重。相比之下，普通 MHA 的 Q/K/V/O 四个 H×H 投影约是 4H²。这个粗算让你看到：MLP 往往是 block 里非常大的参数和 General Matrix Multiply (GEMM，通用矩阵乘法) 来源。

但别把 4H 当铁律。现代 LLM 常使用 SwiGLU 等 gated MLP，intermediate size 和投影数量会不同。以后读具体模型源码，要以配置为准。

05 · A TINY BLOCK IN PYTORCH

用一个最小类，把数据流真正写成代码。

python07_tiny_transformer_block.py
import torch
from torch import nn

class TinyBlock(nn.Module):
    def __init__(self, hidden=64, heads=4):
        super().__init__()
        self.norm1 = nn.LayerNorm(hidden)
        self.attn = nn.MultiheadAttention(
            hidden, heads, batch_first=True
        )
        self.norm2 = nn.LayerNorm(hidden)
        self.mlp = nn.Sequential(
            nn.Linear(hidden, 4 * hidden),
            nn.GELU(),
            nn.Linear(4 * hidden, hidden),
        )

    def forward(self, x):
        z = self.norm1(x)
        attn_out, _ = self.attn(z, z, z, need_weights=False)
        x = x + attn_out

        z = self.norm2(x)
        x = x + self.mlp(z)
        return x

x = torch.randn(2, 16, 64)
block = TinyBlock()
y = block(x)
print(y.shape)  # [2,16,64]

这里用 PyTorch 的高级 MultiheadAttention 是因为上一课已经手写过 Attention shape；这一课重点是观察一个 block 如何组合子模块。真实 LLM 的 attention、mask、position encoding、RMSNorm、gated MLP 等会更具体。

06 · POSITION IS PART OF ATTENTION STATE

同一个 token 出现在第 10 位和第 100 位，Attention 不能把它们当成同一件事。

decoder 不只需要知道“token 是什么”，还需要知道“token 在序列的什么位置”。很多现代 LLM 使用 Rotary Position Embedding (RoPE，旋转位置编码)：在常见实现里，Query 和 Key 会根据 positions 做位置相关变换，再进入 Attention。Value 通常不做同样的旋转。

mental modelposition-conditioned attention
hidden states
    │
    ├─→ Q ─┐
    ├─→ K ─┼─→ RoPE(positions, Q, K) ─→ Attention
    └─→ V ────────────────────────────→ Attention

# common decoder idea, not a promise about kernel fusion order

这会直接影响后面的 KV Cache：缓存不是“随便保存一份 K/V 数字以后就能到处用”。要安全复用本地或远端 KV，至少要保证它仍对应同一模型语义、同一层/头布局、同一 token 前缀与一致的位置编码约定。如果 position 或 RoPE 配置不兼容，即使字节数和 shape 都对，语义也可能已经错了。

token identity

缓存必须对应你以为的那段 prefix，而不是另一段“长度刚好一样”的序列。

position semantics

位置编号、RoPE 参数/缩放等必须与生成这些 K/V 时的约定兼容。

layout / format

layer、head、dtype、cache layout 也必须与消费端契约一致；这会在 06–08 模块继续具体化。

实现和语义要分开：真实 runtime 可以把 Query/Key normalization、RoPE、KV cache write 等步骤融合进 kernel；你不需要背某个函数调用顺序。需要牢牢记住的是：KV reuse 复用的是带上下文语义的模型状态，不只是搬一段显存。

当前 vLLM 的 Qwen3 路径就是一个直观例子：positions 传入 attention，Q/K 先经过 rotary_emb(positions, q, k)，随后进入 attention。源码入口：vLLM · qwen3.py。具体模型与 fused kernel 可能采用不同实现组织，因此这里把它作为语义示例，不把函数排列当永久接口定义。
07 · FROM ONE BLOCK TO A MODEL

大模型，就是把这种 block 重复很多层，再加上入口和出口。

INPUTtoken ids
↓
EMBEDDING[B,S,H]
↓
Transformer Block × LLayer 1Layer 2⋮Layer L
↓
FINAL NORM + Language Model (LM，语言模型) HEADlogits

所以以后看到“80-layer model”，不是 80 个完全不同的概念，而是同一种 block 结构使用不同参数重复 80 次。也因此，单层里一点点显存、通信或 kernel 调度浪费，乘上几十层后都会很明显。

08 · BLOCK VS TRAINING LOOP

别把 forward 里的 block 和外面的 optimizer 混在一起。

MODEL FORWARDblock(x)Norm → Attention → Residual → Norm → MLP → Residual
TRAINING LOOPloss.backward()对所有 blocks 的参数沿计算图产生 gradients
OPTIMIZERstep()在 forward/backward 之外更新所有可训练参数

这三个层级分清以后，读 Megatron 源码会轻松很多：model code 定义“算什么”，distributed/runtime code 决定“在哪张 GPU 算、怎么通信”，optimizer code 决定“参数怎么更新”。

10 · THE ROAD TO INFERENCE

Prefill 和 Decode 都执行这些 blocks，但每一步的工作量结构不同。

PREFILL一次送入很多 prompt tokens大矩阵计算更充分；每层产生并保存 prompt 的 KV Cache。
DECODE通常每条序列一次新增一个 token每层复用历史 KV；小批量/低算术强度问题更突出。

这就是为什么同一个模型，训练 Infra 和推理 Infra 会长得很不一样。vLLM 章节会从这里继续：如何调度很多 request、管理 KV blocks、让 GPU 在 decode 阶段仍然高效。

CHECKPOINTMODULE 02

能把一个 block 画出来，Transformer 地基才算完成。

1. 为什么 Attention 分支输出通常要回到 [B,S,H]？
因为需要和 residual 路径上的输入逐元素相加；主 hidden shape 一致也让多个 blocks 可以连续堆叠。
2. 标准两层 H → 4H → H MLP 忽略 bias 大约有多少权重？
H×4H + 4H×H = 8H²。这是一个教学估算，现代 gated MLP 的结构和 intermediate size 可能不同。
3. Pipeline Parallel 和 Tensor Parallel 最直观的区别是什么？
在这里的第一层直觉是：Pipeline Parallel 更像把不同 Transformer layers 分给不同 stages；Tensor Parallel 则在同一层内部切分大 Linear / attention heads 等张量计算。后面会正式推导通信。
4. 为什么远端拿到 shape 完全正确的 KV，仍然不代表一定可以安全复用？
因为 KV 还依赖生成它时的模型、layer/head layout、token prefix、position/RoPE 语义和 cache format。字节数正确只是必要条件，不是语义兼容的充分条件。
