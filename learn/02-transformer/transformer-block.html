Transformer Block：Attention、MLP、残差连接和归一化怎么拼起来？

到现在我们已经把 Attention 拆开看过了。但真正的大模型不是只有 Attention：每一层还要做归一化、残差连接和多层感知机（MLP）。把这些模块拼起来，你第一次能看见“一个 Transformer 层到底在执行什么”，也终于有资格开始讨论它为什么要被切到多张图形处理器（GPU）。

这节课结束时，你应该能做到：
  • 从输入到输出讲清一个常见的预归一化（pre-norm）解码器块的完整数据流。
  • 理解残差连接为什么要求分支输出保持 [B,S,H]。
  • 知道 MLP 主要也是大型线性层，并能估算标准两层MLP的参数规模。
  • 区分“一个块的前向计算”和外层训练循环 / 优化器。
  • 解释 token 的位置信息如何进入 Attention，并理解可复用的键值状态还依赖一致的位置与模型语义。
  • 指出张量并行、流水线并行和 KV Cache 分别会落在 Transformer Block 的什么位置。
01 · 先看完整 Transformer Block

先看全貌：一个常见现代解码器块有两条大分支。

INPUTx[B,S,H]
↓
NORM 1归一化(x)→ Attention →[B,S,H]
RESIDUALx───────────────┐
＋ add
HIDDENh[B,S,H]
↓
NORM 2归一化(h)→ MLP →[B,S,H]
RESIDUALh───────────────┐
＋ add
OUTPUTy[B,S,H]

把它压成两行伪公式，就是：

pre-norm viewone块
h = x + Attention(Norm(x))
y = h + MLP(Norm(h))

架构并不只有这一种。原始Transformer常被描述为post-norm；很多现代decoder大语言模型（LLM）使用pre-norm，并且归一化、MLP、Attention细节也各有差异。我们先掌握共同的数据流，再学具体模型。

02 · 残差连接

为什么Attention和MLP最后都要回到 [B,S,H]？因为要和输入直接相加。

x [B,S,H]+branch(x) [B,S,H]→output [B,S,H]

残差连接connection就是“保留原来的x，再加上分支学到的新变化”。要逐元素相加，形状必须一致。这也是上一课多头注意力（MHA）最后需要merge heads并经过output投影回到H的原因之一。

形状稳定

每个块输入输出保持同样主形状，几十层可以直接堆起来。

信息直通

分支不必每层都重新创造全部表示，而是在已有表示上学习增量。

训练更稳

残差连接为深层网络提供更直接的信息与梯度路径，是深Transformer能训练起来的重要结构之一。

03 · 归一化

归一化不负责“理解语言”，它主要让数值尺度更可控。

你会在模型里看到LayerNorm、RMSNorm等。现在不用背公式，只要知道它们通常沿隐藏维度对每个token的向量做归一化/缩放相关操作，输出形状不变：

BEFORE NORM[B,S,H]
→
NORMALIZEper token hidden vector
→
AFTER NORM[B,S,H]

现代LLM中RMSNorm很常见，但具体选择属于模型架构。对Infra来说，先记住两点：它是一个额外kernel/算子；它不像大线性层那样有巨大 H×H 权重矩阵，却会参与每层的数据流和kernel调度。

04 · MLP 分支

MLP看起来叫“前馈网络”，本质上还是你已经学过的大线性层。

最经典的两层MLP可以先画成：

INPUTH
线性层 ↑
INTERMEDIATE4H
activation
NONLINEARGELU / …
线性层 ↓
OUTPUTH

忽略bias，如果intermediate size恰好是 4H：

UP投影H × 4H = 4H² parameters
DOWN投影4H × H = 4H² parameters

合计约 8H² 个权重。相比之下，普通MHA的Q/K/V/O四个H×H投影约是4H²。这个粗算让你看到：MLP往往是块里非常大的参数和通用矩阵乘法（GEMM）来源。

但别把4H当铁律。现代LLM常使用SwiGLU等gated MLP，intermediate size和投影数量会不同。以后读具体模型源码，要以配置为准。

05 · 在 PyTorch 里搭一个最小 Block

用一个最小类，把数据流真正写成代码。

python07_tiny_transformer_block.py
import torch
from torch import nn

class TinyBlock(nn.Module):
    def __init__(self, hidden=64, heads=4):
        super().__init__()
        self.norm1 = nn.LayerNorm(hidden)
        self.attn = nn.MultiheadAttention(
            hidden, heads, batch_first=True
        )
        self.norm2 = nn.LayerNorm(hidden)
        self.mlp = nn.Sequential(
            nn.Linear(hidden, 4 * hidden),
            nn.GELU(),
            nn.Linear(4 * hidden, hidden),
        )

    def forward(self, x):
        z = self.norm1(x)
        attn_out, _ = self.attn(z, z, z, need_weights=False)
        x = x + attn_out

        z = self.norm2(x)
        x = x + self.mlp(z)
        return x

x = torch.randn(2, 16, 64)
block = TinyBlock()
y = block(x)
print(y.shape)  # [2,16,64]

这里用PyTorch的高级 MultiheadAttention 是因为上一课已经手写过Attention形状；这一课重点是观察一个块如何组合子模块。真实LLM的attention、mask、position encoding、RMSNorm、gated MLP等会更具体。

06 · 位置信息也是 Attention 状态的一部分

同一个token出现在第10位和第100位，Attention不能把它们当成同一件事。

decoder不只需要知道“token是什么”，还需要知道“token在序列的什么位置”。很多现代LLM使用旋转位置编码（RoPE）：在常见实现里，Query和Key会根据 positions 做位置相关变换，再进入Attention。Value通常不做同样的旋转。

mental modelposition-conditioned attention
hidden states
    │
    ├─→ Q ─┐
    ├─→ K ─┼─→ RoPE(positions, Q, K) ─→ Attention
    └─→ V ────────────────────────────→ Attention

# common decoder idea, not a promise about kernel fusion order

这会直接影响后面的KV Cache：缓存不是“随便保存一份K/V数字以后就能到处用”。要安全复用本地或远端KV，至少要保证它仍对应同一模型语义、同一层/头布局、同一token前缀与一致的位置编码约定。如果position或RoPE配置不兼容，即使字节数和形状都对，语义也可能已经错了。

token identity

缓存必须对应你以为的那段prefix，而不是另一段“长度刚好一样”的序列。

position semantics

位置编号、RoPE参数/缩放等必须与生成这些K/V时的约定兼容。

布局 / format

layer、头、dtype、cache 布局也必须与消费端契约一致；这会在06–08模块继续具体化。

实现和语义要分开：真实runtime可以把Query/Key normalization、RoPE、KV cache write等步骤融合进kernel；你不需要背某个函数调用顺序。需要牢牢记住的是：KV reuse复用的是带上下文语义的模型状态，不只是搬一段显存。

当前vLLM的Qwen3路径就是一个直观例子：positions 传入attention，Q/K先经过 rotary_emb(positions, q, k)，随后进入attention。源码入口：vLLM · qwen3.py。具体模型与fused kernel可能采用不同实现组织，因此这里把它作为语义示例，不把函数排列当永久接口定义。
07 · 从一个 Block 堆成模型

大模型，就是把这种块重复很多层，再加上入口和出口。

INPUTtoken ids
↓
EMBEDDING[B,S,H]
↓
Transformer Block × LLayer 1Layer 2⋮Layer L
↓
FINAL NORM + 语言模型（LM）头logits

所以以后看到“80-layer model”，不是80个完全不同的概念，而是同一种块结构使用不同参数重复80次。也因此，单层里一点点显存、通信或kernel调度浪费，乘上几十层后都会很明显。

08 · Transformer Block 与训练循环的关系

别把前向计算里的块和外面的优化器混在一起。

MODEL前向计算块(x)归一化 → Attention → 残差连接 → 归一化 → MLP → 残差连接
训练循环loss.backward()对所有blocks的参数沿计算图产生gradients
优化器step()在前向计算/backward之外更新所有可训练参数

这三个层级分清以后，读Megatron源码会轻松很多：model code定义“算什么”，distributed/runtime code决定“在哪张GPU算、怎么通信”，优化器code决定“参数怎么更新”。

10 · 通往大模型推理

Prefill和Decode都执行这些blocks，但每一步的工作量结构不同。

PREFILL一次送入很多prompt tokens大矩阵计算更充分；每层产生并保存prompt的KV Cache。
DECODE通常每条序列一次新增一个token每层复用历史KV；小批量/低算术强度问题更突出。

这就是为什么同一个模型，训练Infra和推理Infra会长得很不一样。vLLM章节会从这里继续：如何调度很多请求、管理KV blocks、让GPU在decode阶段仍然高效。

CHECKPOINTMODULE 02

能把一个块画出来，Transformer地基才算完成。

1. 为什么Attention分支输出通常要回到 [B,S,H]？
因为需要和residual路径上的输入逐元素相加；主hidden形状一致也让多个blocks可以连续堆叠。
2. 标准两层 H → 4H → H MLP忽略bias大约有多少权重？
H×4H + 4H×H = 8H²。这是一个教学估算，现代gated MLP的结构和intermediate size可能不同。
3. Pipeline Parallel和Tensor Parallel最直观的区别是什么？
在这里的第一层直觉是：Pipeline Parallel更像把不同Transformer layers分给不同阶段；Tensor Parallel则在同一层内部切分大线性层 / 注意力头等张量计算。后面会正式推导通信。
4. 为什么远端拿到形状完全正确的KV，仍然不代表一定可以安全复用？
因为KV还依赖生成它时的模型、layer/头布局、token prefix、position/RoPE语义和cache format。字节数正确只是必要条件，不是语义兼容的充分条件。
