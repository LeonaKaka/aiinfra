LESSON 02.1 · TRANSFORMER约 45 min

Attention 数据流：Q、K、V 到底从哪里来？

Attention 最容易被一条公式吓住。我们换个顺序：先把它看成一条很普通的数据流水线。输入 X 先经过三个 Linear 变成 Q、K、V；Q 和 K 决定“该看谁”；这些权重再去混合 V。只要每一步的 shape 能追下来，后面 Multi-Head、Key-Value (KV，键-值) Cache、Tensor Parallel 都会自然得多。

这节课结束时，你应该能做到：
  • 解释 Q、K、V 都是从输入 X 经过不同 Linear 投影得到的。
  • 推导 Q @ Kᵀ → [S,S] 为什么得到 token-to-token 的分数矩阵。
  • 理解 causal mask 为什么必须在 decoder 自回归模型里阻止“偷看未来”。
  • 推导 softmax(scores) @ V 为什么又回到每个 token 一条向量。
  • 说出 Attention 与 Megatron Tensor Parallel、vLLM KV Cache 的第一条连接线。
01 · START FROM WHAT YOU KNOW

Attention 的起点，仍然只是一个 [B,S,H] tensor。

先用一个玩具设置：B=2、S=4、H=8。也就是一批有 2 条序列，每条 4 个 token，每个 token 用 8 个数字表示。

X = [2, 4, 8]
B · 2两条样本
S · 4每条四个 token
H · 8每个 token 八维

上一模块已经告诉我们：Linear 可以只改变最后一维。所以如果准备三个不同的 8 → 8 Linear，同一个 X 就能产生三份 shape 完全相同、数值含义不同的 tensor。

02 · THREE LINEAR PROJECTIONS

Q、K、V 不是凭空出现的：就是三个不同的 Linear。

INPUTX[B,S,H]
→
QUERYQ = XWq[B,S,H]
KEYK = XWk[B,S,H]
VALUEV = XWv[B,S,H]

可以先用一个不严格但很好用的比喻：

Query · 我在找什么？

当前 token 以 Q 的方式表达自己的“查询需求”。

Key · 我有什么特征？

每个 token 以 K 的方式提供可被匹配的“索引特征”。

Value · 真正拿走什么？

匹配强弱确定后，最后按权重混合的是 V 中的信息。

别把比喻当定义。真正的定义仍然是三个可学习的线性投影。模型训练后自己学会什么样的 Q/K 匹配对任务有用。

源码预告：概念上我们写成 Wq、Wk、Wv 三个投影；真实高性能实现经常把它们融合成一次更大的 Query-Key-Value (QKV，查询-键-值) projection。并且在 Grouped-Query Attention (GQA，分组查询注意力) 等结构里，K/V 的总宽度也不一定和 Q 一样。下一课再把这些差异拆开。

03 · Q MEETS K

一个 token 怎么给所有 token 打分？用自己的 Q 去点积所有 K。

先暂时忽略 batch，只看一条长度 S=4 的序列。Q 和 K 都可以想成 [4,8]：

Q [4,8]@Kᵀ [8,4]→scores [4,4]

为什么结果是 [4,4]？第一维的 4 代表“有 4 个 query token”；第二维的 4 代表“每个 query 都要和 4 个 key token 比一次”。于是每个格子就是一对 token 的匹配分数。

Q \ K
K₁
K₂
K₃
K₄
Q₁
q₁·k₁q₁·k₂q₁·k₃q₁·k₄
Q₂
q₂·k₁q₂·k₂q₂·k₃q₂·k₄
Q₃
q₃·k₁q₃·k₂q₃·k₃q₃·k₄
Q₄
q₄·k₁q₄·k₂q₄·k₃q₄·k₄

实际 scaled dot-product attention 还会把这些点积除以 √dₖ。现在只记作用：维度大时点积的量级容易变大，缩放可以让 softmax 的数值范围更稳定。

04 · CAUSAL MASK

生成模型不能在训练时偷看右边还没生成的 token。

对于 Generative Pre-trained Transformer (GPT，生成式预训练 Transformer) 这类 decoder-only 自回归模型，token 2 可以看 token 1 和自己，但不能看 token 3、4。于是 softmax 前会把未来位置屏蔽掉：

Q₁✓×××
Q₂✓✓××
Q₃✓✓✓×
Q₄✓✓✓✓

代码里常见做法是把被屏蔽位置的 score 设成一个极小值（概念上可看作 -∞）。softmax 之后，这些位置的权重就变成 0。

不要泛化过头：causal mask 是自回归 decoder attention 的典型要求；不同 Transformer 架构的 mask 规则可以不同。

05 · SCORES BECOME WEIGHTS

Softmax 做的事：把一行分数变成一行“该看多少”的权重。

对某个 query token，假设允许看到三个位置，softmax 后可能得到：

token 10.68
token 20.21
token 30.11

这些权重加起来是 1。权重大，代表当前 query 会从对应 token 的 Value 中取更多信息。于是 attention 不再只是“谁像谁”，而变成了一个可用于加权混合 V 的矩阵。

06 · WEIGHTS MIX VALUES

最后一步：attention weights @ V。

仍然看单条序列：

weights [S,S]@V [S,H]→context [S,H]

每一行权重都对应一个 query token。它拿这 S 个权重去加权 S 条 Value 向量，最后得到一条新的 H 维向量。所以输出又回到“每个 token 一条向量”的结构。

1X[B,S,H]
→
2Q K V3 × [B,S,H]
→
3scores[B,S,S]
→
4weights[B,S,S]
→
5context[B,S,H]

这里故意还是“单头教学版”。下一课 Multi-Head Attention 会把 H 拆成 n_heads × head_dim，到时 scores 会多一个 head 维度。标准 Multi-Head Attention 在各 head 的结果拼回去以后，通常还会再经过一个 output projection Wₒ；我们也留到下一课一起讲。

07 · SEE THE SHAPES IN PYTORCH

不用高级 Attention API，自己把这条数据流跑一次。

python04_attention_single_head.py
import math
import torch

B, S, H = 2, 4, 8
X = torch.randn(B, S, H)

Wq = torch.randn(H, H)
Wk = torch.randn(H, H)
Wv = torch.randn(H, H)

Q = X @ Wq                         # [2,4,8]
K = X @ Wk                         # [2,4,8]
V = X @ Wv                         # [2,4,8]

scores = Q @ K.transpose(-2, -1)   # [2,4,4]
scores = scores / math.sqrt(H)

mask = torch.triu(
    torch.ones(S, S, dtype=torch.bool), diagonal=1
)
scores = scores.masked_fill(mask, float('-inf'))

weights = torch.softmax(scores, dim=-1)  # [2,4,4]
context = weights @ V                    # [2,4,8]

print(Q.shape, scores.shape, context.shape)

这段代码只是为了看 shape，所以 Wq/Wk/Wv 直接用随机矩阵。真正 Transformer 里它们是模型参数，通常由 Linear 层管理并在训练中学习。

08 · WHY INFRA CARES

Attention 一旦变大，会同时碰到计算、显存和并行问题。

Q/K/V PROJECTIONS三个大 Linear → 大量 General Matrix Multiply (GEMM，通用矩阵乘法)；这是 Tensor Parallel 很自然的切分目标。
SCORE MATRIX朴素 attention scores 与序列长度呈 S×S 规模；长上下文时会迅速变大。
TRAININGbackward 需要相关中间状态；FlashAttention 等方法会改变中间数据怎样读写/保存，而不改变 attention 的数学结果。
DISTRIBUTEDheads、sequence/context、Linear 权重都可能成为并行切分维度。

所以学 Attention 的目的不只是会写公式，而是以后看到一个优化时能问：“它到底在减少哪块数据的存储、计算还是通信？”

09 · THE ROAD TO KV CACHE

为什么以后会出现 KV Cache？因为生成下一个 token 时，过去 token 的 K/V 不需要重新变。

自回归推理时，先有 prompt，然后一次只新增一个 token。对已经出现的旧 token 来说，它们在当前层算出的 K 和 V 可以复用；真正新增的是新 token 的 Q/K/V。

STEP told K / Vcache and keep
+
NEW TOKENnew Q / K / Vcompute once
→
ATTENTIONQ_new attends to K_allmix V_all

这就是后面 vLLM 章节最核心的对象第一次露面：KV Cache 本质上就是把历史 token 的 Key / Value 留下来，避免 decode 每一步都重新计算整段历史。

先别急着问 Connector。KV Connector 只是更后面的问题：当这些 K/V 已经在 Graphics Processing Unit (GPU，图形处理器) A 上算好了，GPU B 又要继续 decode，它们怎样高效搬过去？

10 · THE ROAD TO MEGATRON

Attention 也把我们重新带回了 Megatron。

Q/K/V 的来源是几个巨大的 Linear。上一模块已经看到，大 Linear 可以沿输出特征切分。等学到 Megatron Tensor Parallel 时，我们会把这里的抽象重新打开：

QKV PROJECTIONX @ Wqkv
split output / heads →
Tensor Parallel (TP，张量并行) RANK 0subset of Q/K/V
TP RANK 1another subset

现在只需要知道：Attention 并不是一个无法拆分的黑盒，它内部仍然由你已经学过的 tensor、GEMM 和数据搬运组成。

CHECKPOINT02.1

不背公式，直接用 shape 回答。

1. 单头教学版里，Q=[B,S,H]、K=[B,S,H]，为什么 Q @ Kᵀ 是 [B,S,S]？
对每个 batch，Q 的每个 S 个 query 都要和 K 的 S 个 key 做点积；H 是点积中被求和掉的维度，所以留下 S×S。
2. causal mask 应该在 softmax 前还是后应用？为什么常把被屏蔽 score 设成极小值？
通常在 softmax 前作用到 scores。把未来位置设成概念上的 -∞，softmax 后这些位置的概率/权重就会变成 0。
3. KV Cache 为什么缓存 K/V，而不是简单说“把所有东西都缓存”？
decode 新 token 时，需要新的 query；但旧 token 在该层已经算出的 K/V 可以直接复用。保存历史 K/V 就能避免每一步为整个历史重复计算这些投影。
