LESSON 02.1 · TRANSFORMER约45 min

Attention 数据流：Q、K、V 到底从哪里来？

Attention 最容易被一条公式吓住。我们换个顺序：先把它看成一条很普通的数据流水线。输入 X 先经过三个线性投影得到 Q、K、V；Q 和 K 决定“该看谁”；这些权重再去混合 V。只要每一步的形状能追下来，后面的多头注意力、KV Cache 和张量并行也会自然得多。

这节课结束时，你应该能做到：
  • 解释 Q、K、V 都是从输入 X 经过不同线性投影得到的。
  • 推导 Q @ Kᵀ → [S,S] 为什么得到 token 之间的分数矩阵。
  • 理解因果掩码为什么必须在 decoder 自回归模型里阻止“偷看未来”。
  • 推导 softmax(scores) @ V 为什么又回到每个 token 一条向量。
  • 说出 Attention 与 Megatron 张量并行、vLLM KV Cache 的第一条连接线。
01 · 从你已经会的东西出发

Attention的起点，仍然只是一个 [B,S,H] tensor。

先用一个玩具设置：B=2、S=4、H=8。也就是一批有2条序列，每条4个token，每个token用8个数字表示。

X = [2, 4, 8]
B · 2两条样本
S · 4每条四个token
H · 8每个token八维

上一模块已经告诉我们：线性层可以只改变最后一维。所以如果准备三个不同的 8 → 8 线性层，同一个X就能产生三份形状完全相同、数值含义不同的tensor。

02 · 三个线性投影：Q、K、V

Q、K、V不是凭空出现的：就是三个不同的线性层。

INPUTX[B,S,H]
→
QUERYQ = XWq[B,S,H]
KEYK = XWk[B,S,H]
VALUEV = XWv[B,S,H]

可以先用一个不严格但很好用的比喻：

Query · 我在找什么？

当前token以Q的方式表达自己的“查询需求”。

Key · 我有什么特征？

每个token以K的方式提供可被匹配的“索引特征”。

Value · 真正拿走什么？

匹配强弱确定后，最后按权重混合的是V中的信息。

别把比喻当定义。真正的定义仍然是三个可学习的线性投影。模型训练后自己学会什么样的Q/K匹配对任务有用。

源码预告：概念上我们写成Wq、Wk、Wv三个投影；真实高性能实现经常把它们融合成一次更大的查询-键-值（QKV）投影。并且在分组查询注意力（GQA）等结构里，K/V的总宽度也不一定和Q一样。下一课再把这些差异拆开。

03 · Q 和 K 怎样得到注意力分数

一个token怎么给所有token打分？用自己的Q去点积所有K。

先暂时忽略批次，只看一条长度 S=4 的序列。Q和K都可以想成 [4,8]：

Q [4,8]@Kᵀ [8,4]→scores [4,4]

为什么结果是 [4,4]？第一维的4代表“有4个query token”；第二维的4代表“每个query都要和4个key token比一次”。于是每个格子就是一对token的匹配分数。

Q \ K
K₁
K₂
K₃
K₄
Q₁
q₁·k₁q₁·k₂q₁·k₃q₁·k₄
Q₂
q₂·k₁q₂·k₂q₂·k₃q₂·k₄
Q₃
q₃·k₁q₃·k₂q₃·k₃q₃·k₄
Q₄
q₄·k₁q₄·k₂q₄·k₃q₄·k₄

实际scaled dot-product attention还会把这些点积除以 √dₖ。现在只记作用：维度大时点积的量级容易变大，缩放可以让softmax的数值范围更稳定。

04 · 因果掩码

生成模型不能在训练时偷看右边还没生成的token。

对于生成式预训练Transformer（GPT）这类decoder-only自回归模型，token 2可以看token 1和自己，但不能看token 3、4。于是softmax前会把未来位置屏蔽掉：

Q₁✓×××
Q₂✓✓××
Q₃✓✓✓×
Q₄✓✓✓✓

代码里常见做法是把被屏蔽位置的score设成一个极小值（概念上可看作 -∞）。softmax之后，这些位置的权重就变成0。

不要泛化过头：因果掩码是自回归decoder attention的典型要求；不同Transformer架构的mask规则可以不同。

05 · 分数怎样变成权重

Softmax做的事：把一行分数变成一行“该看多少”的权重。

对某个query token，假设允许看到三个位置，softmax后可能得到：

token 10.68
token 20.21
token 30.11

这些权重加起来是1。权重大，代表当前query会从对应token的Value中取更多信息。于是attention不再只是“谁像谁”，而变成了一个可用于加权混合 V的矩阵。

06 · 权重怎样混合 V

最后一步：attention weights @ V。

仍然看单条序列：

weights [S,S]@V [S,H]→context [S,H]

每一行权重都对应一个query token。它拿这S个权重去加权S条Value向量，最后得到一条新的H维向量。所以输出又回到“每个 token 一条向量”的结构。

1X[B,S,H]
→
2Q K V3 × [B,S,H]
→
3分数[B,S,S]
→
4weights[B,S,S]
→
5上下文[B,S,H]

这里故意还是“单头教学版”。下一课Multi-头Attention会把H拆成 n_heads × head_dim，到时分数会多一个头维度。标准Multi-头Attention在各头的结果拼回去以后，通常还会再经过一个output投影 Wₒ；我们也留到下一课一起讲。

07 · 在 PyTorch 里跟踪张量形状

不用高级Attention API，自己把这条数据流跑一次。

python04_attention_single_head.py
import math
import torch

B, S, H = 2, 4, 8
X = torch.randn(B, S, H)

Wq = torch.randn(H, H)
Wk = torch.randn(H, H)
Wv = torch.randn(H, H)

Q = X @ Wq                         # [2,4,8]
K = X @ Wk                         # [2,4,8]
V = X @ Wv                         # [2,4,8]

scores = Q @ K.transpose(-2, -1)   # [2,4,4]
scores = scores / math.sqrt(H)

mask = torch.triu(
    torch.ones(S, S, dtype=torch.bool), diagonal=1
)
scores = scores.masked_fill(mask, float('-inf'))

weights = torch.softmax(scores, dim=-1)  # [2,4,4]
context = weights @ V                    # [2,4,8]

print(Q.shape, scores.shape, context.shape)

这段代码只是为了看形状，所以Wq/Wk/Wv直接用随机矩阵。真正Transformer里它们是模型参数，通常由线性层层管理并在训练中学习。

08 · 为什么系统工程关心 Attention

Attention一旦变大，会同时碰到计算、显存和并行问题。

Q/K/V PROJECTIONS三个大线性层 → 大量通用矩阵乘法（GEMM）；这是Tensor Parallel很自然的切分目标。
SCORE MATRIX朴素注意力分数与序列长度呈S×S规模；长上下文时会迅速变大。
TRAININGbackward需要相关中间状态；FlashAttention等方法会改变中间数据怎样读写/保存，而不改变attention的数学结果。
DISTRIBUTEDheads、sequence/上下文、线性层权重都可能成为并行切分维度。

所以学Attention的目的不只是会写公式，而是以后看到一个优化时能问：“它到底在减少哪块数据的存储、计算还是通信？”

09 · 通往 KV Cache

为什么以后会出现KV Cache？因为生成下一个token时，过去token的K/V不需要重新变。

自回归推理时，先有prompt，然后一次只新增一个token。对已经出现的旧token来说，它们在当前层算出的K和V可以复用；真正新增的是新token的Q/K/V。

STEP told K / Vcache and keep
+
NEW TOKENnew Q / K / Vcompute once
→
ATTENTIONQ_new attends to K_allmix V_all

这就是后面vLLM章节最核心的对象第一次露面：KV Cache本质上就是把历史token的Key / Value留下来，避免decode每一步都重新计算整段历史。

先别急着问Connector。KV Connector只是更后面的问题：当这些K/V已经在图形处理器（GPU）A上算好了，GPU B又要继续decode，它们怎样高效搬过去？

10 · 通往 Megatron

Attention也把我们重新带回了Megatron。

Q/K/V的来源是几个巨大的线性层。上一模块已经看到，大线性层可以沿输出特征切分。等学到Megatron Tensor Parallel时，我们会把这里的抽象重新打开：

QKV投影X @ Wqkv
split output / heads →
张量并行（TP）RANK 0subset of Q/K/V
TP RANK 1another subset

现在只需要知道：Attention并不是一个无法拆分的黑盒，它内部仍然由你已经学过的tensor、GEMM和数据搬运组成。

CHECKPOINT02.1

不背公式，直接用形状回答。

1. 单头教学版里，Q=[B,S,H]、K=[B,S,H]，为什么 Q @ Kᵀ 是 [B,S,S]？
对每个批次，Q的每个S个query都要和K的S个key做点积；H是点积中被求和掉的维度，所以留下S×S。
2. 因果掩码应该在softmax前还是后应用？为什么常把被屏蔽score设成极小值？
通常在softmax前作用到分数。把未来位置设成概念上的 -∞，softmax后这些位置的概率/权重就会变成0。
3. KV Cache为什么缓存K/V，而不是简单说“把所有东西都缓存”？
decode新token时，需要新的query；但旧token在该层已经算出的K/V可以直接复用。保存历史K/V就能避免每一步为整个历史重复计算这些投影。
