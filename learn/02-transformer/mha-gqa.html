LESSON 02.2 · TRANSFORMER约45 min

MHA（多头注意力：让多个 attention head 在不同子空间并行计算）与 GQA（分组查询注意力：多个 Query heads 共享较少的 KV heads，以减少 KV 成本）：为什么 Q 有很多个注意力头，K/V 却可以更少？

上一课故意只画了一个注意力头。真实的 LLM（大语言模型：本课程训练与推理系统的主要模型对象）通常会把 hidden dimension 拆成多个 attention head（注意力头：在一个子空间中独立计算 Attention 的一路表示）。最常见的基本形式是 MHA；为了降低 KV Cache 成本，又出现了 GQA。

这节课结束时，你应该能做到：
  • 把 [B,S,H] 正确拆成 [B,N,S,D]，并知道 H=N×D。
  • 从形状推导多头注意力的分数矩阵为 [B,N,S,S]。
  • 解释 MHA、GQA、MQA（多查询注意力：让所有 Query heads 共享单组 K/V）的区别不在“有没有 Attention”，而在 Q 头与 KV 头的数量关系。
  • 用一个比例说明为什么 GQA 会显著减少 KV Cache。
  • 理解注意力头为什么同时影响 Megatron 张量并行与 vLLM 在线推理。
01 · 为什么要多头

不是把同一个 Attention 重复很多遍，而是把隐藏空间分成多个更小的子空间。

假设 H=8，我们设置 N=2 个 heads，那么每个头的维度就是 D=4：

H = 8=N = 2×D = 4
ONE TOKENhidden = 8
split →
头0D=4
头1D=4

每个头都有自己的Q/K/V子空间，可以学到不同的匹配方式。最后再把所有heads的结果拼回隐藏维度。

重要：“头学到句法、另一个头学到指代”这种说法只能当直觉例子，不是固定分工。头学到什么由训练决定。

02 · 每头维度怎样确定

真正的关键不是头这个词，而是多出来了一个维度。

Q projection 后仍可先看成 [B,S,H]。接着把最后一维 H reshape 成 N × D，再把 head dimension（每头维度：每个 attention head 内部使用的向量宽度）移到 sequence 前面：

PROJECTED Q[B,S,H]
→
RESHAPE[B,S,N,D]
→
TRANSPOSE[B,N,S,D]

K、V 在普通 MHA 中做同样的变换。于是每个 head 独立做上一课学过的单头 Attention：

Q [B,N,S,D]@Kᵀ [B,N,D,S]→scores [B,N,S,S]

只多了一个 N。你可以把它理解为：每个 batch 里，现在并行存在 N 张独立的 S×S 注意力矩阵。

03 · MHA 的完整数据流

MHA 的完整 shape 流程。

INPUTX[B,S,H]
→
QKV PROJECTIONsplit heads[B,N,S,D]
→
ATTENTIONper head[B,N,S,D]
→
CONCATmerge heads[B,S,H]
→
OUTPUTWₒ[B,S,H]

这里上一课没讲完的 Wₒ 出现了。各 head 输出先合并回 H，再经过 output projection。于是整个 MHA 模块输入和输出通常都保持 [B,S,H]，方便接残差连接。

04 · PyTorch 形状练习

亲手做一次 heads 拆分与合并。

python05_multi_head_shapes.py
import math
import torch

B, S, H = 2, 4, 8
N = 2
D = H // N

X = torch.randn(B, S, H)
Wq = torch.randn(H, H)
Wk = torch.randn(H, H)
Wv = torch.randn(H, H)

Q = (X @ Wq).view(B, S, N, D).transpose(1, 2)
K = (X @ Wk).view(B, S, N, D).transpose(1, 2)
V = (X @ Wv).view(B, S, N, D).transpose(1, 2)
# Q, K, V: [2, 2, 4, 4]

scores = Q @ K.transpose(-2, -1) / math.sqrt(D)
# scores: [2, 2, 4, 4]

weights = torch.softmax(scores, dim=-1)
heads = weights @ V
# heads: [2, 2, 4, 4]

merged = heads.transpose(1, 2).contiguous().view(B, S, H)
# merged: [2, 4, 8]

这里暂时省略 causal mask，目的是只观察头维度。注意合并前常见 transpose(...).contiguous().view(...)：transpose 改变了 stride/layout；后续 reshape 是否需要 contiguous copy，要看具体操作与实现。这是以后进入性能工程时值得留意的细节。

05 · KV Cache 为什么会变大

如果 Q/K/V 都有很多 heads，生成时 K/V 就要缓存很多份。

在 MHA 中，通常 Nq = Nk = Nv = N。自回归生成时，每一层、每一个历史 token、每一个 KV head 都要保留 Key 和 Value。

PER SEQUENCE · PER LAYER · ELEMENT COUNTKV ≈ 2 × S × Nkv × D

这里按单条序列记账，前面的 2 代表 K 和 V 两份。再乘层数、dtype 对应的 bytes，以及在线推理时的并发序列数，就会变成非常大的显存账单。

于是问题出现了：Query 一定需要和 KV 一样多的 heads 吗？

06 · GQA 的共享方式

GQA：保留很多 Q heads，但让一组 Q heads 共享一个 K/V head。

例如 Nq=8、Nkv=2。每 4 个 Q heads 共用 1 个 K head 和 1 个 V head：

KV head 0K₀ / V₀
Q₀Q₁Q₂Q₃
KV head 1K₁ / V₁
Q₄Q₅Q₆Q₇
MHANq = Nkv每个Q头有自己的K/V头
GQANq > Nkv > 1多个Q heads共享一个KV头
MQANkv = 1所有Q heads共用一组K/V

GQA的目标是折中：尽量保留多Q头的表达能力，同时显著减少需要缓存和读取的K/V数量。

07 · GQA 为什么对在线推理重要

KV Cache的缩减比例，直接由KV头数量决定。

如果其它条件相同，MHA有32个KV头，而GQA只有8个：

MHA32 KV头
GQA8 KV头
KV元素量约变为8 / 32 = 1/4

这不仅减少显存占用，也减少生成时 Attention 读取历史 K/V 的数据量；如果未来要把 KV Cache 跨进程、跨 GPU、跨节点搬运，KV 更小也意味着更少的传输字节。

这就是 GQA 和 KV Connector（KV 连接器：在不同实例之间衔接和传递已有 KV state 的接口层）的连接：Connector 解决“KV 怎么搬”，而模型结构本身决定“到底有多少 KV 要搬”。

08 · GQA 形状练习

形状上，Q heads和KV头不再一样多。

concept code06_gqa_shapes.py
import torch

B, S, D = 2, 4, 4
Nq = 8
Nkv = 2
group_size = Nq // Nkv              # 4

Q = torch.randn(B, Nq, S, D)        # [2,8,4,4]
K = torch.randn(B, Nkv, S, D)       # [2,2,4,4]
V = torch.randn(B, Nkv, S, D)       # [2,2,4,4]

# 教学上可以把每个 KV head 逻辑扩展给 4 个 query heads：
K_for_q = K.repeat_interleave(group_size, dim=1)
V_for_q = V.repeat_interleave(group_size, dim=1)
# [2,8,4,4]

但不要把这段 repeat 当作生产实现。高性能 kernels 可以根据分组映射让多个 Q heads 读取同一 KV head，而不必真的复制一份更大的 K/V tensor；否则就把 GQA 节省的内存又浪费回去了。

09 · 通往张量并行

heads 天然适合分给不同 TP GPU。

对普通 MHA，Q/K/V projection 的输出特征可以按 heads 切开：

TP GPU 0heads 0–3
TP GPU 1heads 4–7
TP GPU 2heads 8–11
TP GPU 3heads 12–15

每张 GPU 可以先独立计算自己的本地 heads。最后 output projection 再把局部结果组合进后续网络。到 Megatron 章节，我们会把它和 ColumnParallelLinear（列并行线性层：沿输出特征方向切分 Linear 权重） / RowParallelLinear（行并行线性层：沿输入特征方向切分 Linear 权重）对上。

GQA 会让映射更微妙：KV 头比 Q heads 少时，TP 并行度、head 数是否可整除，以及 KV heads 是否需要特殊映射或复制，都要由具体模型和实现决定。这里不提前记死规则。

CHECKPOINT02.2

看见头数，先想到形状和KV Cache。

1. H=4096、N=32，每个头的 D 是多少？
D = H / N = 4096 / 32 = 128。普通 MHA 中可以把 Q/K/V reshape 成包含 32 个头、每个头 128 维的结构。
2. MHA的 Q,K=[B,N,S,D]，分数是什么形状？
[B,N,S,S]。每个批次、每个头都有一张S×S的token之间score matrix。
3. 如果从32 KV头改成8 KV头，其它条件相同，KV Cache元素量大约变成多少？
约变成原来的 8/32 = 1/4。这是GQA对在线推理很重要的原因之一。
