LESSON 02.2 · TRANSFORMER约 45 min

MHA 与 GQA：为什么 Q 有很多个 head，K/V 却可以更少？

上一课故意只画了一个 head。真实 LLM 通常会把 hidden dimension 拆成多个 attention heads，让不同 head 在不同子空间里做匹配。接着为了降低推理时最昂贵的 KV Cache，又出现了 GQA：Query heads 仍然很多，但多个 Query heads 共享更少的 K/V heads。

这节课结束时，你应该能做到：
  • 把 [B,S,H] 正确拆成 [B,N,S,D]，并知道 H=N×D。
  • 从 shape 推导 Multi-Head Attention 的 scores 为 [B,N,S,S]。
  • 解释 MHA、GQA、MQA 的区别不在“有没有 Attention”，而在 Q heads 与 KV heads 的数量关系。
  • 用一个比例说明为什么 GQA 会显著减少 KV Cache。
  • 理解 heads 为什么同时是 Megatron Tensor Parallel 与 vLLM serving 的重要结构。
01 · WHY MULTIPLE HEADS

不是把同一个 Attention 重复很多遍，而是把 hidden space 分成多个更小的子空间。

假设 H=8，我们设置 N=2 个 heads，那么每个 head 的维度就是 D=4：

H = 8=N = 2×D = 4
ONE TOKENhidden = 8
split →
HEAD 0D=4
HEAD 1D=4

每个 head 都有自己的 Q/K/V 子空间，可以学到不同的匹配方式。最后再把所有 heads 的结果拼回 hidden dimension。

重要：“head 学到句法、另一个 head 学到指代”这种说法只能当直觉例子，不是固定分工。head 学到什么由训练决定。

02 · THE HEAD DIMENSION

真正的关键不是 head 这个词，而是多出来了一个维度。

Q 投影后仍可先看成 [B,S,H]。接着把最后一维 H reshape 成 N × D，再把 head 维移到 sequence 前面：

PROJECTED Q[B,S,H]
→
RESHAPE[B,S,N,D]
→
TRANSPOSE[B,N,S,D]

K、V 在普通 MHA 中做同样的变换。于是每个 head 独立做上一课学过的单头 Attention：

Q [B,N,S,D]@Kᵀ [B,N,D,S]→scores [B,N,S,S]

只多了一个 N。你可以把它理解为：每个 batch 里，现在并行存在 N 张独立的 S×S attention map。

03 · MHA END TO END

Multi-Head Attention 的完整 shape 流程。

INPUTX[B,S,H]
→
QKVsplit heads[B,N,S,D]
→
ATTENTIONper head[B,N,S,D]
→
CONCATmerge heads[B,S,H]
→
OUTPUTWₒ[B,S,H]

这里上一课没讲完的 Wₒ 出现了。各 head 输出先拼回 H，再经过一个 output projection。于是整个 MHA 模块输入和输出通常都保持 [B,S,H]，方便接残差连接。

04 · PYTORCH SHAPE LAB

亲手做一次 split heads 和 merge heads。

python05_multi_head_shapes.py
import math
import torch

B, S, H = 2, 4, 8
N = 2
D = H // N

X = torch.randn(B, S, H)
Wq = torch.randn(H, H)
Wk = torch.randn(H, H)
Wv = torch.randn(H, H)

Q = (X @ Wq).view(B, S, N, D).transpose(1, 2)
K = (X @ Wk).view(B, S, N, D).transpose(1, 2)
V = (X @ Wv).view(B, S, N, D).transpose(1, 2)
# Q, K, V: [2, 2, 4, 4]

scores = Q @ K.transpose(-2, -1) / math.sqrt(D)
# scores: [2, 2, 4, 4]

weights = torch.softmax(scores, dim=-1)
heads = weights @ V
# heads: [2, 2, 4, 4]

merged = heads.transpose(1, 2).contiguous().view(B, S, H)
# merged: [2, 4, 8]

这里暂时省略 causal mask，目的是只观察 head 维度。注意 merge 前常见 transpose(...).contiguous().view(...)：transpose 改变了 stride/layout 视图，后续 reshape 是否需要 contiguous copy 要看具体操作与实现。这是以后进入性能工程时值得留意的细节。

05 · THE KV CACHE PROBLEM

如果 Q/K/V 都有很多 heads，decode 时 K/V 要缓存很多份。

在 MHA 中，通常 Nq = Nk = Nv = N。自回归 decode 时，每一层、每一个历史 token、每一个 KV head 都要保留 Key 和 Value。

PER SEQUENCE · PER LAYER · ELEMENT COUNTKV ≈ 2 × S × Nkv × D

这里按单条序列记账，前面的 2 代表 K 和 V 两份。再乘 layer 数、dtype bytes，以及 serving 时的并发序列数，就会变成非常大的显存账单。

于是问题出现了：Query 一定需要和 KV 一样多的 heads 吗？

06 · GROUPED-QUERY ATTENTION

GQA：保留很多 Query heads，但让一组 Query heads 共享一个 K/V head。

例如 Nq=8、Nkv=2。每 4 个 Query heads 共用 1 个 K head 和 1 个 V head：

KV HEAD 0K₀ / V₀
Q₀Q₁Q₂Q₃
KV HEAD 1K₁ / V₁
Q₄Q₅Q₆Q₇
MHANq = Nkv每个 Q head 有自己的 K/V head
GQANq > Nkv > 1多个 Q heads 共享一个 KV head
MQANkv = 1所有 Q heads 共用一组 K/V

GQA 的目标是折中：尽量保留多 Query heads 的表达能力，同时显著减少需要缓存和读取的 K/V 数量。

07 · WHY GQA MATTERS TO SERVING

KV Cache 的缩减比例，直接由 KV head 数量决定。

如果其它条件相同，MHA 有 32 个 KV heads，而 GQA 只有 8 个：

MHA32 KV heads
GQA8 KV heads
KV 元素量约变为 8 / 32 = 1/4

这不仅减少显存占用，也减少 decode 时 attention 读取历史 K/V 的数据量；如果未来要把 KV Cache 跨进程、跨 GPU、跨节点搬运，KV 更小也意味着更少的传输字节。

这就是 GQA 和 KV Connector 的连接：Connector 解决“KV 怎么搬”，而模型结构本身决定“到底有多少 KV 要搬”。

08 · GQA SHAPE LAB

shape 上，Q heads 和 KV heads 不再一样多。

concept code06_gqa_shapes.py
import torch

B, S, D = 2, 4, 4
Nq = 8
Nkv = 2
group_size = Nq // Nkv              # 4

Q = torch.randn(B, Nq, S, D)        # [2,8,4,4]
K = torch.randn(B, Nkv, S, D)       # [2,2,4,4]
V = torch.randn(B, Nkv, S, D)       # [2,2,4,4]

# 教学上可以把每个 KV head 逻辑扩展给 4 个 query heads：
K_for_q = K.repeat_interleave(group_size, dim=1)
V_for_q = V.repeat_interleave(group_size, dim=1)
# [2,8,4,4]

但不要把这段 repeat 当作生产实现。高性能 kernels 可以根据 group mapping 让多个 Q heads 读取同一 KV head，而不必真的复制一份更大的 K/V tensor；否则就把 GQA 节省的内存又浪费回去了。

09 · THE ROAD TO TENSOR PARALLEL

heads 天然适合分给不同 Tensor Parallel ranks。

对普通 MHA，Q/K/V projection 的输出特征可以按 heads 切开：

TP RANK 0heads 0–3
TP RANK 1heads 4–7
TP RANK 2heads 8–11
TP RANK 3heads 12–15

每张 GPU 可以先独立计算自己的 local heads。最后 output projection 再把局部结果组合进后续网络。到 Megatron 章节，我们会把它和 ColumnParallelLinear / RowParallelLinear 对上。

GQA 会让映射更微妙：KV heads 比 Q heads 少时，TP degree、head 数是否可整除，以及 KV heads 是否需要特殊映射/复制都要由具体模型和实现决定。这里不提前记死规则。

CHECKPOINT02.2

看见 head 数，先想到 shape 和 KV Cache。

1. H=4096、N=32，每个 head 的 D 是多少？
D = H / N = 4096 / 32 = 128。普通 MHA 中可以把 Q/K/V reshape 成包含 32 个 head、每个 head 128 维的结构。
2. MHA 的 Q,K=[B,N,S,D]，scores 是什么 shape？
[B,N,S,S]。每个 batch、每个 head 都有一张 S×S 的 token-to-token score matrix。
3. 如果从 32 KV heads 改成 8 KV heads，其它条件相同，KV Cache 元素量大约变成多少？
约变成原来的 8/32 = 1/4。这是 GQA 对 serving 很重要的原因之一。
